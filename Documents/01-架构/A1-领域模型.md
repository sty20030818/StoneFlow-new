# 领域模型

## 当前事实与产品目标

本文描述当前已实现的数据模型。产品已确认但尚未落地的目标不会写成当前字段或约束；它们应在后续重构任务的 SPEC 中设计和实施。

## 核心实体

| 实体 | 当前职责 | 关键关系 |
|---|---|---|
| Space | 任务与 Project 的顶层个人上下文 | 有一个默认项；Task、Project 属于它 |
| Project | Space 内的轻量任务容器 | 属于一个 Space；可包含 Task |
| Task | 最小执行单元 | 属于一个 Space，可选归属 Project |
| TaskLink | Task 的 URL 引用 | 属于一个 Task |
| View | 保存的 Task/Project 查询定义 | 保存 filters、sort、groupBy |
| Activity | 操作时间线记录 | 当前正式展示在 Task 详情 |

## Space

当前 Space 为扁平结构，包含名称、图标、颜色、排序、默认标记、归档与删除时间。系统通过 `isDefault` 保证默认 Space 的语义；Task 和 Project 的 `spaceId` 都是必填归属。

## Project

当前 Project 包含：`spaceId`、名称、描述、`dueAt`、排序，以及完成、归档、删除、创建和更新时间。它目前没有独立的状态、优先级、计划日期或提醒日期字段。

## Task

当前 Task 的主要字段：

| 类别 | 字段 |
|---|---|
| 归属 | `spaceId`、可空的 `projectId`、`inboxAt` |
| 内容 | `title`、`note` |
| 执行 | `status`、`statusChangedAt`、`priority` |
| 时间 | `scheduledAt`、`dueAt`、`reminderAt` |
| 生命周期 | `completedAt`、`canceledAt`、`archivedAt`、`deletedAt` |
| 维护 | `sortOrder`、`createdAt`、`updatedAt` |

当前状态为 `todo | doing | waiting | done | canceled`；优先级为固定数值 `0 | 1 | 2 | 3 | 4`。显示名称与未来统一的 Work 模型尚未在领域层收口。

当前任务位置允许 `project | inbox | noProject`。`Inbox` 仍是实现事实；产品已决定后续移除它，仅保留项目任务和无项目独立待办。

## View

当前 View 有 `system | custom` 两类，记录名称、实体类型、filters、sort、groupBy、可见性和排序。当前 filters 已覆盖状态、优先级、Project、Inbox、时间和生命周期字段；scope 尚未成为 View 的显式字段。

## 生命周期

- 归档通过 `archivedAt` 表达，不等同于删除。
- 删除通过 `deletedAt` 进入 Trash；永久删除属于后续管理动作。
- Project 归档或删除时，当前实现会级联处理 Task；恢复当前只恢复 Project 本身，尚未实现“只恢复该次级联影响内容”的目标规则。

## 领域不变式

- Task 与 Project 必须归属一个 Space。
- Project 不能跨 Space 挂载 Task。
- Space 默认项在同一副本中保持唯一。
- 任务状态变化必须同步维护相应的完成或取消时间。
- 业务写入与待同步 mutation 在同一事务中提交。

## 后续重构边界

以下是已确认的产品目标，而非当前实现：移除 Inbox；抽取 Task 与 Project 可复用的 WorkStatus、WorkPriority、WorkTime；为 Project 补齐状态、优先级与三类时间；为 View 增加显式 scope；实现级联恢复语义。它们必须在独立重构任务中先设计迁移与兼容边界。
