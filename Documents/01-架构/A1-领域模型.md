# 领域模型

## 当前事实与产品目标

本文描述 **当前已落地** 的数据模型：单一 schema baseline、无 Inbox 容器、Task 归属为 **Project 或独立事项（standalone）**。

## 核心实体

| 实体 | 当前职责 | 关键关系 |
|---|---|---|
| Space | 任务与 Project 的顶层个人上下文 | 活跃默认至多一个；Task、Project 属于它 |
| Project | Space 内的轻量任务容器，嵌入 WorkState | 属于一个 Space；可包含 Task |
| Task | 最小执行单元，嵌入 WorkState | 属于一个 Space；可选归属同 Space 的 Project |
| TaskLink | Task 的 URL 引用 | 属于一个 Task；随 Task 物理删除 |
| View | 仅自定义查询定义（系统 View 由代码定义，不入库） | 保存 scope/filters/sort/group_by |
| Activity | Task 可理解操作的时间线 | 正式展示在 Task 详情 |
| Outbox / Tombstone / AppliedOps | 同步写边界元数据 | 与业务写操作同事务 |

## 共享 Work 模块（已落地）

领域层以 `domain::work` 收口（`WorkStatus` / `WorkPriority` / `WorkState`）：

| 类别 | 领域类型 | 存储 |
|---|---|---|
| 状态 | `WorkStatus` 枚举 | `TEXT`：`todo \| doing \| waiting \| done \| canceled` |
| 优先级 | `WorkPriority` 枚举 | `INTEGER`：`0..=4`（none→urgent） |
| 时间 | `WorkState` 字段 | UTC RFC3339 `TEXT`：`planned_at` / `due_at` / `remind_at` / `status_changed_at` / `completed_at` |

规则：

- 任意状态可手动切换。
- 进入 `done` 写入 `completed_at`；离开 `done` 清空 `completed_at`。
- 状态变化更新 `status_changed_at`。
- **不**维护独立 `canceled_at`（取消态由 `status` 表达）。
- 业务代码只使用 enum；数字/字符串映射仅在持久化边界。

## Space

字段：`name`、`icon_key`、`color_key`、`is_default`、`position`、`generation`、`archived_at`、`deleted_at`、`created_at`、`updated_at`。

- 归档用 `archived_at`；回收站用 `deleted_at`（软删）。
- 活跃默认 Space：`is_default=1 AND archived_at IS NULL AND deleted_at IS NULL` 至多一个。
- Seed 仅创建默认 Space「个人」。

## Project

嵌入 WorkState；另有 `space_id`、`name`、`description`、`position`、`generation`、`archived_at`、`deleted_at`。

## Task

| 类别 | 字段 |
|---|---|
| 归属 | `space_id`（必填）、可空的 `project_id`（复合 FK → `projects`） |
| 内容 | `title`、`note` |
| WorkState | 见上 |
| 生命周期 | `archived_at`（归档）、`deleted_at`（软删进回收站） |
| 维护 | `position`、`generation`、`created_at`、`updated_at` |

### 归属（placement）

产品与实现只认两种归属（**无 Inbox 容器、无 `inbox_at` 字段**）：

| 概念 | 持久化 | 列表 / 写入 |
|---|---|---|
| **项目任务** | `project_id` 非空，且与 `space_id` 同 Space | write kind = `project` |
| **独立事项（standalone）** | `project_id IS NULL` | write kind = `standalone`；须指定 `space_id` |

查询侧另有 list filter：

| list placement | 含义 |
|---|---|
| `all` | 不按 project 过滤 |
| `project` | 指定 `project_id` |
| `standalone` | `project_id IS NULL` |

索引：`ix_tasks_space_standalone_position`（按 Space 内独立事项位置排序）。

- 取消态由 `status=canceled` 表达；归档与取消是不同概念。
- **不做**「全局未归类」跨 Space 视图；独立事项始终落在某个 Space。

## 生命周期与删除（两阶段）

1. **归档（Archive）**：写入 `archived_at`；Space / Project / Task 均支持；与回收站是不同列表。
2. **软删（Delete）**：写入 `deleted_at`，实体仍在业务表 → **仍同步**（upsert/patch），可撤回。
3. **恢复（Restore）**：清空 `archived_at` / `deleted_at`（按来源），再同步。
4. **永久删除（PermanentlyDelete）**：物理删除行 + 写 `tombstones` → 同步删除语义，拒绝 stale 复活。

归档与回收站互为独立列表；进入回收站前不必先归档。

## 领域不变式

- Task 与 Project 必须归属一个 Space。
- Task 若有 Project，必须同 Space（复合外键）。
- 活跃默认 Space 唯一，且不可软删/归档到无默认。
- 排序使用容器内 `position`（默认步进 1000）。
- 独立事项不是 Project 实体，也不是侧栏主导航项。

## 产品入口对应（信息架构）

| 入口 | 数据 |
|---|---|
| 主导航：所有任务 | 当前 Scope 任务列表（list placement `all`）；`scope=all` 为跨 Space 并集，**不是**实体 |
| 主导航：项目总览 / 视图 | Project 列表（仅单 Space 正式入口）/ View |
| 项目列表顶部虚拟行「独立事项」 | 当前 Space 下 list `standalone`（All 侧栏不展示） |
| Launcher 快速捕获 | 默认 Space + create `standalone` |
