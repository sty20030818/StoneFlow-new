# ADR-0004：统一 View 契约与版本化迁移

## 状态

已接受；2026-09-15 修订。用户确认 Mac 数据与云端协议已完成当前契约迁移，授权退役历史转换并收敛本地迁移账本。本修订替代此前保留旧基线升级入口的决定，继续保留 SeaORM 的长期前向迁移机制。

## 决策

- View 仅接受当前完整定义，不恢复旧扁平 filters、空定义回退或 sort/group。删除旧格式转换模块；损坏的当前定义继续保留为不可用 View，不替换成默认查询。
- SQLite 当前只有 `m20260915_000001_baseline` 基线，直接建立九列 View 表。退役旧三步迁移链；启动只接受空库或当前迁移链中结构完整的数据库，旧账本、未知版本和残缺结构明确拒绝，不自动重写账本、补库或清库。
- 后续 schema 变更在当前基线之后追加有序 SeaORM 前向迁移，不重写已执行迁移的语义。迁移与账本写入保持同一 IMMEDIATE 事务，失败回滚。
- PostgreSQL 当前协议为 v3，只初始化空同步 schema 或连接有效 v3。退役 v2 到 v3 专用 API、工具及历史转换；本次不更改已有云端 v3 的数据、身份或序号。上传事务继续持有 schema 记录共享锁并重验版本。
- 保留当前 View 契约、无效定义隔离、数据库准入、同步协议及事务失败边界的有效检查；仅退役历史迁移专用检查。

## 取舍与恢复

当前数据已完成旧格式转换，保留历史转换会继续扩大代码和测试的维护范围。本次收敛升级入口；未来持久化格式演进仍由版本化迁移承担。最新代码不再直接打开旧账本或旧备份，旧备份须保留并配合对应历史代码在隔离环境恢复。

本次 Mac 维护先停止应用并保存完整备份，核对数据库已符合当前九列 View 契约；在事务中仅把迁移账本收敛为新基线，逐表校验业务、设置、活动历史和同步状态未变。不得通过清空本地后云端恢复替代这次无损维护，也不得把账本操作放入普通启动路径。本次维护已完成：账本外 16 张表（含 SQLite 序列表）逐表指纹与物理结构保持一致，真实存储启动验证通过；备份和核验报告保存在本机数据库目录下的 `backups/20260915-231517-before-baseline-consolidation/`。

其他设备升级当前代码后，先保留完整本地备份，再重建本地数据库并从同一云端 v3 全量恢复。云端只恢复同步实体，未同步内容、本机设置和活动历史不能依靠全量恢复；未同步内容须在重建前单独保全，原备份继续保留。

回滚需要同时恢复匹配的代码和完整本地备份，不能只改版本号或把旧账本交给最新代码。当前客户端不与 v1/v2 远端或旧客户端混写；也不恢复旧远端接管或启动时清洗数据的路径。
