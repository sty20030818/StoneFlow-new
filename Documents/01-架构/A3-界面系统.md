# 界面系统

## 界面原则

- **效率优先**：高频创建、定位、推进和批量操作应短路径完成。
- **稳定优先**：Sidebar、主列表和详情层的空间关系可预测，局部操作不应无故打断扫描。
- **信息优先**：用排版、对齐、状态与轻量边界表达层级，不堆叠装饰卡片。
- **键盘优先，鼠标顺手**：快捷键和 Command 覆盖高频操作，但所有核心流程保留直接鼠标入口。
- **状态可扫读**：状态、优先级、日期与归属应比装饰更容易识别。

## 必须统一的 UI 与交互规则

| 主题 | 规则 |
|---|---|
| 视觉基线 | 浅色、克制、高信息密度、低装饰；不做企业管理后台或消费型打卡应用风格。 |
| 页面骨架 | 主应用使用稳定 Shell；列表是默认工作面，详情按需通过 Drawer 或独立页进入。 |
| 创建 | 应用外快速创建使用独立 Launcher；应用内创建使用主应用的创建弹窗。 |
| 状态操作 | 不依赖颜色作为唯一表达；文本、图标和位置共同传达状态。 |
| 危险操作 | 删除、永久删除和破坏性批量操作必须可辨识，批量破坏性操作需要二次确认。 |
| 反馈 | 保存、同步、归档、恢复与错误提供及时但克制的反馈，不打断连续操作。 |
| 布局 | 控件与列表保持稳定尺寸；窄窗口优先保证主内容和关键操作可用。 |

## 侧栏信息架构（当前）

| 区域 | 内容 |
|---|---|
| 主导航 | 全部任务、视图、项目总览（**无收件箱**） |
| 项目列表 | 顶部虚拟行「独立事项」+ 当前 Space 的 Project 行 |
| 页脚 | 归档、回收站 |

- 独立事项路径：`/$scopeKey/standalone`；数据 = 该 Space 下 `project_id IS NULL`。
- 全部任务页 toolbar 可筛「仅独立事项」（客户端 `standaloneOnly`），与独立事项列表页是不同入口。
- 快捷键：`G I` 前往独立事项、`N I` 新建独立事项（`S` 预留给 Space 相关能力）。

## 代码入口

| 内容 | 真实来源 |
|---|---|
| Design Token 与主题映射 | `src/styles/tokens/` |
| 共享基础组件 | `src/shared/components/` |
| 共享交互 pattern | `src/shared/components/patterns/` |
| Shell 与全局布局 | `src/layout/` |
| Feature 特有交互 | 对应 `src/features/*/` 与其 `ARCHITECTURE.md` |

具体 Token 数值、组件 API 和页面实现以代码为准；用户路径属于 [产品蓝图](../00-产品/P2-产品蓝图.md)，复杂 Feature 的交互机制应写入其 `DESIGN.md`，不在本文复制。
