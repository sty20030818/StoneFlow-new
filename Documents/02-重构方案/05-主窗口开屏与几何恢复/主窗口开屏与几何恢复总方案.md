# StoneFlow 主窗口开屏与几何恢复总方案

## 0. 文档信息

| 项目 | 内容 |
|------|------|
| 文档名称 | 主窗口开屏与几何恢复总方案 |
| 文档目的 | 给出长期稳定、可落地的冷启动 / 窗体几何 / 首屏体验方案，指导后续实现与验收 |
| 适用范围 | 主窗口 `main` 冷启动、托盘唤起、单实例二次启动；**不含** Launcher 浮层面板（独立生命周期） |

# 1. 核心结论（先读）

## 1.1 最终推荐方案

```txt
Native MainWindowLifecycle（隐藏创建 → 恢复几何 → show）
  + tauri-plugin-window-state（仅 main；不含 VISIBLE）
  + 首帧壳色（HTML inline + WebView/窗背景）
  + 统一 Shell 首屏（一次壳轮廓 + 主区 skeleton）
  + 路由记忆保持现状（与几何正交）
```

用户体感目标（对标 Linear / Notion / VS Code 类生产力桌面端）：

1. **窗一出现就稳**——上次在哪、多大，还在哪；没有「先偏再跳到中间」。
2. **一出现就是壳色**——允许主区 skeleton，不允许白闪。
3. **阶段尽量少**——不要「白屏 → 跳动 → 恢复文案 → 骨架 → 数据」五跳；理想是 **稳窗 + 壳骨架 → 数据淡入**。

## 1.2 一句话否决项

| 方案 | 结论 | 原因 |
|------|------|------|
| 每次冷启动强制 `center()` | **否** | 日常破坏用户布局；多屏时「中心」不稳 |
| 品牌 Logo Splash 第二窗 | **否（V1）** | 生产力工具更吃「直接进壳」；多窗复杂度高；Tauri splash 教程适合重资源/登录门闸，不适合本产品 |
| 等列表数据 ready 再 show | **否** | 把 IO 绑进可见门闸 → 感觉更慢；与「本地窗先可用」既有方向冲突 |
| 自研一套 window geometry store | **否（优先）** | 官方插件已存在且 capability 已开；先用官方，不够再补校验 |
| 持久化 `VISIBLE` | **否** | 本应用关窗 = `hide`；持久化可见性会导致冷启动「看不见」或逻辑混乱 |

## 1.3 分期一览

| 波次 | 名称 | 价值 |
|------|------|------|
| W0 | 接线与防跳 | 注册 window-state；隐藏创建；去掉可见后 `center`；排除 `VISIBLE`；只跟踪 `main` | **已落地** |
| W1 | 消灭白闪 | HTML/窗背景对齐壳色；首帧不再等 CSS |
| W2 | 统一首屏 | 合并「恢复工作区」文案页与壳骨架；冷启动/托盘唤起规则一致 |
| W3 | 稳健性（可选） | 离屏检测回退、最大化边界、主题色联动 |

# 2. As-Is：当前为什么突兀

## 2.1 用户可见时序（冷启动）

```txt
进程启动
  → block_on(bootstrap_database)     // 尚无窗
  → build_main_window
       visible(true) 建窗            // WebView 空 → 白闪
       center()                      // 从系统默认落点跳到「某屏中心」
       show + focus
  → FE：/ loader「正在恢复上次工作区…」
  → ShellLayoutSkeleton
  → 列表 / 看板数据
```

关键实现（现状）：

```rust
// src-tauri/crates/runtime/src/window/main.rs
.visible(true);
// ...
window.center()?;
window.show()?;
```

## 2.2 根因拆解

| 现象 | 根因 | 证据 |
|------|------|------|
| 白闪 | 窗已可见但 CSS/React 未铺色；`index.html` 无 inline 底色 | `index.html` 空 body；`--sf-shell-bg` → `#f3f3f4` 仅在 CSS token |
| 跳到中间 | **可见后**再 `center()` | `main.rs` 建窗后 `center()` |
| 每次位置不同 | **未真正恢复几何**；多屏时 `center` 落点随默认 monitor 变 | `window-state` 依赖 + `capabilities` 有权限，但 `runtime` **未 `.plugin(...)`** |
| 骨架本身 | 合理 | `ShellLayoutSkeleton` 注释：挡壳层白屏——只覆盖 chrome 数据门闸之后 |
| 关窗再开 | `CloseRequested` → `hide`；托盘/单实例 `show` **不再 center** | 冷启动与热唤起心智不一致 |

## 2.3 半成品债务

| 项 | 状态 |
|----|------|
| `tauri-plugin-window-state` crate | Cargo workspace 已声明 |
| `window-state:default` | `capabilities/main.json` 已授予 |
| 插件注册 | **未注册** → 权限空转 |
| Launcher 窗 | 独立 panel 生命周期，**不得**被主窗几何逻辑绑定 |

# 3. 行业与官方对照

## 3.1 Electron 生态（Linear / Notion / VS Code 同类栈的惯例）

官方与社区长期共识（`BrowserWindow` 文档 + 大量桌面应用实践）：

1. **`show: false` 创建** → 设好位置/尺寸 → 再 `show`。
2. **`backgroundColor` 对齐应用底色**——即使仍有一帧闪，也是壳色不是白。Electron 明确写：即便使用 `ready-to-show`，仍建议设置 `backgroundColor`。
3. **复杂应用不要死等 `ready-to-show` 才出窗**——太晚会「感觉慢」；生产力工具优先「稳几何 + 壳色」，内容可以 skeleton。
4. **记住 size / position / maximized**；换显示器时要校验，避免窗飞到已断开屏幕。
5. **不要在 mapped 后再 `center: true`**——后置居中会产生可见位移动画（开源 Linear 客户端类项目曾专门去掉 post-create center）。

Notion 系桌面实现常见模式：`WindowPositionService` 独立持久化 bounds，restore 时校验 display work area，非法则回退居中——与「几何模块高内聚」一致。

## 3.2 Tauri v2 官方

[Window State 插件](https://v2.tauri.app/plugin/window-state/)：

- 关闭时保存，下次恢复。
- **官方 tip**：创建时 `visible: false`，由插件在 restore 后 show，**防止 flashing**。
- Capability 必须显式授予（本仓已具备）。
- 可用 `StateFlags` 精细控制；社区明确支持 **排除 `VISIBLE`**（托盘/隐藏启动场景）。

Tauri 另有 [Splashscreen 教程](https://v2.tauri.app/learn/splashscreen)（主窗 hidden + 独立 splash 窗）。本方案 **V1 不采用**：StoneFlow 是本地优先生产力壳，不是资源重载/登录门闸；多窗会与 Launcher / tray hide 叠加复杂度。

## 3.3 产品侧对标（用户心智）

| 产品类型 | 开屏策略 | 对本仓启示 |
|----------|----------|------------|
| Linear / Notion / Craft | 直接进工作区壳；记住窗几何 | **目标形态** |
| VS Code | 恢复窗 + 工作区；无营销 splash | 几何与「内容恢复」分离 |
| 游戏启动器 / 安装器 | Logo Splash 可接受 | **非本产品** |
| 本仓 Launcher | 浮层、屏顶锚点、短生命周期 | **禁止**与 main 共用 window-state |

# 4. 产品体验规格（To-Be）

## 4.1 冷启动（Cold start）

```txt
隐藏创建 main（定尺默认 1280×900）
  → 若有合法已存几何：restore SIZE|POSITION|MAXIMIZED
  → 若无状态 / 非法（离屏）：center 一次（用户不可见）
  → 首帧已是壳色（HTML + 原生背景）
  → show + focus
  → FE：直接进入壳轮廓（skeleton），并行恢复路由与数据
  → 数据就绪：主区内容替换 skeleton（可轻微淡入，禁止整窗位移）
```

**禁止**：可见后的 `center()` / `setPosition` 动画；Logo 全屏闪屏；「正在恢复…」独立中间页（W2 起）。

## 4.2 热唤起（Tray / single-instance / 任务栏）

```txt
show + unminimize + focus
  → 不改动用户当前几何
  → 不强制 center
```

与冷启动共用「几何真相源」：都尊重上次用户摆放；热唤起只做可见性。

## 4.3 关窗

保持现行为：`CloseRequested` → `prevent_close` + `hide`（进程常驻）。

几何应在合适时机落盘（插件默认在关闭/退出路径保存；实现时验证 **hide 不丢尺寸**，exit 仍能写盘）。**永不把「当前是否可见」当作下次冷启动条件。**

## 4.4 首次安装

无状态文件 → 隐藏态 `center()` 一次 → show。用户第一次看到的就是居中稳窗，无跳动。

## 4.5 首屏内容层级（FE）

| 层 | 何时可见 | 内容 |
|----|----------|------|
| L0 原生/HTML 底色 | show 当下 | `#f3f3f4`（现行 `--sf-neutral-100` / `--sf-shell-bg`） |
| L1 壳骨架 | chrome 未就绪或路由 pending | `ShellLayoutSkeleton`（或等价） |
| L2 壳 chrome | spaces + sidebar settings ready | Header / Sidebar / Footer |
| L3 主区数据 | 各 scene query ready | Board / List / Detail |

**原则**：L0→L1 无白；L1→L2→L3 只替换内容区，窗几何不动。

# 5. 目标架构（模块化）

## 5.1 分层与边界

```txt
src-tauri/crates/runtime/src/window/
  main.rs                 # 薄：常量、label、对外 build/toggle
  main_lifecycle.rs       # 新：隐藏创建 → restore/fallback → show（唯一编排）
  （既有）launcher/       # 禁止依赖 main_lifecycle；几何策略独立

frontend:
  index.html              # inline 壳色（L0）
  layout/ShellLayout*     # L1/L2 唯一壳首屏
  app/navigation memory   # 路由记忆；与窗几何正交，禁止交叉写入
```

### 职责表

| 模块 | 职责 | 不做什么 |
|------|------|----------|
| `main_lifecycle` | 主窗创建与首次可见编排 | 不读业务 DB 结果；不管 Launcher |
| `window-state` 插件 | 持久化 SIZE/POSITION/MAXIMIZED | 不持久化 VISIBLE；不跟踪 launcher label |
| `toggle_main_window` / tray / single-instance | 可见性切换 | 不 center、不改 bounds |
| `ShellLayoutSkeleton` | L1 壳占位 | 不承担原生几何 |
| `memoryStore` | 工作区路径记忆 | 不存窗坐标 |

## 5.2 DRY / KISS 约束

1. **几何恢复只有一条路径**：`main_lifecycle`；禁止在 tray/FE/多处再写 `center`。
2. **可见性只有一类调用**：`show` / `hide` / `set_focus`；与几何 API 分离。
3. **默认尺寸常量单处定义**（已有 `MAIN_WINDOW_*`），fallback center 复用，不复制魔法数。
4. **不做「第三种首屏页」**：删除或降级独立 `RootRestorePending` 中间态（W2）。
5. **不引入新 npm 几何库**：Tauri 官方插件即可。

## 5.3 插件配置规格（关键）

推荐注册形态（实现时以当前插件 API 为准）：

```rust
.plugin(
  tauri_plugin_window_state::Builder::new()
    // 托盘 hide 语义：切勿恢复「隐藏」
    .with_state_flags(
      StateFlags::SIZE | StateFlags::POSITION | StateFlags::MAXIMIZED
      // 显式不含 VISIBLE / FULLSCREEN（FULLSCREEN 是否纳入：默认否，避免误恢复）
    )
    // 仅 main；Launcher 浮层绝不能吃这套
    .with_filter(|label| label == "main")
    .build()
)
```

若当前版本 filter API 名称不同，等价目标不变：**只跟踪 `main`；flags 不含 `VISIBLE`。**

创建时：

```rust
.visible(false)
// build
// restore_state(SIZE|POSITION|MAXIMIZED) 或依赖插件 on_ready 自动 restore
// 若无状态：center()（仍 hidden）
// show + set_focus
```

**删除**今日「`visible(true)` 后再 `center()`」顺序。

## 5.4 与 DB bootstrap 的关系

保持现策略：`bootstrap_database` 在建窗前 `block_on`（本地可用优先）。

本方案 **不**把「窗 show」延后到 DB 之后更久；DB 仍挡在建窗前。若未来 DB 变慢，另开波次「先出壳后灌数据」，不在本方案范围。

## 5.5 FE 首屏合并（W2）

现状：

- `/` → `pendingComponent: RootRestorePending`（居中文案）
- 进壳后 → `ShellLayoutSkeleton`

目标：

- `/` pending 与壳未就绪 **共用同一壳骨架组件**（或 pending 直接渲染 `ShellLayoutSkeleton`）。
- 文案可作为骨架主区 status，不再换一套页面布局。
- 符合「一次壳轮廓」；避免设计系统两套 loading 语言。

动效（`make-interfaces-feel-better`）：

- **禁止**整页入场大动画干扰开屏（`initial={false}` 类原则）。
- 数据替换 skeleton 可用短 opacity；**禁止**位移动画。
- 不用 `transition: all`。

# 6. 实现分期

## W0 · 接线与防跳（必做，收益最大）

**改动面（预计）**

- `runtime/src/lib.rs`：注册 `window-state` 插件（flags + filter）。
- `runtime/src/window/main.rs`（或抽出 `main_lifecycle.rs`）：`visible(false)` → restore/fallback → `show`。
- 删除可见后的强制 `center()`。
- 确认 `capabilities/main.json` 权限仍足够（已有 `window-state:default`）。
- 文档：在 `src-tauri/ARCHITECTURE.md` / `window` 模块注释写清「几何 vs 可见性」。

**验收**

- [ ] 冷启动无可见跳动。
- [ ] 移动/缩放后完全退出再开，位置与尺寸恢复。
- [ ] 关到托盘再点开：不 center、不改尺寸。
- [ ] Launcher 位置/行为无回归。
- [ ] 首次安装（清 window-state 文件）仅居中一次且无跳动。

## W1 · 消灭白闪

**改动面**

- `index.html`：`html, body, #root` inline `background: #f3f3f4`（与 `--sf-neutral-100` 对齐；注释标明同步 token）。
- 主窗 builder：设置与壳一致的背景色（Tauri/WebView 平台 API 以当前版本文档为准；至少 HTML 层必做）。
- 可选：暗色主题落地后再做主题感知底色（本波次可不做）。

**验收**

- [ ] 慢机器/冷缓存下，show 瞬间无刺眼白闪（允许极短同色底）。
- [ ] 与现亮色壳视觉连续。

## W2 · 统一首屏

**改动面**

- `src/routes/index.tsx`：pending 改用壳骨架，去掉独立「正在恢复…」全页。
- 如需，微调 `ShellLayoutSkeleton` status 文案位。
- 保证 `ShellLayoutContent` 门闸与骨架单一入口。

**验收**

- [ ] 冷启动视觉阶段 ≤ 2（稳窗壳色/骨架 → 数据）。
- [ ] 无居中反馈页 → 骨架的布局跳变。

## W3 · 稳健性（可选增强）

- 恢复后检测窗是否在任一 display work area 内；否则 hidden `center` 回退。
- DPI / 缩放剧变时的尺寸钳制（不低于 `MAIN_WINDOW_MIN_*`）。
- 最大化状态与 Windows/macOS 装饰差异回归矩阵。
- 主题切换时更新原生/HTML 底色（若上暗色）。

# 7. 测试与验证矩阵

| 场景 | 期望 |
|------|------|
| 首次安装 | 居中出现，无跳动，壳色 |
| 单屏挪到右下角后重启 | 仍在右下角同尺寸 |
| 最大化后退出再开 | 仍最大化 |
| 关窗（hide）再托盘打开 | 几何不变，仅 show |
| 单实例二次启动 | 同热唤起 |
| 外接屏断开后启动 | 不离屏；回退居中或主屏安全区 |
| 打开 Launcher | 不受 main restore 影响 |
| 慢启动（throttle CPU） | 无白闪、无跳动；可长时间骨架 |

自动化建议：

- Rust：lifecycle 单元测难以覆盖 OS 窗，优先集成/手工清单。
- FE：骨架组件测保留；不必 mock 原生几何。
- 发布前：Windows + macOS 各跑一遍矩阵。

# 8. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 误持久化 `VISIBLE` → 冷启动窗不可见 | **高** | flags 显式排除；测试「关到托盘后杀进程再开」 |
| Launcher 被 window-state 污染 | **高** | `with_filter` 仅 `main`；回归 Launcher |
| 插件 restore 时机仍闪一下 | 中 | 严格 `visible(false)`；官方 tip；必要时手动 `restore_state` 再 `show` |
| 离屏坐标 | 中 | W3 校验；W0 可先依赖插件默认行为并记录已知限制 |
| HTML 硬编码色与 token 漂移 | 低 | 注释 + 设计 token 变更 checklist |
| show 过晚感觉慢 | 低 | **不**等业务数据；只等几何 + 底色 |
