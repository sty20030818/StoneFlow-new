## 1. 当前结构

当前系统分成四层：

1. `src/features/command`
   - 全局应用内命令；
   - 全局应用内快捷键；
   - Command Menu；
   - Shortcut Help；
   - Chord Hint。

2. `src/features/task/shortcuts`
   - Task Row 局部快捷键；
   - 基于 hover / focus / active drawer / selection 的 row target 解析。

3. `src/shared/ui/shortcut-menu`
   - Dropdown 打开时的数字选择层。

4. `src-tauri/crates/helper-app`
   - 系统级 `Option+Space`；
   - Quick Create 浮窗唤起与 IPC。

## 2. Scoped Picker 模式

当前只有两条命令会进入 scoped picker 模式：

| 命令 | 快捷键 | 进入的 mode | 当前行为 |
|---|---|---|---|
| `open.task` | `O T` | `task-picker` | 打开 Command Menu，并切成“只搜索任务”的 scoped picker。 |
| `open.project` | `O P` | `project-picker` | 打开 Command Menu，并切成“只搜索项目”的 scoped picker。 |

结论：

1. 这不是独立弹窗；
2. 这不是第二套 UI；
3. 它复用同一个 `CommandMenu` 容器，只是 `mode` 不同；
4. `default` 模式显示 registry 命令组；
5. `task-picker` / `project-picker` 模式只显示搜索结果，不显示默认命令分组。

## 4. Task Row 快捷键

这一层不走全局 `CommandShortcutLayer`，而是走 `TaskRowShortcutScope`。

### 4.1 目标解析

当前 row target 优先级：

1. hover 行；
2. keyboard focus 行；
3. 已打开 drawer 对应行；
4. 单选 selection；
5. 多选时不产生单行 target。

### 4.2 已接入行为

| 快捷键 | 入口 | 触发条件 | 当前行为 | 状态 |
|---|---|---|---|---|
| `W` | Row 层键盘 | 有 row target；非输入态；无上层 dropdown/menu 阻断 | 完成或取消完成目标任务；多选时批量执行 | 已接入 |
| `X` | Row 层键盘 | 同上 | 切换目标任务选择状态 | 已接入 |
| `Space` | Row 层键盘 | 有单行 target；非输入态；无阻断 | 打开目标任务 | 已接入 |
| `Enter` | Row 层键盘 | 有单行 target；非输入态；无阻断 | 打开目标任务 | 已接入 |
| `A` | Row 层键盘 | 有 row target；非输入态；无阻断 | 归档目标任务；多选时批量执行 | 已接入 |
| `Delete` | Row 层键盘 | 有 row target；非输入态；无阻断 | 删除目标任务；多选时批量执行 | 已接入 |
| `Cmd+Backspace` | Row 层键盘 | 同上 | 删除目标任务；多选时批量执行 | 已接入 |
| `Ctrl+Backspace` | Row 层键盘 | 同上 | 删除目标任务；多选时批量执行 | 已接入 |
| `P` | Row 层键盘 | 有 row target；非输入态；无阻断 | 点击当前行已有的优先级 trigger | 已接入 |
| `S` | Row 层键盘 | 有 row target；非输入态；无阻断 | 点击当前行已有的状态 trigger | 已接入 |

### 4.3 Row 层已注册但当前没接上的 command 语义

registry 中的这些 `task.*` 命令目前仍显示为 disabled：

- `task.peek`
- `task.openDetail`
- `task.rename`
- `task.setPriority`
- `task.setStatus`
- `task.openDateMenu`
- `task.archive`
- `task.delete`
- `task.convertToProject`
- `task.createProjectFromTask`

原因不是 row 层完全没行为，而是：

2. row scope 的真实行为由 `TaskRowShortcutScope` 单独实现；
3. 所以“局部快捷键可用”和“全局命令面里该命令已接业务”是两件事。

## 5. Dropdown 数字选择

### 5.1 当前规则

| 规则 | 当前实现 |
|---|---|
| 作用范围 | 只在 dropdown content 挂载期间 |
| 触发键 | 单个数字键 `0-9` |
| 编号起点 | 有空态项时从 `0` 开始，否则从 `1` 开始 |
| 选择结果 | 调用原有 `onSelect(item)` |
| 关闭行为 | 选择后自动发 `Escape` 关闭 dropdown |
| 状态边界 | 不依赖 command registry；不注册 `CommandId` |

### 5.2 当前状态

这层已经是独立 primitive，逻辑已接入，属于已完成能力。

## 8. 当前阻断规则

### 8.1 全局命令层

1. 文本输入中默认不触发普通单键和 chord；
2. `Cmd/Ctrl+K`、`Cmd/Ctrl+/` 允许输入态触发；
3. `ShortcutHelp` 打开时，全局层只保留帮助页自己的 toggle；
4. 其余普通全局命令被阻断。

### 8.2 Row 层

1. 输入态不触发；
2. 上层 dropdown/menu content 存在时不触发；
3. 只在有 row target 时触发。

### 8.3 Dropdown 数字层

1. 只在 dropdown content 挂载时存在；
2. 不拦截带 `meta/ctrl/alt` 的组合键；
3. 只处理单数字。

### 10.3 v2 中有快捷键，但当前不建议直接补为默认快捷键的项

这些项虽然在 v2 中写了快捷键，但直接落地会带来冲突或范围膨胀，建议先确认产品优先级。

| 快捷键 | v2 用途 | 不建议直接补的原因 | 建议 |
|---|---|---|---|
| `Cmd/Ctrl+Shift+C` | Copy Task Title | 和系统 / 浏览器 /开发工具复制心智接近，默认占用偏重 | 先做 command-only，确认高频后再绑定。 |
| `Cmd/Ctrl+D` | Duplicate Task | 在浏览器环境常见为书签，且复制任务不是当前主链 | 先做 command-only。 |
| `[` / `]` | Toggle Sidebar / Preview | 单键符号可能和文本输入、系统键盘布局、未来列表操作冲突 | 可先保留为 registry 命令，等布局状态稳定后再绑定。 |
| `F` | Add Filter | `F` 作为单键会引入新的全局前缀 / 单键冲突，需要和 `F P/F S/F C` 的 chord 体验一起设计 | 不建议只单独补 `F`，应整体实现筛选快捷键层。 |
| `Cmd/Ctrl+B` | Toggle List / Board | 可能和富文本加粗冲突；输入态必须严格阻断 | 需要等列表/看板切换真实存在后再接。 |
| `Shift+V` | Show Display Options | `V` 在 v2 中刻意不做创建入口，但 `Shift+V` 心智仍偏弱 | 可作为后期展示面板快捷键，不进入当前主链。 |

### 10.4 当前清单相对 v2 的主要结论

1. 当前已经完成的是“应用内 Command Menu + 高频创建/导航/打开 + Row 层部分任务操作 + Dropdown 数字选择 + Helper Quick Create”。
2. v2 中“任务整理流”的关键缺口是 `D / R / M P / M I / M N / Shift+↑/↓ / Cmd/Ctrl+A / Esc 清空选择`。
3. v2 中“全局窗口级操作”的关键缺口是 `Esc / Cmd/Ctrl+Enter / Cmd/Ctrl+, / Cmd/Ctrl+[ / Cmd/Ctrl+]`。
4. v2 中“筛选与视图”的命令框架已经有一部分 registry，但没有任何快捷键和真实业务。
5. v2 中“复制、恢复、导出、活动记录、模板、Space、收藏、排序、分组”等大量项目仍没有进入 registry，当前应视为后期能力，不应计入阶段 16 主链。
6. 如果下一阶段继续推进，优先级建议是：先补 `Esc` 层级规则和 Row 层 `D/R/M*`，再补筛选 `F*`，最后补 command-only 的复制 / 恢复 / 输出类命令。
