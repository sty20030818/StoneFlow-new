# StoneFlow 命令与快捷键系统技术方案 v2

> Command First + Shortcut Manager 的键盘驱动架构设计

---

## 1. 文档定位

StoneFlow 是一个以「快」为核心的个人任务管理工具。命令与快捷键系统是 StoneFlow 键盘驱动体验的底层基础。

本文档用于定义 StoneFlow 命令系统的技术架构、核心模型、模块职责、快捷键分层、执行流程、菜单数字协议、Row 上下文解析、Command Menu 接入方式，以及 V1 的实现阶段。

这份文档偏「技术实现 / 架构落地」，目标是让后续开发或 AI 生成代码时遵循统一方案，避免把快捷键、业务逻辑、UI 事件和页面状态散落在 Header、Search、Row、Dropdown、Dialog 各处。

---

## 2. 背景与目标

### 2.1 背景

StoneFlow 需要支持大量键盘操作：

- 应用外快速唤起 Quick Create；
- 应用内快速创建任务；
- 快速跳转固定页面；
- 快速打开任务、项目、视图、空间；
- 快速修改任务状态、优先级、日期、项目；
- 快速完成、选择、批量处理任务；
- 快速在 Dropdown 中用数字选择选项；
- 快速从 Command Menu 中搜索并执行所有命令。

如果继续在各组件中直接监听键盘，会很快出现问题：

- Header 监听 `C`；
- Search 监听 `/`；
- Command Menu 监听 `Cmd/Ctrl + K`；
- Row 监听 `P / S / D / W`；
- Dropdown 监听 `0~5`；
- Dialog / Drawer / Popover 又各自处理 `Esc / Enter`。

最终会导致：

- 同一个键被多个层级抢占；
- 输入框中误触快捷键；
- 弹窗打开时底层页面仍响应快捷键；
- 快捷键文案和实际行为不一致；
- 快捷键帮助页无法自动生成；
- 后续自定义快捷键、Command Menu 排序、AI 命令接入都变得困难。

因此 StoneFlow 需要一个中心化的 Command + Shortcut 架构。

### 2.2 核心目标

V1 技术目标：

- 建立统一 Command 抽象；
- 建立统一 Keybinding 快捷键模型；
- 建立统一 Command Context 上下文模型；
- 建立统一 ShortcutManager 应用内快捷键调度；
- 支持系统级快捷键与应用内快捷键分层；
- 支持两段式前缀快捷键；
- 支持 Row 上下文目标解析；
- 支持 Dropdown 数字选择协议；
- 支持 Command Menu 从 Registry 自动读取命令；
- 支持不同上下文下的命令可见、可用、排序；
- 支持输入框保护与弹层优先级；
- 支持快捷键帮助页自动生成；
- 为后续自定义快捷键、AI 命令、插件化命令预留结构。

### 2.3 非目标

V1 暂不实现：

- 用户自定义快捷键；
- 快捷键设置页；
- 快捷键云同步；
- 快捷键冲突可视化编辑器；
- Vim-like 默认导航；
- 三段及以上复杂 chord；
- 完整插件系统；
- AI 自动命令编排；
- 完整 Undo Stack；
- 跨窗口复杂命令同步；
- 系统级注册大量全局快捷键。

这些能力可以预留字段和扩展点，但不进入 V1 实现范围。

## 3. 核心架构原则

### 3.1 Command First

StoneFlow 的所有用户动作都应该优先抽象为 `Command`。

快捷键、Command Menu、按钮点击、右键菜单、顶部菜单，本质上都是触发 Command 的不同入口。

```txt
Button / Menu / Shortcut / Command Menu / Context Menu
                          ↓
                      Command
                          ↓
                  Application Service
                          ↓
              Store / Router / SQLite / Tauri
```

### 3.2 Shortcut 只是 Command 的入口

快捷键不应该直接写业务逻辑。

正确链路：

```txt
Keyboard Event
      ↓
ShortcutManager
      ↓
CommandRuntime.execute(commandId)
      ↓
Command.run(ctx)
      ↓
Application Service
```

不推荐：

```txt
Keyboard Event
      ↓
直接修改 task store / router / sqlite
```

### 3.3 系统级与应用内严格分层

StoneFlow 的快捷键分为四层：

```txt
Layer A：系统级全局快捷键
Layer B：应用内全局快捷键
Layer C：列表 / Row 上下文快捷键
Layer D：Dropdown 菜单内数字快捷键
```

不同层级由不同模块负责，不能混在一起。

### 3.4 统一调度，局部执行

所有应用内键盘事件应该由 `ShortcutManager` 统一调度。

但具体动作仍由各业务模块提供。

```txt
ShortcutManager 负责判断：哪个键、哪个层级、哪个上下文、哪个 Command
Feature Service 负责执行：创建任务、移动任务、修改状态、归档任务
```

### 3.5 输入态保护优先

只要当前焦点在输入框、textarea、contenteditable 中，普通字母键和前缀键都不能触发快捷键。

允许的输入态快捷键只保留少量系统行为，例如：

- `Esc`；
- `Cmd/Ctrl + Enter`；
- `Cmd/Ctrl + K`；
- `Cmd/Ctrl + Z`；
- `Cmd/Ctrl + Shift + Z`。

### 3.6 弹层优先级高于页面

当 Dropdown、Modal、Command Menu、Drawer 打开时，键盘事件应优先作用于最上层 UI。

底层页面不能穿透响应危险操作。

## 4. 快捷键分层模型

## 4.1 Layer A：系统级全局快捷键

系统级全局快捷键由 Tauri / Helper 负责。

V1 只保留：

| 快捷键 | 作用 |
|---|---|
| `Option + Space` | 应用外唤起 Quick Create |

### 职责

- 在 StoneFlow 不聚焦时唤起 Quick Create；
- 只负责窗口唤起和事件传递；
- 不负责应用内 Row 操作；
- 不负责 Dropdown 数字选择；
- 不负责任务属性修改。

### 边界

系统级快捷键不承接：

- `C` 快速创建任务；
- `W` 完成任务；
- `P / S / D` 属性菜单；
- `0~5` Dropdown 数字选择；
- `G / O / N / M / F` 应用内前缀快捷键。

---

## 4.2 Layer B：应用内全局快捷键

应用内全局快捷键由 React 前端的 `ShortcutManager` 负责。

代表快捷键：

| 快捷键 | 作用 |
|---|---|
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `/` | 搜索 |
| `C` | 当前上下文快速创建任务 |
| `N T` | 完整创建任务 |
| `N I` | 创建任务到 Inbox |
| `G I` | 跳转 Inbox |
| `O P` | 打开项目 |
| `Cmd/Ctrl + [` | 后退 |
| `Cmd/Ctrl + ]` | 前进 |

触发条件：

- app 已聚焦；
- 当前不是文本输入态；
- 没有更高优先级弹层接管键盘。

---

## 4.3 Layer C：列表 / Row 上下文快捷键

列表上下文快捷键依赖当前任务、项目或列表焦点。

代表快捷键：

| 快捷键 | 作用 |
|---|---|
| `W` | 完成 / 取消完成任务 |
| `X` | 选择当前项 |
| `Shift + ↑/↓` | 连续选择 |
| `Space` | 预览 |
| `Enter` | 打开详情 |
| `P` | 打开优先级菜单 |
| `S` | 打开状态菜单 |
| `D` | 打开日期菜单 |
| `R` | 重命名 |
| `A` | 归档 |
| macOS: `Cmd + Backspace` | 删除 |
| Windows / Linux: `Delete` | 删除 |

触发条件：

- 存在明确 Row Target；
- 当前不是文本输入态；
- 当前没有 Dropdown / Modal / Command Menu 等更高优先级层级；
- 当前目标允许交互。

---

## 4.4 Layer D：Dropdown 菜单内数字快捷键

菜单数字快捷键只在 Dropdown / Select / Menu 打开时生效。

代表规则：

| 菜单 | 数字规则 |
|---|---|
| Status Menu | `1~5` |
| Priority Menu | `0~4` |
| Date Menu | `0~4` |
| Project Menu | `0~N` |

触发条件：

- 菜单已打开；
- 菜单声明支持数字选择；
- 当前焦点仍在菜单所属上下文内；
- 数字在当前菜单项范围内。

菜单关闭时，数字键不作为全局快捷键使用。

## 6. 模块职责

## 6.1 `shared/shortcuts`

纯协议与无业务工具。

职责：

- 定义快捷键基础类型；
- 定义输入态 guard；
- 定义快捷键显示格式；
- 定义前缀序列工具；
- 定义平台快捷键格式化；
- 不读取业务 Store；
- 不执行 Command；
- 不操作 Router / SQLite。

示例职责：

```txt
formatShortcut("CmdOrCtrl+K")
isEditableElement(event.target)
parseSequence("G I")
```

---

## 6.2 `app/shortcuts`

应用内统一调度层。

职责：

- 监听应用内键盘事件；
- 统一输入态保护；
- 统一层级优先级判断；
- 维护前缀等待状态；
- 匹配 Keybinding；
- 调用 CommandRuntime；
- 维护 Chord Hint。

不负责：

- 不直接写业务数据；
- 不直接操作任务 / 项目；
- 不渲染具体 Dropdown；
- 不知道具体 Row DOM 结构。

---

## 6.3 `command/core`

Command 核心运行层。

职责：

- 定义 Command 类型；
- 注册所有命令；
- 生成 CommandContext；
- 判断命令可见性；
- 判断命令可执行性；
- 计算排序权重；
- 执行命令；
- 统一错误处理；
- 记录最近使用命令。

---

## 6.4 `command/commands`

领域命令定义层。

按领域拆分：

- general；
- navigation；
- open；
- new；
- list；
- task；
- project；
- view；
- filter；
- inbox；
- layout；
- system。

每个命令只描述：

- 命令 id；
- 标题；
- 分类；
- 快捷键；
- 可见性；
- 可执行性；
- 排序；
- 执行时调用哪个 service。

---

## 6.5 `features/task/shortcuts`

Row 上下文快捷键目标层。

职责：

- 维护当前 hover row；
- 维护当前 keyboard-focused row；
- 维护当前 active row；
- 维护 selected row；
- 为 `W / X / P / S / D / R / A / Space / Enter` 提供目标；
- 支持多选场景下的批量目标。

不负责：

- 不监听全局键盘；
- 不维护前缀状态机；
- 不执行复杂业务；
- 不处理 Command Menu 搜索。

---

## 6.6 `shared/ui/shortcut-menu`

Dropdown 数字选择共享工具。

职责：

- 菜单项右侧渲染数字提示；
- 根据有无空态决定从 `0` 还是 `1` 开始；
- 菜单打开时接管 `0~9` 数字选择；
- 超出范围数字忽略；
- 菜单关闭后释放数字键。

## 8. Command Context 上下文设计

### 8.1 上下文作用

Command Context 是命令系统的统一输入。

它用于判断：

- 当前命令是否可见；
- 当前命令是否可执行；
- 当前命令作用于哪个对象；
- 当前命令在 Command Menu 中排多高；
- 当前快捷键是否应该生效。

### 8.2 Context 基础结构

```ts
type CommandContext = {
  route: RouteContext
  selection: SelectionContext
  focus: FocusContext
  rowTarget: RowTargetContext
  space: SpaceContext
  project: ProjectContext
  view: ViewContext
  ui: UIContext
}
```

### 8.3 RouteContext

```ts
type RouteContext = {
```

### 8.9 Context 生成原则

Command Context 应该：

- 在执行命令前实时生成；
- 不长期缓存关键状态；
- 不直接暴露复杂 Store；
- 尽量保持只读；
- 作为所有命令判断的唯一输入。

## 9. Row Target Resolver 设计

### 9.1 目标

Row 上下文快捷键必须知道当前到底操作哪一行。

例如：

- `W` 完成哪条任务；
- `P` 打开哪条任务的优先级菜单；
- `Space` 预览哪条任务；
- `Enter` 打开哪条任务详情；
- 多选时 `W` 是批量完成还是单条完成。

### 9.2 目标解析优先级

```txt
hover row
> keyboard-focused row
> active row
> 单选 selected row
> 无目标，不响应
```

### 9.3 多选规则

如果存在多选：

| 快捷键 | 行为 |
|---|---|
| `W` | 批量完成 / 取消完成 |
| `P` | 批量打开优先级菜单 |
| `S` | 批量打开状态菜单 |
| `D` | 批量打开日期菜单 |
| `M P` | 批量移动到项目 |
| `M I` | 批量移动到 Inbox |
| `M N` | 批量移动到无项目 |
| `A` | 批量归档 |
| Delete | 批量删除 |
| `R` | 不生效或隐藏，避免批量重命名歧义 |
| `Space` | 不生效或预览 active row，V1 建议不生效 |
| `Enter` | 不生效或打开 active row，V1 建议不生效 |

### 9.4 RowTargetResolver 示例

```ts
type ResolveRowTargetInput = {
  hover?: RowRef
  keyboardFocus?: RowRef
  active?: RowRef
  selection: SelectionContext
}

function resolveRowTarget(input: ResolveRowTargetInput): RowTargetContext {
  if (input.hover) {
    return toRowTarget(input.hover, "hover")
  }

  if (input.keyboardFocus) {
    return toRowTarget(input.keyboardFocus, "keyboard-focus")
  }

  if (input.active) {
    return toRowTarget(input.active, "active")
  }

  if (input.selection.isSingleSelection && input.selection.ids[0]) {
    return {
      targetId: input.selection.ids[0],
      targetType: input.selection.type,
      source: "selected",
      hasTarget: true,
      isTaskTarget: input.selection.type === "task",
      isProjectTarget: input.selection.type === "project",
    }
  }

  return {
    source: "none",
    hasTarget: false,
    isTaskTarget: false,
    isProjectTarget: false,
  }
}
```

## 10. Command Registry 设计

### 10.1 Registry 职责

Command Registry 负责：

- 注册所有命令；
- 根据 id 获取命令；
- 获取全部命令；
- 按 category 获取命令；
- 校验重复 id；
- 给 Command Runtime、Command Menu、Shortcut Manager、快捷键帮助页提供数据源。

### 10.2 注册方式

命令按领域拆分。

```ts
export const taskCommands: Command[] = [
  completeTaskCommand,
  selectTaskCommand,
  renameTaskCommand,
  setTaskPriorityCommand,
  setTaskStatusCommand,
  openDateMenuCommand,
  moveTaskToProjectCommand,
  moveTaskToInboxCommand,
  moveTaskToNoProjectCommand,
]
```

统一汇总：

```ts
export const allCommands: Command[] = [
  ...generalCommands,
  ...navigationCommands,
  ...openCommands,
  ...newCommands,
  ...listCommands,
  ...taskCommands,
  ...moveCommands,
  ...projectCommands,
  ...viewCommands,
  ...filterCommands,
  ...inboxCommands,
  ...layoutCommands,
  ...systemCommands,
]
```

### 10.3 Registry 示例

```ts
class CommandRegistry {
  private commands = new Map<CommandId, Command>()

  register(command: Command) {
    if (this.commands.has(command.id)) {
      throw new Error(`Duplicate command id: ${command.id}`)
    }

    this.commands.set(command.id, command)
  }

  registerMany(commands: Command[]) {
    commands.forEach((command) => this.register(command))
  }

  get(commandId: CommandId) {
    return this.commands.get(commandId)
  }

  getAll() {
    return Array.from(this.commands.values())
  }

  getByCategory(category: CommandCategory) {
    return this.getAll().filter((command) => command.category === category)
  }
}
```

### 10.4 Registry 不应该做的事

Command Registry 不应该：

- 监听键盘事件；
- 读取 DOM；
- 直接写数据库；
- 处理 UI 展示；
- 在注册阶段执行命令；
- 保存运行时上下文。

## 11. Command Runtime 设计

### 11.1 Runtime 职责

Command Runtime 是命令执行前后的统一处理层。

负责：

- 判断命令是否可见；
- 判断命令是否可执行；
- 获取禁用原因；
- 计算命令排序权重；
- 执行命令；
- 统一错误处理；
- 记录最近使用命令；
- 后期接入 Activity Log。

### 11.2 执行流程

```txt
trigger command
      ↓
get current context
      ↓
find command by id
      ↓
check visible
      ↓
check enabled
      ↓
run command
      ↓
handle result / error
      ↓
record recent command
```

### 11.3 Runtime 示例

```ts
class CommandRuntime {
  constructor(
    private registry: CommandRegistry,
    private getContext: () => CommandContext,
  ) {}

  canExecute(command: Command, ctx: CommandContext) {
    return command.isEnabled?.(ctx) ?? true
  }

  isVisible(command: Command, ctx: CommandContext) {
    return command.isVisible?.(ctx) ?? true
  }

  getPriority(command: Command, ctx: CommandContext) {
    return command.getPriority?.(ctx) ?? 0
  }

  async execute(commandId: CommandId) {
    const command = this.registry.get(commandId)
    if (!command) return

    const ctx = this.getContext()

    if (!this.isVisible(command, ctx)) return

    if (!this.canExecute(command, ctx)) {
      const reason = command.getDisabledReason?.(ctx)
      // toast(reason ?? "Command is disabled")
      return
    }

    try {
      await command.run(ctx)
      // recentCommandStore.record(command.id)
    } catch (error) {
      // log error
      // toast error
    }
  }
}
```

## 12. Command Priority 排序设计

### 12.1 排序目标

Command Menu 的排序应根据上下文变化。

例如：

- 选中任务时，`task.setPriority` 权重提高；
- 选中多个任务时，批量操作权重提高；
- 在项目页，`new.quickTask` 创建到当前项目，权重提高；
- 在收件箱，`task.moveToProject` 和 `task.createProjectFromTask` 权重提高；
- 在回收站，`restore` 类命令权重提高。

### 12.2 推荐评分公式

```ts
score =
  basePriority
  + contextBoost
  + selectionBoost
  + routeBoost
  + recentBoost
  + searchMatchBoost
```

### 12.3 示例

```ts
const moveTaskToInboxCommand: Command = {
  id: "task.moveToInbox",
  title: "Move to Inbox",
  category: "move",
  defaultShortcut: "M I",
  scope: ["task-list", "project-page"],
  isVisible: (ctx) => ctx.selection.type === "task" && ctx.selection.hasSelection,
  getPriority: (ctx) => {
    let score = 40

    if (ctx.selection.isMultiSelection) score += 20
    if (ctx.route.page === "project") score += 20
    if (ctx.route.page === "inbox") score -= 30

    return score
  },
  run: async (ctx) => {
    await taskService.moveToInbox(ctx.selection.ids)
  },
}
```

## 15. ShortcutManager 设计

### 15.1 职责

ShortcutManager 负责应用窗口内快捷键。

它负责：

- 监听 `keydown`；
- 标准化键盘事件；
- 判断是否处于输入状态；
- 判断当前活跃层级；
- 匹配单键快捷键；
- 将前缀键交给 ChordManager；
- 调用 CommandRuntime 执行命令。

### 15.2 触发流程

```txt
keydown
  ↓
normalize event
  ↓
check input guard
  ↓
check active layer
  ↓
if dropdown open → dropdown digit handler
  ↓
if chord active → chord manager
  ↓
match keybinding
  ↓
get command context
  ↓
commandRuntime.execute(commandId)
```

### 15.3 输入框保护

如果当前焦点在输入框、textarea、contenteditable 中：

允许：

- `Esc`；
- `CmdOrCtrl+Enter`；
- `CmdOrCtrl+K`；
- `CmdOrCtrl+Z`；
- `CmdOrCtrl+Shift+Z`。

阻止：

- 普通字母快捷键；
- 前缀快捷键；
- 任务操作快捷键；
- 页面导航快捷键；
- Dropdown 外部数字快捷键。

### 15.4 层级优先级

```txt
Dropdown / Select Menu / Context Menu
> Modal
> Command Menu
> Detail Drawer
> Preview Drawer
> Main Page
```

例如：

- Dropdown 打开时，数字键优先选择菜单项；
- Modal 打开时，`Esc` 优先关闭 Modal；
- Command Menu 打开时，`Enter` 优先执行当前高亮命令；
- 输入框中，字母优先输入文本。

### 15.5 ShortcutManager 不应该做的事

ShortcutManager 不应该：

- 直接执行业务逻辑；
- 直接修改任务数据；
- 直接跳转页面；
- 直接控制复杂 UI；
- 写死命令列表。

它只负责把键盘事件转换为 Command 执行。

## 17. Dropdown 数字选择协议

### 17.1 起始位规则

不是所有菜单都一律从 `1` 开始。

规则如下：

| 菜单类型 | 数字规则 | 示例 |
|---|---|---|
| 无空态菜单 | 从 `1` 开始 | status |
| 有空态菜单 | 从 `0` 开始 | priority、project、date |

判断标准不是业务实体类型，而是：

```txt
当前菜单里是否存在显式的「无 / 未设置 / 无归属 / 清空」选项
```

### 17.2 菜单项类型

```ts
type ShortcutMenuItem<TValue> = {
  label: string
  value: TValue
  isEmptyValue?: boolean
  disabled?: boolean
}
```

### 17.3 数字映射函数

```ts
type DigitShortcutMap<TValue> = Array<{
  digit: string
  item: ShortcutMenuItem<TValue>
}>

function buildDigitShortcutMap<TValue>(items: ShortcutMenuItem<TValue>[]) {
  const hasEmptyValue = items.some((item) => item.isEmptyValue)
  const start = hasEmptyValue ? 0 : 1

  return items.map((item, index) => ({
    digit: String(start + index),
    item,
  }))
}
```

### 17.4 Status Menu

状态菜单没有空态，从 `1` 开始。

```txt
1 = 待执行
2 = 进行中
3 = 等待中
4 = 已完成
5 = 已取消
```

### 17.5 Priority Menu

优先级菜单有「无优先级」，从 `0` 开始。

```txt
0 = 无优先级
1 = 低
2 = 中
3 = 高
4 = 紧急
```

### 17.6 Date Menu

日期菜单有「无时间」，从 `0` 开始。

```txt
0 = 无时间 / 清除日期
1 = 今天
2 = 明天
3 = 本周
4 = 自定义
```

### 17.7 Project Menu

项目菜单有「无项目 / 独立事项」，从 `0` 开始。

```txt
0 = 无项目 / 独立事项
1~N = 当前菜单显示顺序中的项目
```

### 17.8 行为规则

菜单已打开时：

- 数字键优先由菜单处理；
- 数字命中菜单项时直接选择；
- 数字超出范围时忽略；
- disabled 菜单项不可选择；
- 菜单关闭后数字键不再被该菜单接管。

## 22. 关键命令实现说明

### 22.1 `C`：Quick Create Task

`C` 永远表示快速创建任务。

它的目标由当前上下文决定。

| 当前页面 | 创建目标 |
|---|---|
| Inbox | Inbox |
| Project Detail | 当前项目 |
| All Tasks | Inbox |
| Today | Inbox，后期可默认计划时间为 Today |
| Upcoming | Inbox |
| Focus | Inbox |
| Custom View | Inbox |
| Archive / Trash / Settings | 不生效或提示不可创建 |

实现建议：

```ts
function resolveQuickCreateTarget(ctx: CommandContext): CreateTaskTarget | null {
  if (ctx.route.page === "project" && ctx.route.projectId) {
    return { type: "project", projectId: ctx.route.projectId }
  }

  if (["inbox", "allTasks", "today", "upcoming", "focus", "views"].includes(ctx.route.page)) {
    return { type: "inbox", spaceId: ctx.space.currentSpaceId }
  }

  return null
}
```

### 22.2 `N T`：Full Create Task

完整创建任务。

特点：

- 打开更完整的创建面板；
- 可以选择 Space；
- 可以选择 Project / Inbox / 无项目；
- 可以设置优先级、状态、日期、提醒、备注等；
- 不依赖当前页面目标，但可以带入当前上下文作为默认值。

### 22.3 `N I`：New Task in Inbox

强制创建到 Inbox。

即使用户在 Project 页面，`N I` 也创建到 Inbox。

### 22.4 `W`：Complete Task

`W` 用于完成 / 取消完成任务。

实现规则：

- 单选任务：切换当前任务完成状态；
- 多选任务：批量完成 / 取消完成；
- 无任务目标：不响应；
- 输入框中：输入字母 w，不触发快捷键。

### 22.5 `X`：Select Row

`X` 用于选择当前 Row。

实现规则：

- 有 Row Target：切换当前 Row 选择状态；
- 多选时保持 selectionStore；
- 输入框中不响应。

### 22.6 `Shift + ↑/↓`：Range Select

用于连续选择。

实现建议：

- 需要列表维护可见 row 顺序；
- selectionStore 记录 anchorId；
- Shift + Arrow 根据 anchor 和当前 focus 生成 range；
- 只选择当前可见列表范围，不跨页面。

### 22.7 `M I / M N`

移动命令：

- `M I`：移动到 Inbox；
- `M N`：移动到无项目 / 独立事项。

这两个命令用于区分：

| 归属 | 语义 |
|---|---|
| Inbox | 临时收集，待整理 |
| 无项目 / 独立事项 | 已经明确不属于任何项目 |

### 22.8 `Convert Task to Project`

Command-only。

语义：

- 当前任务本身转为项目；
- 原任务不再作为普通任务存在；
- 适合 Inbox 中「这其实是一个项目」的任务。

### 22.9 `Create Project from Task`

Command-only。

语义：

- 以当前任务标题创建项目；
- 原任务可以保留、完成或移动进项目；
- V1 可以先弹确认面板让用户选择策略。

## 23. 与 Tauri / Helper 的关系

### 23.1 应用内快捷键

应用窗口内部快捷键由 React 前端 ShortcutManager 处理。

包括：

- `C`；
- `W`；
- `P`；
- `S`；
- `D`；
- `N T`；
- `G I`；
- `O P`；
- `Cmd/Ctrl + K`。

### 23.2 系统级全局快捷键

系统级全局快捷键由 Tauri / Helper 处理。

V1 只包括：

- `Option + Space` 打开 Quick Create。

后期可以考虑：

- 打开主窗口；
- 打开全局 Command Window；
- 全局搜索。

### 23.3 分工原则

| 类型 | 处理方 |
|---|---|
| 应用窗口内快捷键 | React ShortcutManager |
| 系统级热键 | Tauri / Helper |
| 命令执行 | CommandRuntime |
| 数据变更 | Service + Store + SQLite |
| 窗口显示隐藏 | Tauri Window API / Helper |

### 23.4 全局热键与 Command 的连接

Tauri / Helper 收到全局热键后，不应该直接写复杂业务。

推荐流程：

```txt
Global Shortcut
      ↓
Tauri / Helper
      ↓
show Quick Create window
      ↓
frontend receives focus
      ↓
Quick Create handles input
      ↓
create task via taskService
```

## 24. 错误处理与安全规则

### 24.1 命令执行错误

命令执行失败时：

- 不崩溃应用；
- 显示 toast；
- 记录错误日志；
- 保持 UI 可恢复；
- 不丢失用户输入。

### 24.2 危险命令确认

| 命令 | V1 处理建议 |
|---|---|
| Delete Task | 移入回收站，不一定二次确认 |
| Delete Multiple Tasks | 可二次确认或提供 toast undo |
| Delete Project | 建议二次确认 |
| Empty Trash | 必须二次确认 |
| Archive Project | 可二次确认或 toast undo |

### 24.3 删除快捷键平台规则

| 平台 | 默认删除快捷键 |
|---|---|
| macOS | `Cmd + Backspace` |
| Windows / Linux | `Delete` |

实现上可以同时支持两者，但帮助页按平台优先展示。

### 24.4 Undo 预留

用户侧保留 `Cmd/Ctrl + Z`。

技术上可以分阶段：

| 阶段 | 方案 |
|---|---|
| V1 | 局部 toast undo，例如删除任务后可撤销 |
| V2 | 引入 action log，实现更多撤销 |
| V3 | 完整 undo stack |

- `O T` 打开任务搜索；
- `O P` 打开项目搜索；
- `W` 完成任务；
- `X` 选择当前项；
- `Shift + ↑/↓` 连续选择；
- `Space` 预览任务；
- `Enter` 打开详情；
- `P` 打开优先级菜单；

- `Cmd/Ctrl + ]` 前进；

### 27.2 体验验收

必须满足：

- 输入框中普通字母不会触发快捷键；
- Command Menu 打开足够快；
- 前缀快捷键有轻提示；
- Dropdown 数字提示和行为一致；
- 快捷键帮助页与实际命令一致；
- 单选 / 多选任务下命令排序不同；
- 项目页、收件箱、回收站有不同上下文优先级；
- 危险命令不会误触穿透；
- `Esc` 行为稳定且符合层级规则。

### 27.3 架构验收

必须满足：

- 系统级快捷键与应用内快捷键分离；
- 应用内快捷键统一由 ShortcutManager 调度；
- 命令定义和快捷键监听分离；
- Command Menu 不维护独立命令列表；
- 快捷键帮助页不手写静态表；
- Dropdown 数字选择使用共享协议；
- Row 目标解析统一，不由各 Row 自己猜；
- 业务逻辑主要在 Service 中；
- Command Runtime 统一处理执行；
- Context 是命令判断的统一输入；
- Registry 能检查重复 CommandId。

| `G` 和 `O` 是否分开 | 必须分开 |
| `Space` 用途 | 预览，不是完成 |
| 完成任务 | `W` |
| 选择当前项 | `X` |
| 连续选择 | `Shift + ↑/↓` |

## 30. 最终架构约定

StoneFlow 命令与快捷键系统采用以下核心约定：

```txt
Command 是一等公民
Shortcut 只是 Command 的入口
系统级和应用内严格分层
应用内快捷键统一由 ShortcutManager 调度
Row 目标统一由 RowTargetResolver 解析
Dropdown 数字选择统一由共享协议处理
Command Menu 消费 Command Registry
ShortcutManager 调用 CommandRuntime
业务逻辑沉到 Service
上下文统一由 CommandContext 提供
快捷键帮助页从 Registry 自动生成
```

核心执行链路：

```txt
Keyboard / Button / Command Menu
              ↓
        ShortcutManager / UI Trigger
              ↓
        Command Runtime
              ↓
          Command.run(ctx)
              ↓
        Application Service
              ↓
    Store / Router / SQLite / Tauri
```

V1 的重点不是做一个复杂的快捷键平台，而是建立一套干净、稳定、可扩展的命令底座。

只要这套底座稳定，后续的快捷键自定义、Command Menu 智能排序、AI 命令、全局窗口、插件化能力都可以自然叠加。
