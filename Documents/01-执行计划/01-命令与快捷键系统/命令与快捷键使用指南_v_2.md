# StoneFlow 命令与快捷键使用指南 v2

> 以键盘为核心的任务流操作规范

---

## 1. 文档定位

StoneFlow 是一个以「快」为主旨的个人任务管理工具。它不应该只依赖按钮、菜单和鼠标操作，而应该允许用户通过键盘快速完成大部分高频任务。

这份文档用于定义 StoneFlow 的命令体系、快捷键规则、使用场景、排序逻辑和扩展边界。

本文档偏「用户侧 / 产品侧」，重点回答：

- StoneFlow 有哪些核心命令；
- 哪些命令应该有默认快捷键；
- 哪些命令只进入 Command Menu；
- 不同页面、不同选中状态下，命令如何出现和排序；
- 快捷键如何分层；
- 菜单内数字快捷选择如何设计；
- 输入框、弹窗、抽屉、菜单打开时，快捷键应该如何处理。

---

## 2. 核心定位

### 2.1 Command 是一等公民

StoneFlow 的所有能力都应该优先抽象为 Command。

快捷键只是 Command 的一个入口，不是功能本身。

也就是说：

- 一个功能可以没有快捷键，但应该可以在 Command Menu 中被搜索和执行；
- 一个功能如果足够高频、稳定、低风险，才值得绑定默认快捷键；
- Command Menu 是 StoneFlow 的全局操作中心；
- 快捷键是高频命令的加速入口。

### 2.2 Command Menu 与 Quick Create 分离

StoneFlow 中存在两个不同的快速入口：

| 入口 | 定位 | 典型场景 |
|---|---|---|
| Quick Create | 极快创建任务 | 应用外 / 应用内快速捕获一条任务 |
| Command Menu | 操作整个软件 | 搜索、跳转、打开对象、执行命令、批量操作 |

二者可以共享底层命令系统，但不应该是同一个窗口。

Quick Create 只服务「快速创建」，Command Menu 服务「所有操作」。

### 2.3 快捷键不是越多越好

StoneFlow V1 不追求给每一个命令都绑定快捷键。

默认快捷键应该只覆盖：

- 高频创建；
- 高频导航；
- 高频搜索 / 打开；
- 任务的高频编辑；
- 任务的批量操作；
- 常用面板切换；
- 常用系统操作。

低频、危险、复杂、后期能力可以只存在于 Command Menu。

## 3. 快捷键分层模型

StoneFlow 的快捷键必须严格分层，避免系统级热键、应用内快捷键、局部菜单数字选择混在一起。

### 3.1 Layer A：系统级全局快捷键

系统级全局快捷键是指 StoneFlow 不在前台时也能触发的快捷键。

V1 只保留：

| 快捷键 | 作用 |
|---|---|
| `Option + Space` | 唤起 Quick Create |

系统级快捷键只负责应用外唤起，不负责任务列表操作、Dropdown 选择、Row 操作或页面内 Command。

### 3.2 Layer B：应用内全局快捷键

应用内全局快捷键是指 StoneFlow 窗口聚焦时，在大多数页面可用的快捷键。

例如：

| 快捷键 | 作用 |
|---|---|
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `/` | 搜索 |
| `C` | 快速创建任务 |
| `N T` | 完整创建任务 |
| `G I` | 跳转 Inbox |
| `O P` | 打开项目 |

触发条件：

- StoneFlow 应用窗口处于聚焦状态；
- 当前不是文本输入态；
- 没有更高优先级的弹窗、菜单或抽屉抢占快捷键。

### 3.3 Layer C：列表 / Row 上下文快捷键

列表上下文快捷键依赖当前任务、项目或列表焦点。

例如：

| 快捷键 | 作用 |
|---|---|
| `W` | 完成 / 取消完成当前任务 |
| `X` | 选择当前项 |
| `P` | 打开优先级菜单 |
| `S` | 打开状态菜单 |
| `D` | 打开日期菜单 |
| `R` | 重命名 |
| `A` | 归档 |
| `Space` | 预览 |
| `Enter` | 打开详情 |

这些快捷键不是系统级全局键，也不是输入态可触发的按键。

它们必须有明确目标行或明确选中对象。

### 3.4 Layer D：菜单内数字快捷键

菜单内数字快捷键只在 Dropdown / Select / Menu 打开时生效。

例如：

| 菜单 | 数字规则 |
|---|---|
| 状态菜单 | `1~5` |
| 优先级菜单 | `0~4` |
| 日期菜单 | `0~4` |
| 项目菜单 | `0~N` |

菜单关闭时，数字键不作为全局快捷键使用。

## 4. 核心设计原则

### 4.1 快捷键服务高频操作

默认快捷键只服务高频、稳定、低风险的命令。

例如：

- `C` 快速创建任务；
- `W` 完成任务；
- `P` 修改优先级；
- `S` 修改状态；
- `D` 打开日期菜单；
- `M P` 移动到项目；
- `G I` 跳转收件箱；
- `O P` 打开某个项目。

复制 URL、复制 ID、导出、恢复、查看活动记录等低频操作，优先只放在 Command Menu。

### 4.2 一个按键只表达一个稳定心智

StoneFlow 中，核心按键语义应该长期稳定。

```txt
C = Create Task
W = 完成
X = Select
P = Priority
S = Status
D = Date
R = Rename
A = Archive
G = Go to
O = Open
N = New
M = Move
F = Filter
```

其中 `C` 永远表示「创建任务」，不会在不同页面变成创建项目或创建视图。

项目和视图创建统一走 `N P`、`N V`。

### 4.3 上下文可以影响目标，但不能改变动作

`C` 永远是创建任务。

但创建到哪里，可以根据当前上下文决定。

例如：

| 当前场景 | `C` 的目标 |
|---|---|
| Inbox 页面 | 创建到 Inbox |
| Project 详情页 | 创建到当前项目 |
| All Tasks | 创建到 Inbox |
| Today | 创建到 Inbox，后期可默认计划时间为 Today |
| Upcoming | 创建到 Inbox |
| Focus | 创建到 Inbox |
| 自定义 View | V1 默认创建到 Inbox |
| Archive / Trash / Settings | 不生效或提示不可创建 |

原则：

> `C` 永远是 Create Task，只是默认归属目标根据明确容器变化。

### 4.4 输入状态下不抢普通按键

当用户正在输入任务标题、备注、搜索词或其他文本内容时，普通字母键不应该触发快捷键。

输入状态下仍可生效的快捷键主要是：

| 快捷键 | 作用 |
|---|---|
| `Esc` | 返回 / 关闭 / 取消 |
| `Cmd/Ctrl + Enter` | 保存 / 提交 |
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `Cmd/Ctrl + Z` | 撤销 |
| `Cmd/Ctrl + Shift + Z` | 重做 |

### 4.5 菜单打开时，菜单优先

当 Dropdown、Select、Context Menu 打开时，数字键、方向键、Enter、Esc 应优先作用于当前菜单。

底层页面不应该响应这些按键。

### 4.6 不做散装监听

应用内快捷键不应该散落在 Header、Search、Row、Dropdown、Dialog 各处。

所有应用内快捷键应该由统一 Shortcut Manager 调度。

组件只暴露动作，不直接成为全局键盘监听器。

## 5. 快捷键语法规则

### 5.1 单键快捷键

单键快捷键用于当前上下文最高频动作。

| 快捷键 | 动作 |
|---|---|
| `C` | 快速创建任务 |
| `W` | 完成 / 取消完成任务 |
| `X` | 选择当前项 |
| `Space` | 预览当前项 |
| `Enter` | 打开 / 编辑当前项 |
| `P` | 打开优先级菜单 |
| `S` | 打开状态菜单 |
| `D` | 打开日期菜单 |
| `R` | 重命名 |
| `A` | 归档 |
| `/` | 搜索 |
| `Esc` | 返回 / 关闭 / 清空 |

### 5.2 前缀快捷键

前缀快捷键用于可扩展命令。

用户先按前缀键，再按目标键。

| 前缀 | 含义 | 示例 |
|---|---|---|
| `N` | New，新建 | `N T`, `N I`, `N P`, `N V` |
| `G` | Go to，跳转固定页面 | `G I`, `G T`, `G P` |
| `O` | Open，搜索并打开对象 | `O T`, `O P`, `O V` |
| `M` | Move，移动 | `M P`, `M I`, `M N` |
| `F` | Filter，筛选 | `F P`, `F S`, `F C` |

### 5.3 修饰键快捷键

修饰键快捷键用于全局、系统级、窗口级操作。

| 快捷键 | 动作 |
|---|---|
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `Cmd/Ctrl + Enter` | 保存 / 提交 |
| `Cmd/Ctrl + /` | 查看快捷键 |
| `Cmd/Ctrl + ,` | 打开设置 |
| `Cmd/Ctrl + [` | 后退 |
| `Cmd/Ctrl + ]` | 前进 |
| `Cmd/Ctrl + Z` | 撤销 |
| `Cmd/Ctrl + Shift + Z` | 重做 |
| macOS: `Cmd + Backspace` | 删除选中项 |
| Windows / Linux: `Delete` | 删除选中项 |

### 5.4 前缀快捷键规则

| 规则 | 说明 |
|---|---|
| 最大长度 | V1 只支持两段式，如 `G I`、`O P` |
| 超时时间 | 用户按下前缀后，短时间内未继续输入则取消 |
| 按错处理 | 取消当前前缀状态，并给出轻提示 |
| `Esc` | 取消当前前缀状态 |
| 输入框中 | 不触发前缀快捷键 |
| 状态提示 | 可在界面角落显示当前前缀，如 `G …` |

## 6. General 全局命令

全局命令在大多数页面都可用。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Open Command Menu | `Cmd/Ctrl + K` | 打开命令菜单 |
| Open Search | `/` | 打开当前搜索 |
| Back / Close | `Esc` | 返回、关闭弹层、清空选择 |
| Save or Submit | `Cmd/Ctrl + Enter` | 保存当前编辑或提交当前表单 |
| View Keyboard Shortcuts | `Cmd/Ctrl + /` | 查看快捷键帮助 |
| Open Settings | `Cmd/Ctrl + ,` | 打开设置 |
| Go Back | `Cmd/Ctrl + [` | 回到上一个页面 / 上一个访问位置 |
| Go Forward | `Cmd/Ctrl + ]` | 前进到下一个访问位置 |
| Undo | `Cmd/Ctrl + Z` | 撤销上一步操作 |
| Redo | `Cmd/Ctrl + Shift + Z` | 重做操作 |

### 6.1 使用场景

- 用户想执行一个不记得快捷键的操作时，使用 `Cmd/Ctrl + K`；
- 用户想搜索当前页面或全局内容时，使用 `/`；
- 用户想退出当前状态时，使用 `Esc`；
- 用户想保存编辑时，使用 `Cmd/Ctrl + Enter`；
- 用户想在页面历史中后退 / 前进时，使用 `Cmd/Ctrl + [` / `Cmd/Ctrl + ]`。

## 7. Navigation 导航命令

导航命令用于跳转固定页面。

统一使用 `G` 前缀。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Go to Inbox | `G I` | 跳转收件箱 |
| Go to All Tasks | `G T` | 跳转全部任务 |
| Go to Today | `G D` | 跳转今日任务 |
| Go to Upcoming | `G U` | 跳转未来任务 |
| Go to Focus | `G F` | 跳转专注视图 |
| Go to Views | `G V` | 跳转视图中心 |
| Go to Projects | `G P` | 跳转项目页面 |
| Go to Archive | `G A` | 跳转归档 |
| Go to Trash | `G X` | 跳转回收站 |
| Go to Settings | `G S` | 跳转设置 |
| Go to Recent | `G R` | 跳转最近访问 / 最近上下文 |

### 7.1 `G` 的规则

`G` 只表示 Go to。

它用于固定页面或明确导航位置。

例如：

```txt
G P = Go to Projects
G I = Go to Inbox
G R = Go to Recent
```

### 7.2 `G` 与 `O` 的区别

| 目标 | 使用 |
|---|---|
| 去固定页面 | `G` |
| 打开具体对象 | `O` |

例如：

```txt
G P = Go to Projects Page
O P = Open Project
```

## 8. Open 打开对象命令

打开对象命令用于搜索并打开某个具体对象。

统一使用 `O` 前缀。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Open Task | `O T` | 搜索并打开任务 |
| Open Project | `O P` | 搜索并打开项目 |
| Open View | `O V` | 搜索并打开视图 |
| Open Space | `O S` | 搜索 / 切换空间 |
| Open Recent | `O R` | 打开最近访问对象 |
| Open Favorite | `O F` | 打开收藏项，后期支持 |

### 8.1 使用场景

- 用户知道自己要找某个任务，但不知道它在哪个项目；
- 用户想快速进入某个项目；
- 用户想打开最近访问的任务或项目；
- 用户想搜索某个自定义视图。

### 8.2 相关对象打开

当选中任务时，Command Menu 中可以出现：

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Open Related Project | Command only | 打开当前任务所属项目 |
| Open Current Project | Command only | 打开当前项目详情 |

这类命令不需要默认快捷键，但在上下文中非常有用。

## 9. New 创建命令

创建命令统一使用 `N` 前缀。

同时，任务快速创建有单键入口 `C`。

### 9.1 创建快捷键清单

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Quick Create Task | `C` | 当前上下文快速创建任务 |
| Full Create Task | `N T` | 完整创建任务 |
| New Task in Inbox | `N I` | 强制创建任务到 Inbox |
| New Project | `N P` | 新建项目 |
| New View | `N V` | 新建视图 |
| New Space | `N S` | 新建空间，后期支持 |
| New Task from Template | Command only | 从模板新建任务，后期支持 |
| New Project from Template | Command only | 从模板新建项目，后期支持 |

### 9.2 `C` 的创建目标规则

`C` 是当前上下文快速创建任务。

| 当前页面 / 场景 | `C` 创建目标 |
|---|---|
| Inbox 页面 | Inbox |
| Project 详情页 | 当前项目 |
| All Tasks | Inbox |
| Today | Inbox，后期可默认计划时间为 Today |
| Upcoming | Inbox |
| Focus | Inbox |
| 自定义 View | V1 默认 Inbox |
| Archive / Trash | 不生效或提示无法在此创建 |
| Settings | 不生效 |

### 9.3 在项目页创建到 Inbox

当用户在项目页面时：

| 快捷键 | 动作 |
|---|---|
| `C` | 创建到当前项目 |
| `N T` | 完整创建任务，可手动选择目标 |
| `N I` | 强制创建到 Inbox |

### 9.4 为什么不用 `V` 做完整创建

`V` 不作为全屏创建任务入口。

原因：

- `V` 更容易和 View 心智冲突；
- 完整创建任务用 `N T` 更清晰；
- `C` 已经承担快速创建；
- 不需要为了完整创建额外占用一个语义较弱的单键。

## 10. List / Board 列表与看板命令

列表 / 看板命令用于在任务列表、项目列表、看板列之间移动、选择、预览和打开内容。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Move Up | `↑` | 焦点上移 |
| Move Down | `↓` | 焦点下移 |
| Move Left | `←` | 看板中移动到左侧列 |
| Move Right | `→` | 看板中移动到右侧列 |
| Peek Focused Item | `Space` | 预览当前聚焦项 |
| Open Focused Item | `Enter` | 打开当前聚焦项 |
| Select Current Row | `X` | 选择当前项 |
| Range Select | `Shift + ↑/↓` | 连续选择 |
| Select All Visible Items | `Cmd/Ctrl + A` | 选择当前列表所有可见项 |
| Clear Selection | `Esc` | 清空选择 |
| Toggle Layout View | `Cmd/Ctrl + B` | 切换 List / Board |
| Show Display Options | `Shift + V` | 打开展示选项 |

### 10.1 不默认支持 Vim-like

StoneFlow V1 不默认支持：

```txt
J = Down
K = Up
GG = Top
G = Bottom
```

原因：

- StoneFlow 不是程序员专用工具；
- 方向键更符合通用用户习惯；
- 避免与 `G` 前缀导航体系冲突。

后期可作为可选设置支持。

### 10.2 Row 快捷键目标解析

列表上下文快捷键需要明确当前作用对象。

目标优先级：

```txt
hover row
> keyboard-focused row
> active row
> 单选 selected row
> 无目标，不响应
```

说明：

- hover row 表示用户最明确的当前操作意图；
- keyboard-focused row 支持纯键盘操作；
- active row 用于详情或预览打开时的当前行；
- selected row 只在单选且无 hover / focus / active 时兜底；
- 多选状态下，支持明确的批量命令，如 `W / P / S / D / M P / A / Delete`。

## 11. Task 任务命令

任务命令是 StoneFlow 最核心的一组命令。

### 11.1 单选任务命令

当用户选中或聚焦一个任务时，可使用以下命令：

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Quick Create Task | `C` | 在当前上下文快速创建任务 |
| Complete / Uncomplete Task | `W` | 完成 / 取消完成任务 |
| Select Task | `X` | 选择当前任务 |
| Peek Task | `Space` | 预览任务 |
| Open Task Detail | `Enter` | 打开任务详情 |
| Rename Task | `R` | 重命名任务 |
| Change Priority | `P` | 打开优先级菜单 |
| Change Status | `S` | 打开状态菜单 |
| Open Date Menu | `D` | 打开日期菜单 |
| Move to Project | `M P` | 移动到项目 |
| Move to Space | `M S` | 移动到空间 |
| Move to Inbox | `M I` | 移动到 Inbox |
| Move to No Project | `M N` | 移动到独立事项 / 无项目 |

| 命令 | 快捷键 | 说明 |

| Open Date Menu | `D` | 批量设置日期 |
| Move to Project | `M P` | 批量移动到项目 |
| Move to Space | `M S` | 批量移动到空间 |
| Move to Inbox | `M I` | 批量移动到 Inbox |

## 12. Dropdown 菜单数字选择规则

StoneFlow 所有支持快捷选择的 Dropdown，都应采用统一数字规则。

### 12.1 起始位规则

不是所有菜单都一律从 `1` 开始。

规则如下：

| 菜单类型 | 数字规则 | 示例 |
|---|---|---|
| 没有空态 / 无值态 | 从 `1` 开始 | status |
| 有空态 / 无值态 | 从 `0` 开始 | priority、project、date |

判断标准：

> 当前菜单里是否存在显式的「无 / 未设置 / 无归属 / 清空」选项。

### 12.2 Status Menu

状态菜单没有空态，因此从 `1` 开始。

示例：

| 数字 | 状态 |
|---|---|
| `1` | 待执行 |
| `2` | 进行中 |
| `3` | 等待中 |
| `4` | 已完成 |
| `5` | 已取消 |

### 12.3 Priority Menu

优先级菜单有「无优先级」，因此从 `0` 开始。

示例：

| 数字 | 优先级 |
|---|---|
| `0` | 无优先级 |
| `1` | 低 |
| `2` | 中 |
| `3` | 高 |
| `4` | 紧急 |

### 12.4 Date Menu

日期菜单有「无时间」，因此从 `0` 开始。

示例：

| 数字 | 日期选项 |
|---|---|
| `0` | 无时间 / 清除日期 |
| `1` | 今天 |
| `2` | 明天 |
| `3` | 本周 |
| `4` | 自定义 |

说明：

- 暂时不需要 `D T / D M / D W` 这类日期 chord；
- 只需要在日期下拉打开后支持数字快捷选择；
- 日期菜单内部可以继续支持方向键、Enter、Esc。

### 12.5 Project Menu

项目菜单有「无项目 / 独立事项」，因此从 `0` 开始。

示例：

| 数字 | 项目选项 |
|---|---|
| `0` | 无项目 / 独立事项 |
| `1~N` | 当前菜单显示顺序中的项目 |

### 12.6 数字含义说明

数字代表当前菜单显示顺序，不代表数据库枚举值。

如果菜单顺序变化，右侧数字提示和数字选择逻辑也跟着变化。

## 21. 快捷键冲突与优先级规则

### 21.1 页面上下文优先

同一个快捷键可以在不同对象上下文中执行同类操作。

例如：

| 场景 | `R` 的含义 |
|---|---|
| 选中任务 | Rename Task |
| 选中项目 | Rename Project |
| 输入框中 | 输入字母 r |

### 21.2 输入框优先

只要当前焦点处于输入框、文本域、富文本编辑器中，普通字母键必须优先作为文本输入。

快捷键系统不能抢占用户输入。

### 21.3 Modal / Drawer / Dropdown 优先

如果当前存在弹窗、菜单或抽屉：

- 快捷键优先作用于当前弹层；
- 当前弹层无法处理时，才向外层传递；
- 危险操作不应该穿透弹层执行。

层级优先级：

```txt
Dropdown / Select Menu / Context Menu
> Modal
> Command Menu
> Detail Drawer
> Preview Drawer
> Main Page
```

### 21.4 Esc 层级规则

`Esc` 的处理顺序：

```txt
候选菜单 / 下拉菜单
> Modal 弹窗
> Command Menu
> Detail Drawer
> Preview Drawer
> 当前选择
> 当前页面返回
```

### 21.5 Delete 操作规则

删除是危险操作，需要符合以下规则：

| 平台 | 默认删除快捷键 |
|---|---|
| macOS | `Cmd + Backspace` |
| Windows / Linux | `Delete` |

行为规则：

- 选中任务时删除任务；
- 选中项目时删除项目；
- 多选时批量删除；
- 输入框中不触发删除命令，只删除文本；
- 删除项目等高风险操作可以要求二次确认；
- 普通任务删除可进入回收站，不必每次确认。

## 26. 当前明确不做

为了避免范围膨胀，V1 明确不做：

1. 用户自定义快捷键；
2. 快捷键设置页；
3. 快捷键冲突可视化管理器；
4. 三段及以上复杂 chord；
5. Vim-like 默认导航；
6. 把所有命令都绑定快捷键；
7. 日期类 `D T / D M / D W` 快捷 chord；
8. 用 `V` 做完整创建；
9. 用 `.` 做操作菜单；
10. 给所有菜单都强行接入 `1~9`，只给声明支持的 Dropdown 接入；
11. 系统级增加大量全局键。

## 27. 后续扩展

### 27.1 用户自定义快捷键

后期支持用户自定义快捷键。

需要保留：

- 默认快捷键；
- 用户自定义快捷键；
- 是否启用；
- 是否与其他命令冲突；
- 是否恢复默认。

### 27.2 最近使用命令权重

Command Menu 后期可以根据用户行为调整排序。

例如：

- 用户经常使用 Move to Project，则该命令排序提高；
- 用户经常打开某个项目，则该项目在 `O P` 中排序提高；
- 用户经常使用某个筛选器，则该筛选器在 Command Menu 中更靠前。

### 27.3 AI / Smart Actions

后期可加入智能命令。

例如：

- 整理收件箱；
- 拆分任务；
- 总结项目；
- 推荐下一步；
- 自动生成任务计划；
- 优化任务标题；
- 根据任务生成子步骤。

这些命令初期只进入 Command Menu，不绑定默认快捷键。

### 27.4 更多页面专属命令

后期如果出现 Calendar、Timeline、Review、Statistics 等页面，可以为页面增加专属命令。

但页面专属命令必须遵守以下规则：

- 不破坏全局快捷键语义；
- 不抢占任务高频单键；
- 优先在当前页面上下文中展示；
- 低频能力只进入 Command Menu。

## 28. 最终约定

StoneFlow V1 的快捷键体系采用以下核心约定：

```txt
系统级：Option + Space = Quick Create

Cmd/Ctrl + K = Command Menu
/ = Search

C = Quick Create Task
N T = Full Create Task
N I = New Task in Inbox
N P = New Project
N V = New View

G = Go to fixed page
O = Open/search object
M = Move
F = Filter

W = Complete
X = Select
Shift + ↑/↓ = Range Select
Space = Preview
Enter = Open/Edit
P = Priority Menu
S = Status Menu
D = Date Menu
R = Rename
A = Archive

macOS: Cmd + Backspace = Delete
Windows / Linux: Delete = Delete

Dropdown:
有空态从 0 开始
无空态从 1 开始
```

V1 的目标不是让所有命令都有快捷键，而是让所有能力都进入 Command，让最高频的操作拥有稳定、可记忆、可持续扩展的快捷键。

StoneFlow 的命令系统应该让用户逐渐形成这样的使用习惯：

```txt
想创建任务：C
想完整创建：N T
想丢到 Inbox：N I
想跳转页面：G
想打开对象：O
想移动任务：M
想筛选列表：F
想完成任务：W
想选择任务：X
想改属性：P / S / D
想找不到功能：Cmd/Ctrl + K
```

这套规则是 StoneFlow 键盘驱动体验的基础。
