## 1. 问题陈述

### 1.1 双轨状态

当前并行存在：

| 载体 | 形状 | 消费者 |
|------|------|--------|
| 前端 `phase` | `idle \| checking \| available \| downloading \| ready \| error` | Footer / Chip / 事件分流 |
| 前端 `status: UpdateStatus` | domain 镜像联合体（含 `updateAvailable` / `downloaded` / …） | 主要为 `UpdateDialog`、`setStatus` |
| 前端 `progress` / `errorMessage` | 与 `status.downloading` / `status.error` **重复** | Footer / Dialog |
| IPC Channel `UpdateEvent::StatusChanged { status }` | 同上 `UpdateStatus` | 手动下载进度 |
| 全局事件 `update-phase` | 已单轨 | 自动检查 / 静默下载 |
| 后端 `UpdateSessionPhase` | `Idle \| Downloading \| Ready` | hydrate |

结果：

- 改一处状态要改两套字段  
- 注释仍写「status 兼容 Dialog」  
- `applyUpdatePhase` 与 `setStatus` 两套入口  

### 1.2 迁移残留

| 代码 | 作用 |
|------|------|
| `migrate_check_mode_from_stored("autoInstall")` | 历史四档 → 三档 |
| store load 时 `check_mode_migrated` 回写 | 清持久化脏值 |
| 测试与 HOWTO 说明 | 文档税 |

个人工具下：**没有需要保护的线上用户**，不必保留「再跑一年迁移」。

## 2. 目标架构

### 2.1 单一状态机（前后端语义对齐）

```text
                    ┌─────────────┐
                    │    idle     │
                    └──────┬──────┘
           check(manual)   │   hydrate none
                           ▼
                    ┌─────────────┐
         ┌─────────│  checking   │─────────┐
         │         └──────┬──────┘         │
         │ none           │ some           │ error
         ▼                ▼                ▼
   ┌──────────┐    ┌────────────┐    ┌─────────┐
   │ upToDate │    │ available  │    │  error  │
   └──────────┘    └─────┬──────┘    └─────────┘
                         │ download
                         ▼
                  ┌─────────────┐
                  │ downloading │◄── cancel ──► available 或 idle
                  └──────┬──────┘
                         │ complete
                         ▼
                  ┌─────────────┐
                  │    ready    │── restart ──► 进程结束
                  └─────────────┘
```

**说明：**

- `upToDate`：可选独立 phase（推荐），避免「已是最新」挤在 `idle` 里说不清  
- `available`：仅提醒/手动发现更新  
- `downloading` / `ready`：与后端 session 一致；cancel → 回 `available`（若有 `updateInfo`）或 `idle`  
- 自动下载路径：**不进** `available` UI，直接 `downloading`  

### 2.2 前端 Store（定稿）

```ts
export type UpdateUiPhase =
  | 'idle'
  | 'checking'
  | 'upToDate'
  | 'available'
  | 'downloading'
  | 'ready'
  | 'error'

export interface UpdateInfo {
  version: string
  body: string | null
  pubDate: string | null
}

export interface UpdateProgress {
  downloaded: number
  total: number | null
}

interface UpdateState {
  phase: UpdateUiPhase
  updateInfo: UpdateInfo | null
  progress: UpdateProgress | null
  errorMessage: string | null
  checkMode: UpdateCheckMode | null
  dialogVisible: boolean
  dismissedVersion: string | null
  readyChipDismissedVersion: string | null
  readyToastVersion: string | null
  downloadUiAbandoned: boolean

  // 显式 action（禁止 setStatus(UpdateStatus)）
  setCheckMode: (mode: UpdateCheckMode | null) => void
  setChecking: () => void
  setUpToDate: () => void
  showAvailable: (info: UpdateInfo, options?: { openDialog?: boolean }) => void
  setDownloading: (progress: UpdateProgress, version?: string) => void
  setReady: (version: string) => void
  setError: (message: string) => void
  cancelDownloadUi: () => void  // 本地 abandon；再 invoke cancel
  closeDialog: () => void
  skipAndClose: () => void
  dismissReadyChip: () => void
  openDialog: () => void
  hydrateFromSession: (snap: SessionSnap) => void
  reset: () => void
}
```

**删除字段：** `status: UpdateStatus`、`setStatus`、`showUpdate`（改名为 `showAvailable` 或保留别名一期后删）、`markReady`/`abandonDownloadUi` 可内聚到上面命名。

**命名迁移表：**

| 旧 | 新 |
|----|-----|
| `showUpdate(info)` | `showAvailable(info, { openDialog })` |
| `setStatus({ status: 'checking' })` | `setChecking()` |
| `setStatus({ status: 'downloading', ... })` | `setDownloading({ downloaded, total })` |
| `setStatus({ status: 'downloaded', version })` | `setReady(version)` |
| `setStatus({ status: 'error', message })` | `setError(message)` |
| `setStatus({ status: 'upToDate' })` | `setUpToDate()` |
| `markReady` | `setReady` |
| `abandonDownloadUi` | `cancelDownloadUi`（仅本地；IPC 另调） |

### 2.3 全局事件（已基本正确）

保持 **仅** `update-phase`：

```ts
type UpdatePhasePayload = {
  phase: 'available' | 'downloading' | 'ready' | 'error'
  version?: string | null
  body?: string | null
  pubDate?: string | null
  downloaded?: number | null
  total?: number | null
  message?: string | null
}
```

`applyUpdatePhaseEvent` 只调用新 action，**禁止**再调 `setStatus`。

可选增强（本方案纳入）：payload 增加 `checking` / `upToDate` **仅当**手动检查也想走统一事件；当前手动检查在前端本地 set phase，**可不发全局事件**。

### 2.4 IPC Channel（与全局事件同构）

**删除** `UpdateEvent::StatusChanged { status: UpdateStatus }`。

改为：

```rust
// runtime commands/update.rs
#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct UpdatePhasePayload { /* 与前端同字段 */ }

#[derive(Clone, Serialize)]
#[serde(tag = "event", content = "data", rename_all = "camelCase")]
pub enum UpdateChannelEvent {
    Phase(UpdatePhasePayload),
}
```

或更简单：Channel **直接** `Channel<UpdatePhasePayload>`，不包一层 tag。

**推荐：直接 `Channel<UpdatePhasePayload>`**，与 `listen('update-phase')` 同构，前端一个 `applyUpdatePhaseEvent` 吃到底。

`download_and_install` 命令：

```text
on_event.send({ phase: "downloading", version, downloaded: 0, total: null })
… progress …
Completed → { phase: "ready", version }
Cancelled → { phase: "available", version } 或 { phase: "idle" }（有 updateInfo 则 available）
Err → { phase: "error", message }
```

### 2.5 domain `UpdateStatus` 处置

| 选项 | 做法 | 本方案 |
|------|------|--------|
| 删除 | domain 去掉 `UpdateStatus` 枚举 | **是**（若全仓无引用） |
| 保留内部 | 仅 adapter 日志用 | 否，YAGNI |

实现时：`rg UpdateStatus` 清零。

### 2.6 后端会话（保持并略扩展）

现有 `UpdateSessionPhase = Idle | Downloading | Ready` 足够 hydrate。

可选：cancel 后 snapshot `phase: Idle` + `version: pending` 以便 UI 回到 available——前端 hydrate 时若 `version` 有且 phase idle 且非 ready，可设 `available`。**定稿规则：**

```text
hydrate:
  downloading → setDownloading + updateInfo.version
  ready → setReady
  idle + version 有值 + 非 dismissed → 不自动 available（避免弹窗骚扰）
  idle → idle
```

与现行为一致即可。

### 3.3 parse 逻辑定稿

```rust
pub fn parse_check_mode(raw: &str) -> UpdateCheckMode {
    match raw {
        "manual" => Manual,
        "notifyOnly" => NotifyOnly,
        "autoDownload" => AutoDownload,
        _ => NotifyOnly, // 含 autoInstall、空、垃圾
    }
}
```

不再返回 `(mode, migrated)` 布尔——若解析结果与存盘字符串不同可仍回写规范化（合法三档 + 间隔），那是 **规范化**，不是历史迁移。

## 5. Dialog 状态表（单轨后）

| phase | 标题 | 主按钮 | 次按钮 | 关闭 |
|-------|------|--------|--------|------|
| checking | 检查中… | disabled | — | 可 |
| available | 发现新版本 x | 立即更新 | 跳过 | 可 |
| downloading | 正在下载 | 下载中 disabled | 取消 / 后台继续 | 可（后台） |
| ready | 更新已准备就绪 | 立即重启 | 稍后重启 | 可 |
| error | 更新失败 | 立即更新（重试） | 跳过 | 可 |
| upToDate | （通常不弹窗，toast） | — | — | — |
| idle | 不展示 | — | — | — |

`dialogVisible` 独立：`available` 默认 true（非 auto）；`downloading` 可关不改 phase。

## 8. 风险（个人工具场景下可接受）

| 风险 | 处理 |
|------|------|
| 本地旧 store 字符串 autoInstall | 变 notifyOnly；你改一次设置即可 |
| Channel 与 phase 字段 camelCase | 与现有 `update-phase` 共用同一 serde 形状，抽公共类型（Rust 可放 runtime 或 domain 轻量 DTO） |
| Dialog 漏状态 | 按 §5 表做检查表勾选 |
| 改动集中易 regress | 先绿自动化再手测 §7.2 |

**不做的兜底：** 功能 flag、双写两周、兼容层 adapter「旧 status → 新 phase」长期存在。
