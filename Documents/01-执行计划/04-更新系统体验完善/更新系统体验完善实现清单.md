# 更新系统体验完善 · 实现清单

> **For agentic workers:** 按任务顺序实现；每项用 checkbox 跟踪。推荐 subagent-driven 逐任务交付，或本会话 inline 分批实现。
> **设计依据：** `Docs/01-执行计划/04-更新系统体验完善/更新系统体验完善设计方案.md`
> **前置能力：** `Docs/01-执行计划/03-应用内更新系统/应用内更新系统技术方案.md`
> **日期：** 2026-07-09

**Goal：** 三档更新模式 + 自动下载静默体验 + Footer 进度环 + 就绪 Chip + 下载单飞；长期可演进系统状态轨。

**Architecture：** Rust domain/usecase 收敛模式与会话锁；bootstrap 按模式分流事件；前端 store 以 `phase` 为真相源，Dialog 仅服务「是否下载」决策，Footer/Chip 服务后台进度与重启。

**Tech Stack：** Tauri v2 updater · Rust domain/usecase/runtime · React · Zustand · shell footer patterns

## Global Constraints

- 更新模式仅三档：`manual` | `notifyOnly` | `autoDownload`（删除 `autoInstall`）
- 自动下载：**发现更新不弹模态框**；下载完成后非模态提醒重启
- **永不自动重启**；仅用户确认后 `restart_and_install`
- 进度环嵌在 **Footer**，不占 Header
- 就绪主 CTA 用 **Ready Chip**；Dialog 保留给仅提醒/手动
- 同一时刻最多一个 download（会话锁）
- 检查间隔本阶段仍硬编码 6h；启动延迟 3s
- 与设计方案冲突时以设计方案为准；与 03 文档冲突时以 04 为准
