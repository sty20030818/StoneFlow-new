# StoneFlow 头像菜单与应用入口 设计方案

> 版本：v1
> 状态：设计定稿（待实现）
> 日期：2026-07-13
> 作用：将 Header 独立「设置」齿轮收敛为 **头像下拉应用菜单**；能用的接现有命令，其余占位；为用户资料等预留口子
> 前置文档：
> - `Docs/01-执行计划/05-设置侧栏与Settings-Mode/设置侧栏与Settings-Mode设计方案.md`
> - `Docs/U1-设计系统.md` · `Docs/P1-产品内核.md`
> 适用范围：StoneFlow Desktop（Tauri v2）前端 `ShellHeader` + command 入口

---

## 0. 结论摘要

| 决策 | 内容 |
|------|------|
| 入口形态 | **头像可点 → Dropdown**；**移除** Header 独立设置齿轮 |
| 菜单定位 | **本机应用菜单**（偏好 / 帮助 / 诊断），不是团队账号 Profile |
| V1 可接线 | **设置**（`openSettings`）、**键盘快捷键**（`openShortcutHelp`） |
| 占位项 | 用户资料 · 检查更新 · 关于 · 诊断与支持（及子项）—— UI 可见，动作暂 no-op 或 toast「即将推出」 |
| 快路径 | **`Cmd+,` / `G S` / Command「打开设置」** 不变，不依赖打开下拉 |
| 不做 | 分区直达、假登出、业务导航塞进菜单、Footer 再塞入口 |
| 落地 | 单 PR 可完成壳 + 两项接线 + 占位；诊断/关于后续另开 |

本方案是 **UI 入口收敛**，不改变 Settings Mode 内部结构。

## 1. 背景与问题

### 1.1 现状

- Header 右侧：`新建任务` 集群 + **独立齿轮** + **静态头像**（不可点）
- 设置已升级为 Settings Mode（侧栏变目录 + 四分区 + lastSection）
- 已有命令：`openSettings`、`openShortcutHelp`（及快捷键 `Cmd+,`、`Cmd+/` 等，以 keybinding 表为准）
- Footer：`h-7` 系统状态轨（同步 / 更新 / 版本）—— 与应用菜单职责分离

### 1.2 问题

| 问题 | 说明 |
|------|------|
| 齿轮与头像并列 | 两块弱入口抢位；个人工具更常见「头像菜单」收敛低频入口 |
| 头像无语义 | 装饰占位，无法承载「本机 / 偏好 / 帮助」 |
| 后续 QA / 关于无家 | 若继续堆 Header 图标会乱 |

### 1.3 目标

1. Header 右侧更干净：创造（新建）与配置（头像菜单）分工清晰
2. 设置、快捷键从菜单可达，且与现有命令/快捷键同源
3. 结构一次定清：占位项可挂，不空壳误导成「已实现」
4. 不削弱键盘路径

### 1.4 非目标

- 真实账号 / 登录 / 多用户
- 设置分区直达菜单项
- 在菜单里做同步主操作（立即同步仍归 Footer）
- 完整「关于」页、日志查看器实现（本阶段可占位）

## 2. 产品定位

### 2.1 菜单角色

```text
新建任务 ▾     → 创造（任务 / 项目）
头像 ▾         → 配置与帮助（应用级、低频）
Command / 快捷键 → 快路径（不经过菜单）
```

一句话：

> 头像下拉是 **StoneFlow 本机应用菜单**，不是协作产品的成员菜单。

### 2.2 与相关表面的边界

| 表面 | 放什么 | 不放什么 |
|------|--------|----------|
| 头像菜单 | 设置、帮助、关于、诊断入口 | 收件箱/项目等业务导航 |
| Settings Mode | 具体偏好表单 | 临时诊断 toast |
| Footer | 同步灯、更新事务、版本号 | 设置入口 |
| Command | 可检索的全部动作 | — |

## 3. 信息架构与层级

### 3.1 目标结构（定稿）

```text
┌ 头像 ──────────────── ▾ ─┐
│ [可选] 本机 · StoneFlow   │  ← Header 区，非按钮，弱文案
│                           │
│ ── 偏好 ──                │  ← 可选 group label；V1 可无 label 仅靠分隔
│ 设置                 ⌘,   │  ✅ 接线 openSettings
│ 用户资料…                 │  ⬜ 占位（预留口子）
│                           │
│ ── 帮助 ──                │
│ 键盘快捷键           ⌘/   │  ✅ 接线 openShortcutHelp
│                           │
│ ── 应用 ──                │
│ 检查更新…                 │  ⬜ 占位
│ 关于 StoneFlow            │  ⬜ 占位
│                           │
│ ── 诊断 ──                │
│ 诊断与支持            ▸   │  ⬜ 子菜单占位
│   · 复制诊断信息          │  ⬜
│   · 打开日志              │  ⬜
│   · 同步诊断…             │  ⬜（未来可 deep link 设置·云同步，本阶段不接）
└───────────────────────────┘
```

### 3.2 分组原则

1. **偏好**：改应用怎么工作（设置、未来用户资料）
2. **帮助**：怎么学（快捷键）
3. **应用**：关于本软件（更新、关于）
4. **诊断**：排障 / QA，默认折叠在子菜单，避免日常噪音

### 3.3 实现状态矩阵

| ID | 菜单项 | 类型 | V1 行为 | 快捷键 hint |
|----|--------|------|---------|-------------|
| `settings` | 设置 | **enabled** | `onRunCommand(openSettings)` | `⌘,`（Win：`Ctrl+,`，展示层跟 shortcut-display） |
| `profile` | 用户资料… | **placeholder** | 关闭菜单 + 轻提示「即将推出」或 disabled + tooltip | — |
| `shortcuts` | 键盘快捷键 | **enabled** | `onRunCommand(openShortcutHelp)` | `⌘/` |
| `checkUpdate` | 检查更新… | **placeholder** | 同上 | — |
| `about` | 关于 StoneFlow | **placeholder** | 同上 | — |
| `diagnostics` | 诊断与支持 | **placeholder submenu** | 子项均可 placeholder | — |
| `copyDiagnostics` | 复制诊断信息 | **placeholder** | — | — |
| `openLogs` | 打开日志 | **placeholder** | — | — |
| `syncDiagnostics` | 同步诊断… | **placeholder** | — | — |

> 文案带「…」表示将打开对话框/子流程（即便暂占位），与 macOS 菜单惯例一致。

### 3.4 最小可交付（MVP）vs 一次铺齐

| 方案 | 内容 | 说明 |
|------|------|------|
| **A. 仅两项 + 无占位** | 设置、快捷键 | 最干净，但用户资料口子看不到 |
| **B. 接线两项 + 全占位（采纳）** | 上表全部 UI 出现 | 满足「占位口子」；实现仍薄 |
| **C. 仅设置一项** | 过空 | 不采纳 |

**采纳 B：** 菜单结构一次到位；enabled 只接两个已有命令；其余 `disabled` 或 select 时 toast。

**占位交互二选一（实现时定一种并写死）：**

- **推荐：** `disabled` + `title`/tooltip「即将推出」—— 不会误点
- 备选：可点但 `sonner` 提示「即将推出」—— 可发现性略好

本方案 **推荐 disabled + 即将推出**。

## 4. 交互规格

### 4.1 触发与关闭

| 项 | 规格 |
|----|------|
| 触发 | 点击头像（整块可点，hit ≥ 40×40） |
| 形态 | `DropdownMenu`；`align="end"` |
| 关闭 | 点外侧 / Esc / 选中 enabled 项后 |
| 拖拽 | 头像按钮 **不要** `data-tauri-drag-region`，避免吞点击 |
| 与齿轮 | **删除**独立设置齿轮按钮 |

### 4.2 与 Settings Mode

- 点「设置」→ 与现齿轮相同：`openSettings` → lastSection
- 已在设置页再点「设置」→ 仍 navigate 到设置（可 no-op 同路径，或保持不变）
- **不**在菜单内嵌设置表单

### 4.3 与快捷键帮助

- 点「键盘快捷键」→ `openShortcutHelp` / 现有 ShortcutHelp 层
- 全局快捷键保持可触发，**不依赖**菜单打开

### 4.4 键盘

| 路径 | 行为 |
|------|------|
| `Cmd+,` | 直达设置（不经菜单） |
| `Cmd+/`（以 keybinding 为准） | 直达快捷键帮助 |
| `G` `S` | 打开设置（已与 openSettings 统一） |
| 菜单内 | Dropdown 默认 roving tabindex / 方向键 |

### 4.5 视觉

| 项 | 规格 |
|----|------|
| 头像 | 保持现 `size-7.5` + badge（若有） |
| 打开态 | `aria-expanded`；可选轻微 active 底 |
| 菜单宽 | `min-w-52`～`min-w-56` |
| 项 | 左图标（可选）+ 文案；右 shortcut hint（enabled 项） |
| 占位项 | 降低对比 / `opacity` 或 `disabled` 样式 |
| 分隔 | `DropdownMenuSeparator` 分三～四组 |
| Group label | 可选；若用则 muted 小字，**左对齐** |

### 4.6 可选菜单头（V1 可砍）

```text
StoneFlow
本机工作区
```

非按钮。版本号已在 Footer 时，**V1 可不做菜单头**，减噪。

## 6. 架构与实现要点

### 6.1 组件建议

```text
ShellHeader
  └── UserAppMenu（新）
        ├── DropdownMenuTrigger → Avatar
        └── DropdownMenuContent
              ├── 偏好组：设置(✅) · 用户资料(⬜)
              ├── 帮助组：键盘快捷键(✅)
              ├── 应用组：检查更新(⬜) · 关于(⬜)
              └── 诊断组：子菜单(⬜)
```

- **不要**在 `ShellHeader` 内堆大段菜单 JSX；抽 `UserAppMenu.tsx`（或 `header/UserAppMenu.tsx`）
- 动作统一走 `onRunCommand(CommandId)`，与齿轮同源，避免第二套 navigate

### 6.2 Props（示意）

```ts
type UserAppMenuProps = {
  isSettingsActive?: boolean
  onRunCommand: (id: CommandId) => void
}
```

### 6.3 关键文件

| 路径 | 动作 |
|------|------|
| `src/app/layouts/shell/ShellHeader.tsx` | 删齿轮；挂 UserAppMenu |
| `src/app/layouts/shell/header/UserAppMenu.tsx` | **新建** |
| `src/shared/ui/patterns/shell-chrome.ts` | 若需菜单/头像 cluster 样式微调 |
| `src/features/command/...` | 一般无需改（复用命令） |
| 测试 | Header 或 UserAppMenu 轻测：点头像出菜单；设置/快捷键触发 command |

### 6.4 与 05 文档的关系

| 05 原表述 | 本方案 |
|-----------|--------|
| 入口 = Header 齿轮 | **改为** 头像菜单「设置」项 |
| Cmd+, 打开设置 | **保持** |
| App 侧栏无设置项 | **保持** |

实现本方案后，05 文档「入口」一句应视为被本方案覆盖（可在 05 结论表加注「入口迁至 06 头像菜单」）。

## 7. 分阶段落地

### P0 — 本阶段（本方案范围）

1. `UserAppMenu` 壳 + 分组 + 占位
2. 接线：设置、键盘快捷键
3. 移除独立齿轮
4. 占位项 disabled +「即将推出」
5. 基础 a11y：`aria-label="应用菜单"`、`aria-expanded`

**验收：**

- [ ] 无独立齿轮
- [ ] 点头像出菜单
- [ ] 设置 → Settings Mode，lastSection 行为不变
- [ ] 键盘快捷键 → 帮助层
- [ ] `Cmd+,` / Command 仍可进设置
- [ ] 占位项不可用或明确「即将推出」
- [ ] Footer 高度与职责不变

### P1 — 后续（不在本方案实现）

| 项 | 条件 |
|----|------|
| 检查更新 | 接 `checkUpdate` / 现有 update store 动作 |
| 关于 | 版本、渠道、开源许可链接 |
| 复制诊断 | 聚合 app 版本 + sync 摘要 + 环境 |
| 用户资料 | 有可编辑字段或展示名后再做 |
| 同步诊断菜单项 | 可选 `openSettings(scope, 'sync')` |

### P2 — 可选打磨

- 菜单头版本号
- 当前在设置时「设置」项 checkmark
- 诊断仅 dev / 设置开关显示

## 8. 风险

| 风险 | 缓解 |
|------|------|
| 设置发现变差 | 保留快捷键与 Command；菜单项「设置」置顶 |
| 占位过多像半成品 | disabled +「即将推出」；诊断收子菜单 |
| 拖拽窗体吞点击 | 触发器禁用 drag-region |
| 与新建 ▾ 两个菜单 | 视觉权重：新建 outline，头像弱入口 |

## 10. 总结

把设置从「旁挂齿轮」收成 **头像应用菜单** 的第一项，并排好用户资料、更新、关于、诊断等 **占位层级**；V1 只把 **设置** 与 **键盘快捷键** 接到现有命令，键盘快路径不降级。

**本阶段完成定义：** 无齿轮、有下拉、两项真能用、其余明确占位、Settings Mode 行为不回归。
