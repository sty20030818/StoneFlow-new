# 导航与路由当前架构

> 日期：2026-07-14
> 状态：阶段 7 文档收口。本文档记录当前实现事实和后续维护边界。

## 1. 当前结论

导航体系已经完成模块化收口：

- `src/routes/`：TanStack Router file routes，只负责 URL 匹配、loader、redirect、页面入口和 route-level layout。
- `src/app/router.tsx`：应用级 TanStack Router 实例，负责 `createHashHistory`、route tree 和 router context。
- `src/app/navigation/`：StoneFlow 导航语义模块，负责路径解析、路径生成、启动恢复、scope 记忆、最近浏览和 Shell header 的前进后退状态。
- `src/app/layouts/`：Shell 视觉布局和用户交互，不再持有路由记忆规则。
- `src/features/*`：业务页面和业务数据，不直接管理浏览器 history。

长期建议继续保持这个形态：`routes` 管“URL 入口”，`navigation` 管“应用导航语义”，业务模块只发起明确的导航意图。

## 2. 真相源边界

| 能力 | 真相源 | 说明 |
|---|---|---|
| 当前 URL | TanStack Router | 不用 Zustand、Query 或自定义 store 复制当前路由 |
| 浏览器前进后退 | TanStack Router history | `sessionRouteHistory` 只读状态并调用 `router.history.go()` |
| 启动恢复 | `routeMemoryStore.ts` + Tauri Store | 只持久化本机最后可恢复路径，不接管当前 URL |
| scope 上次位置 | `routeMemory.ts` 纯规则 + `routeMemoryStore.ts` 持久化 | 用于从 all/space 切换时回到该 scope 上次页面 |
| 最近浏览 | `sessionRouteHistory.ts` 内存状态 | 当前会话 UI 能力，不持久化 |
| 业务数据缓存 | TanStack Query | 不存导航历史，不存当前路由 |
| Shell UI 状态 | Zustand 或局部 state | 只放非 URL 的 UI 状态，例如折叠、弹窗等 |

## 3. `src/app/navigation/` 文件职责

```txt
src/app/navigation/
  shellRoute.ts
  scope.ts
  routePaths.ts
  intents.ts
  routeMemory.ts
  routeMemoryStore.ts
  useRememberCurrentShellRoute.ts
  sessionRouteHistory.ts
```

- `shellRoute.ts`：把 URL 解析成 `ShellRoute` / `AppRoute`，是产品语义层，不做副作用。
- `scope.ts`：从 route 推导当前 scope，避免 layout 和业务组件重复判断 all/space。
- `routePaths.ts`：生成 canonical path，所有路径拼接优先走这里。
- `intents.ts`：把“打开任务、打开项目、切换设置页”等业务意图转换成 path。
- `routeMemory.ts`：启动恢复和 scope 记忆的纯函数规则，负责 normalize、validate、fallback。
- `routeMemoryStore.ts`：Tauri Store 边界，隐藏 store key、加载、保存和错误处理。
- `useRememberCurrentShellRoute.ts`：route file 调用的 hook，把当前 TanStack location 写入 route memory。
- `sessionRouteHistory.ts`：当前会话最近浏览、Header back/forward 可用性和跳转行为。

## 4. `src/routes/` 文件职责

`src/routes/` 是 TanStack Router 官方 file-based routing 层。这里允许做：

- route tree 结构声明；
- loader 数据预取；
- redirect；
- route-level error / notFound；
- route-level layout；
- 调用 `useRememberCurrentShellRoute()` 记录当前 scope 路径。

这里不应该做：

- 自己维护最近浏览列表；
- 自己读写 Tauri Store；
- 自己拼复杂业务路径；
- 放业务页面的大块 UI；
- 放跨 route 复用的导航规则。

## 5. 已删除的冗余层

这些目录或概念不应该再恢复：

- `src/app/routing/`
- `src/app/navigation-runtime/`
- `tanstackCompat`
- 全局 `navigationStore`
- `src/test-utils/`

删除原因不是“目录少更好”，而是它们没有稳定职责：要么只是兼容转发，要么把 runtime、规则、UI 和测试基础设施混在一起。当前长期边界更清楚：导航语义进 `src/app/navigation/`，测试基础设施进 `src/test/`。

## 6. 当前缺陷与后续约束

当前没有发现必须新增模块的缺口，但有几个长期约束要守住：

- 不要把 `src/app/navigation/` 变成万能工具箱。只有跨 route、跨 layout 的导航语义才放这里。
- 不要新增 barrel `index.ts`。直接 import 具体文件，依赖关系更明确。
- 不要把 Query 当导航状态容器。Query 只服务服务端/本地业务数据缓存。
- 不要把 Zustand 当 URL 镜像。URL 已经由 TanStack Router 管理。
- 不要让 Tauri Store 参与前进后退。持久化只服务启动恢复和 scope 记忆。
- 新增 route 时必须同时确认是否需要：
  - `shellRoute.ts` 能识别；
  - `routePaths.ts` 能生成 canonical path；
  - `routeMemory.ts` 允许记忆；
  - `sessionRouteHistory.ts` 能展示合理名称和图标。

## 7. 变更检查清单

改导航或新增 route 前后，至少检查：

```bash
rg "@/app/(routing|navigation-runtime)|tanstackCompat|@/test-utils" src
bun run typecheck
bun run lint
bun run test:run src/app/navigation
```

涉及 router helper 或 React Query hook 的测试，还要跑相关页面测试，确认测试环境同时具备 Router context 和 QueryClientProvider。
