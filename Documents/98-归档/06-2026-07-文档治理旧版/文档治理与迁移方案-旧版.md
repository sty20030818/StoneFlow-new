## 2. 核心原则

这次文档整理遵循四条原则：

1. 根目录只放长期稳定文档。
2. `01-执行计划` 和 `02-重构方案` 都只放进行中的内容。
3. 已完成、已失效、已废弃的内容直接归档，不保留在主工作区。
4. 同一主题的调研、技术方案、执行计划、实施稿尽量放在同一主题目录，不再人为拆散上下文。

## 5. 偏移文档调查方案

这里的“偏移文档”指：

- 文档描述的结构、技术选型、目录边界、产品规则，已经与当前代码事实不一致。

### 5.1 调查范围

优先调查：

- `T1-系统设计.md`
- `X1-决策日志.md`
- `D1-领域与数据模型.md`
- `P2-产品蓝图.md`
- 各类 `ARCHITECTURE.md`

### 5.2 调查步骤

每份文档按同一套方法核对：

1. 先列出文档中的关键断言。
2. 再到代码、路由、目录、命令、数据模型里核对是否真实存在。
3. 对每条断言标记：
   - `一致`
   - `部分一致`
   - `已偏移`
   - `已失效`
4. 最后形成“纠偏清单”。

### 5.3 偏移判断标准

出现以下情况之一，就算偏移：

1. 文档写的目录结构在仓库中已不存在。
2. 文档写的技术栈中心已经变化。
3. 文档写的是旧阶段目标，但被表述成当前事实。
4. 文档写的决策已经被后续实现推翻。
5. 文档写的产品规则已被真实行为替代。

## 6. 偏移文档重写方案

### 6.1 常青文档重写顺序

建议按这个顺序重写：

1. `T1-系统设计.md`
2. `X1-决策日志.md`
3. `D1-领域与数据模型.md`
4. `P2-产品蓝图.md`
5. `U1-设计系统.md`
6. `P1-产品内核.md`

原因：

- `T1` 和 `X1` 最容易误导后续技术判断。
- `D1` 和 `P2` 其次，关系到模型和页面心智。
- `U1` 和 `P1` 更偏长期稳定层，可以在后面补齐。

### 6.2 常青文档重写方式

每份文档都按以下方式重写：

1. 保留原文件名，不重命名。
2. 不做“旧内容补丁式追加”，直接按当前事实重写主干。
3. 如有仍有参考价值的旧决策，在文中明确标注“历史背景”。
4. 不再把旧阶段方案写成当前事实。

### 6.3 `ARCHITECTURE.md` 偏移重写方式

代码附近架构文档不应该写成长方案，应统一写成“当前事实 + 约束文档”。

每份 `ARCHITECTURE.md` 重写时统一包含：

1. 适用范围
2. 当前心智模型
3. 当前正式目录结构
4. 允许依赖方向
5. 禁止事项
6. 后续新增代码时的落点规则

禁止继续写：

- 大段执行计划
- 历史迁移步骤
- 已经失效的旧架构对比

如果要保留历史迁移背景，应放回 `02-重构方案/` 或 `98-归档/`。
