## 阶段 2：核心价值与产品气质

### 提问与回答

#### Q1. 你真正最想解决的是哪一个瞬间？

是 `想到事情时来不及记`，还是 `记下来了但后面乱`，还是 `任务很多但不知道先做哪个`？
**用户回答**
- 快速地记录和查看 todo 叭。

#### Q2. 如果把 `StoneFlow` 的主价值只能压成一个动作，你选哪个？

是 `极速捕获`，还是 `极速整理`，还是 `极速开始执行`？
**用户回答**
- 极速记录。
- 但是要有清晰的整理和执行的路径。

#### Q3. 你说的全局快捷创建 todo，理想体验像哪个？

是像 `Raycast` 一样弹一个命令框直接输入，还是像 `Linear` 一样带结构化字段，还是像 `Things` 一样极简先记下再整理？
**用户回答**
- 想 Raycast 那样，直接一个 command 可以查看和记录 todo。

#### Q4. 你希望用户创建任务时，默认是先无脑记下还是当场填完整？

**用户回答**
- 先记下。

#### Q5. 你心里更想把 `StoneFlow` 做成哪一种？

是 `一个极强的 Inbox`，还是 `一个完整的个人执行系统`，还是 `一个命令式任务中枢`？
**用户回答**
- 我是想一个完整的个人执行系统。
- 但是亮点是快，快速记录查看。

#### Q6. 你参考 `Linear`，你真正想借的是哪一层？

**用户回答**
- 视觉风格。
- 交互节奏。
- 键盘优先。
- 状态流转。
- 筛选系统。
- 以及专业感。

#### Q7. 你参考 `Raycast`，你真正想借的是哪一层？

**用户回答**
- 全局唤起。
- 命令输入。
- 模糊搜索。
- 以及体验。

#### Q8. 你参考 `Things`，你真正想借的是哪一层？

**用户回答**
- 借鉴它作为一个老牌 todo 的那种逻辑。
- 还有功能完整性。

#### Q9. 你说"可以做很窄的 MVP，也可以不做很窄的 MVP"，这句话其实说明你还没想清楚你要的是：

`先做一个真正尖锐的单点产品`，还是 `先把自己理想中的完整 TODO 雏形搭出来`？
**用户回答**
- 我可能会偏向先把完整搭出来。
- 因为这个产品是给我自己用的，不着急发布。

#### Q10. 假设明天只能上线一个最小版本，你更希望用户夸它哪句话？

是 `录入任务真的快`，还是 `用起来真的很专业`，还是 `终于有一个程序员想长期用的 TODO 了`？
**用户回答**
- 我希望的是，很快很好用，值得长期用，值得付费。

### 助手收敛总结

- 当前临时产品定义可以写成：
	- `StoneFlow 是一个面向高频脑力工作者、以极速捕获为入口、以清晰整理和执行为落点的 macOS 个人执行系统。`
- 当前已经明确的事情：
	- 第一性价值不是"管理复杂项目"，而是快速记录和查看
	- 入口亮点是全局唤起、command 式输入、键盘优先
	- 它不是纯收集箱，因为你明确要整理路径和执行路径
	- 它也不是单纯极简待办，因为你要的是完整的个人执行系统
	- 产品气质偏向 Raycast 的入口方式 + Linear 的专业交互 + Things 的逻辑沉淀

## 阶段 3：信息架构与任务组织

### 提问与回答

#### Q1. 你心里一个任务完成它的一生，大概会经历哪些状态？

比如：`收集`、`待处理`、`计划中`、`今天`、`进行中`、`已完成`、`搁置`。
**用户回答**
- 我觉得可能有很多的路径。
- 比如先快速收集，然后我归类，然后开始，然后结束，然后归档。
- 也有可能是直接在项目里创建，然后等待别的任务完成后，开始，然后结束。
- 又或者它是一个长期任务，需要我每天去做，每天完成，就当是目标叭。

#### Q2. 你更希望任务按什么来组织？

是按 `时间`，比如今天、稍后、计划；还是按 `项目`，比如工作项目、个人事务、学习目标；还是按 `状态`，比如待办、进行中、完成；还是三者都要，但必须有一个主轴。你觉得主轴应该是什么？
**用户回答**
- 我可能会想要主线是按照项目来归类。
- 希望一个 `space -> project -> task` 的结构。
- 但是也会有按照时间的分类。
- 然后在每个 project 里面是按照状态来排 task 的。

#### Q3. 你每天真正会高频查看的首页，应该是什么？

是 `今天`，还是 `Inbox`，还是 `一个聚合首页`，同时看到今天、即将到来、收集箱、进行中。
**用户回答**
- 我觉得最高频的应该是 Inbox。
- 我把它当做一个过渡状态。
- 所有在 Inbox 的 task 最好是被引导到各个 project。
- 然后今日或者最重要 task，我也希望可以一键查看。

#### Q4. 你记下一个任务之后，希望它默认流向哪里？

是全部先去 `Inbox`，还是根据输入内容自动归类，还是直接进入 `Today / Upcoming` 之类的视图？
**用户回答**
- 我会希望进入 Inbox。
- 但是也可以直接进入 project。
- 之后可以出自动归类。
- 然后 today 之类的只是视图罢了。

#### Q5. 你觉得"清晰整理路径"具体指什么？

是每天固定花几分钟清空 Inbox，还是随手记完后立刻补字段，还是靠搜索和命令二次整理？
**用户回答**
- 每天花一些时间清理 Inbox。
- 其他的方式也可以，但不是首选。
- 所以说 Inbox 是个很重要的。

#### Q6. 你理想中的任务，第一版最少必须有哪些字段？

你可以从这些里选：`标题`、`备注`、`截止时间`、`提醒`、`优先级`、`标签`、`项目`、`状态`、`预计时长`、`重复`、`日期`。
**用户回答**
- 必须的：标题、备注、优先级、状态、标签。
- 其他的次选应该都需要。

#### Q7. 你是否接受第一版里，一个任务只有 `标题 + 状态 + 时间相关字段 + 项目/标签中的一种` 先极简起步？

**用户回答**
- 一开始就是上面那些必须叭。

#### Q8. 你说"专业"，那你更需要哪种专业能力先出现？

是 `强筛选和检索`、`强状态流转`、`清晰项目结构`、`批量操作`、`日程/提醒能力` 中的哪一个？
**用户回答**
- 专业体现在架构清晰、操作流程清晰。
- 但是强筛选检索、强状态流转、批量操作、日程这些都少不了。
- 一起组成了我说的专业，就是能干所有 todo 的事。

#### Q9. 你会不会需要"任务不是平的"这件事？

也就是：要不要 `子任务`、要不要 `项目`、要不要 `任务依赖`？
**用户回答**
- 要项目。
- 没有子任务。
- 但是依赖可能有，比如这个 task 挂着哪个文档、哪个文件、哪个代码库。

#### Q10. 你更想让 StoneFlow 帮你解决"记住所有事"，还是"每天做对的事"？

**用户回答**
- 我更想的是，管理好所有事。

#### Q11. 你说像 Raycast 一样 Command 式，那这个命令框你希望主要承担什么？

是只负责 `快速新增/搜索`，还是它本身就是整个产品的主入口，连整理、切换视图、修改状态都能做？
**用户回答**

## 全局阶段性结论

### 已明确

- StoneFlow 是一个以"快"和"专业"为方向的 macOS 个人执行系统
- 核心入口是全局唤起 + command 输入 + 搜索即创建
- 主结构强制为 `Space -> Project -> Task`
- Inbox 是捕获层
- Project 是归宿层
- 时间页是视图层，不是存储层
- 时间页可以是自动筛选，也可能进一步演变成自定义规则聚合页
- 任务默认先轻量创建，再补充整理
- 离开 Inbox 的任务必须归入某个 Project
- 依赖当前更接近"任务外挂资源"
- 完成反馈是核心体验之一，而且必须有明显存在感
- `Focus` 有机会成为新的核心聚合页命名
- 主导航初步倾向为：Space Tabs + Space 内 Sidebar + 右侧任务区
- 第一版外挂资源优先支持：文档链接、本地文件、本地文件夹
- `Focus` 倾向于"系统预置多个 + 用户自定义多个"的规则视图体系
- `Inbox` 更像 Space 下的特殊系统模块，而不是普通 Project
- 子项目是第一版真实需求
- Project 页交互倾向为任务列表/分组视图 + Drawer 详情
- `Focus` 第一版预置页倾向为：`Focus / Upcoming / 高优先级 / 最近添加`
- 子项目第一版只支持一层
- `Project` 默认视图先做按状态分组的列表
- `Inbox` 是强过渡态模块：不能有子项目、不能长期存、需要清理引导
- `Focus` 第一版默认更适合作为"手动 pin 任务页"
- `Upcoming` 第一版主展示方式先按截止日期组织
- `最近添加` 的职责是按创建时间回看最近捕获的任务
- `Inbox` 中的任务只有补齐必选信息后才能离开
- `Inbox` 离开条件至少包括：优先级、所属 Project、状态(Todo)
- `Inbox` 是模块，不是状态；其中任务默认状态就是 `Todo`
- `高优先级` 页面可以考虑并入 `Focus` 页内部 tab
- 同一个任务允许出现在多个视图中
- Drawer 第二层顺序倾向为：项目归属 -> 资源 -> 快捷操作 -> 历史记录
- `Project` 页顶部需要一个可折叠摘要区
- Sidebar 第一版结构倾向为：`Space Tabs -> Inbox -> Focus -> Trash -> Projects List`
- `Focus` 是聚合视图容器，而不是单个页面
- `Upcoming / 最近添加 / 高优先级` 等更适合作为 `Focus` 内部 tabs
- `Task` 第一版状态先极简为：`todo / done`
- `Project` 列表第一版默认先按名称排序
- `Focus` 内部第一版 tabs 暂定为：`Focus / Upcoming / 最近添加 / 高优先级`
- `Focus` tab 第一版先只展示用户手动 pin 的任务
- `Trash` 用于承接已删除的 `Project` 与 `Task`
- `Trash` 导航位置倾向放在 `Projects List` 下方
- `Project` 摘要区第一版默认展开

### 仍待确认
