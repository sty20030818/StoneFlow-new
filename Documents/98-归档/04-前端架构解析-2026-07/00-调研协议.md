# 调研协议 · 模块标准卡

> 每个被调研模块（大层 / feature / shared 子包 / 关键 route 组）必须填完整六卡。  
> 复制「空白模板」到对应 As-Is 章节使用。  
> 颗粒度：越细越好——大模块到文件级，小模块至少到公开 API 文件列表。

---

## 1. 评级枚举

### 现状评级（结论卡）

| 值 | 含义 |
|----|------|
| `Optimal` | 边界清晰、可删除性高、符合规范与官方用法 |
| `Acceptable` | 可用，有小债但不阻碍演进 |
| `Debt` | 明显耦合/职责混乱/规范违反，应进 Gap |
| `Critical` | 破坏不变式或双真相源，优先处理 |
| `TBD` | 未调研 |

### 建议动作

`Keep` | `Document-only` | `Extract` | `Split` | `Merge` | `Delete` | `TBD`

### 壳厚度（scene / 疑似假 feature）

| 值 | 含义 |
|----|------|
| `thin-shell` | 几乎只有页面壳，逻辑在别处 |
| `thick-feature` | 自包含能力 + UI + 数据 |
| `empty` | 无实现或仅空目录 |
| `mixed` | 壳与能力混杂 |
| `n/a` | 非 scene |

### Delete 分（1–5）

| 分 | 含义 |
|----|------|
| 5 | 删目录 + 卸装配 + 去 route 即可，他处几乎无感 |
| 4 | 少量 import 点需改，无业务纠缠 |
| 3 | 若干 feature/layout 引用，需适配层 |
| 2 | 枢纽依赖，删除需大规模改消费者 |
| 1 | 删了系统难跑；实质平台内核 |

质量项：`Pass` | `Partial` | `Fail` | `N/A` + 证据路径。

| 列 | 说明 |
|----|------|
| ID | `FE-APP-NAV`、`FE-ROUTE-SHELL`、`FE-F-TASK`、`FE-S-UI-BOARD`… |
| 路径 | 仓库相对路径 |
| 层 | app/routes/feature/shared/styles/test/entry |

| 文件数 | 整数 |

## 5. 依赖矩阵单元格（W7）

`from \ to`：  

- `0` 无依赖  
- `T` 仅类型  
- `P` 公开 API  
- `X` 触及私有实现（债）  
- `A` 仅装配（app 挂 provider）  
- `?` TBD
