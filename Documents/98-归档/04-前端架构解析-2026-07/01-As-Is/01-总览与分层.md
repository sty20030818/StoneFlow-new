## 3. 分层职责（As-Is 心智）

```txt
TanStack Router shell route
  → app/layouts 应用壳与页级骨架
  → features/* 业务能力、业务状态、数据接线
  → shared/* 跨业务 UI / query / events / lib
  → styles/* 全局样式与 token
  → Tauri IPC 经 feature api facade 进入 Rust
```

| 层 | 负责 | 不负责 |
|----|------|--------|
| `routes/` | URL 匹配、loader、redirect、route layout、页面入口 | 业务大块 UI、导航记忆规则、手拼复杂业务 path |
| `app/navigation/` | ShellRoute 语义、path builder、intents、启动恢复、session 历史 | 业务 mutation、页面 UI |
| `app/layouts/` | 壳骨架、页级编排、装配 feature providers | 实体业务规则真相 |
| `app/providers/` | QueryClient 等全局 provider | 业务规则 |
| `features/*` | api / query / model / 业务 UI | 重造 shared primitive、反向定义壳 |
| `shared/*` | 无产品归属的复用基建 | task/project/space 专属业务 |
| `styles/*` | token 与全局样式真相 | 页面补丁业务 |

## 4. 依赖方向（现行允许 / 禁止）

**允许**

```txt
app → features, shared, styles
features → shared, styles
shared → styles
styles → （不依赖业务）
```

**禁止（短契约不变式）**

1. `shared` → `features`
2. `styles` → 页面/业务组件
3. UI 散落裸 `invoke()`
4. store 复制 Query 已有服务器数据
5. 某 feature 私有状态成为全局真相源
6. 第二套路由 DSL / `tanstackCompat` 复活

**跨 feature 依赖**：现状待 W7 矩阵画清后，在 To-Be 固化策略（决策 3=C）。

## 6. 架构不变式（回退信号）

与 `src/ARCHITECTURE.md` §10 对齐，As-Is 调研中若发现违反，记入 Gap，不在调研中「顺手重构」：

6. bulk-action / command 塞回页面内部  
7. 为抽象而抽象的并行 registry / 状态机

## 7. 新代码落点决策树（现行）

1. 路由壳 / 布局骨架 / 全局 provider？→ `app/` 或 `routes/`  
2. 业务能力 / 查询 / 业务页面？→ `features/{name}/`  
3. 跨业务且无产品归属？→ `shared/`  
4. 视觉 token / 全局样式？→ `styles/`  
5. 只被一个 feature 用一次？→ **不要**升 `shared/`
