## 6. 工程纪律（破坏性必备）

### 6.1 分支

```txt
main（稳）
  └─ refactor/arch-t2-<史诗id>   每史诗一分支
       或 monorepo 式 stack：arch/1-dep-inv → arch/2-…
```

- 禁止在脏 main 上直接炸路由
- 大刀（5、6、10）考虑 **可回滚的 redirect 兼容**

### 6.2 每 PR 门禁

```bash
bun run check          # typecheck + lint + boundaries + format + tests + rust
# 史诗相关手工冒烟（§8）
```

### 6.3 禁止偷懒

- `--no-verify`
- 为过编临时 `any` 大面积
- 合并时留下「临时 re-export 永久化」无删窗

### 6.4 兼容窗

| 类型 | 建议 |
|------|------|
| public 路径迁移 | re-export **最多 1～2 个 PR 周期** 后删 |
| 旧 URL | redirect **长期** |
| Bridge 双轨 | C3 试点期：新 register + 旧 slice 转发，试点绿再删 |

## 7. 兼容与迁移技巧

| 场景 | 做法 |
|------|------|
| 命令 C3 | 先加 API 不删旧；task 试点；再删 slice |
| bulk B3 | 文件 git mv 到 domain；Boundary 改 import |
| 倒依赖 | 先引入 port 类型/回调，再删 layout import |
| 路由单树 | 先 path builder 只生成新 canonical；再改 file routes；最后 redirect 旧树 |
| QC 双搜 | 适配层统一 DTO，后端命令可后并 |
