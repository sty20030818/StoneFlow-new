## 1. 不可破原则（12 条）

下列原则在 To-Be 与 Migrate 期间**默认不可破**。破例须先写进 `X1-决策日志` 或本目录决策附录，并说明回退条件。

### P1 · 可删除性一等公民

删一个 feature 的理想代价：**去掉对应 `routes` 薄页 + 去掉 `layout` / `app` 上的装配注册**。  
不得要求先改其它 feature 的私有实现。互依仅允许 **Public Surface（B′）**。

### P2 · 真相源唯一

| 种类 | 唯一真相 |
|------|----------|
| URL / 导航位置 | TanStack Router（path + validated search） |
| 服务端/持久实体 | TanStack Query cache（经 feature `hooks`） |
| UI 瞬态（选中、弹层开合、本地草稿） | 组件 local / 明确 scoped Provider / 少量 Zustand |
| 跨启动恢复 | Tauri Store（经明确 api/navigation 边界，非到处读） |

禁止同一事实双写（例如 badges 既 store 又 query 无主从）。

### P3 · UI 与逻辑分离

| 侧 | 放什么 |
|----|--------|
| **UI** | `routes` 薄页 · `features/*/components` · `layout/*` · `shared/components` |
| **逻辑** | `features/*/model` · `hooks` · `api` |

- 页与 components **禁止** 直接 `invoke` / 直接碰 `api/`。  
- 只通过 **facade hooks**（`hooks/`）消费 `state` / `actions` / `meta`。

### P4 · 防腐层（ACL）必经门面

跨边界**禁止穿透**：

| 边界 | 门面 |
|------|------|
| Tauri/JSON ↔ 领域 | `api/` 实现 `model` 的 ports / 映射类型 |
| 视图 ↔ 用例与缓存 | `hooks/` facade |
| Feature ↔ Feature | **`index.public.ts`（或约定的唯一 public 入口）** |
| 主窗 ↔ QC 窗 | 共享停在 model + 必要 hooks 面；**不共享 layout 壳** |

ACL 不是多一个叫 anti-corruption 的文件夹，而是**依赖方向 + 唯一入口**。

### P5 · shared 防火墙

`shared/**` **不得** import `@/app`、`@/layout`、`@/features`、`@/routes`。  
只放与**具体业务实体无关**的 components / hooks / lib。  
业务 resolver、submit-from-form、scene wiring **不属于** shared。

### P6 · 高内聚 · 低耦合 · 模块化

- **内聚：** 改 task 相关行为，优先只动 `features/task/**`。  
- **耦合：** 跨 feature 只依赖 public；layout/app 只装配。  
- **模块化：** 按产品能力垂直切（`features/*`），不按「全仓 components/」平铺业务。  
- **组件化：** 可复用 UI 用 composition（compound / children），不用布尔参数丛林。

### P7 · DRY 与 KISS

- **DRY：** 第三份实质相同的逻辑再抽；优先抽到 **feature `hooks` facade**，不提前进 shared。  
- **KISS：** 不为抽象而抽象；小 feature 可不建空夹，但**不得**把 invoke 写进组件。  
- 死代码、空壳 feature：**默认删除**（M-0 取向确认）。

### P8 · 依赖单向

```txt
routes / app / layout  →  features (public)  →  shared
features/A             →  shared · features/B (public only)
shared                 →  （无业务树）
feature 内： components → hooks → api → model
```

违反方向的 import 视为架构缺陷（目标用 lint 固化，Migrate 落地）。

### P9 · 组合优于布尔扩展（Composition）

对齐 Vercel Composition Patterns：

- 不用一串 `showX` / `isY` 扩展同一组件；改 **显式变体** 或 **compound + children**。  
- Provider **只暴露**稳定的 `{ state, actions, meta }`，消费方不依赖内部 store 形态。  
- 复杂壳与 MainCard 类布局：**槽位组合**，不塞业务 if 森林。

### P10 · 路由与数据加载同构官方实践

**TanStack Router（原则级）：**

- File-based routes；pathless layout 挂铬架。  
- 薄页写在 `routes/**`（可与 route 文件同文件）；**不设**顶层 `pages/`。  
- loader 用 `ensureQueryData` + feature 导出的 `queryOptions`；loader 不做业务 if 大全。  
- search **校验 + 默认值**；导航优先 `Link` / typed `navigate`。  
- 意图预加载（intent preload）可保留/加强。

**TanStack Query（原则级）：**

- Query key **工厂**、层级、可序列化。  
- mutation 后 **定向 invalidate**（优于无脑 `invalidateAll`）。  
- 实体读模型进 Query；不把服务端列表真相放进全局 Zustand。

细则与检查表 → **T2 / T3 / T6**。

### P11 · React 性能与工程纪律（原则级）

对齐 Vercel React Best Practices（桌面 SPA 适用子集）：

- **直接 import** 具体文件；公共面 `index.public` 是**边界出口**，不是鼓励全仓深 barrel 链。  
- 独立异步 **并行**（`Promise.all`），避免无意义 waterfall。  
- 重渲染：稳定 actions、派生在 render、交互逻辑优先事件而非 effect；**不在组件内定义子组件**。  
- 非紧急更新可用 `startTransition`。  
- 长列表关注结构与 `content-visibility` 等渲染纪律（实现期）。

完整映射与 doctor 对照 → **T6**。

### P12 · 破坏性可接受 · 质量门不可破

- 允许**分史诗**大爆炸（目录搬家、壳拆分）。  
- **每个史诗结束**必须 `bun run check` 绿。  
- 大史诗后建议复跑 `react-doctor`；**不替代**架构原则与依赖 lint。

## 2. 术语表

| 术语 | 含义（StoneFlow To-Be） |
|------|-------------------------|
| **Feature** | `features/<name>/` 垂直产品切片；默认可删除单位 |
| **Public Surface / public** | feature 对外唯一允许依赖面，约定文件 `index.public.ts`（B′） |
| **Private** | feature 内 `components` 实现细节；外 feature **禁止**深 import |
| **model** | feature 内领域：types、纯 rules、ports；无 React / 无 Tauri |
| **api** | feature 内基础设施：invoke / Store / listen；把外部形状压成 model |
| **hooks** | feature 内应用层：query/mutation、list-scene 等 facade |
| **components**（feature） | 业务 UI；只经 hooks 拿数据与动作 |
| **shared** | 与业务实体无关的 components / hooks / lib |
| **app** | 组合根：bootstrap（Providers/QueryClient）、navigation 语义 |
| **layout** | 应用铬架：侧栏/顶栏/主区、EntityScene 槽、CommandBridge 装配、壳级 overlay |
| **routes** | TanStack file routes + **薄页**；路由 layout 只挂 `layout` 出口 |
| **Assembly / 装配** | 在 app/layout 把 feature public 注册进壳（命令、侧栏项等），不写实体规则 |
| **Command Bridge** | layout 侧组合各 feature 提供的 command 实现切片；菜单 UI 可在 command feature |
| **EntityScene** | layout 内零业务槽位编排（board/header/…）；不认实体 DTO |
| **MainCard** | `shared/components` 纯布局 compound |
| **list-scene / Scene facade** | 列表页共用的应用编排 hook（数据+选择+bulk 注册等）；落在 **owner feature 的 hooks**，不进 shared |
| **Platform feature** | 被多处装配的能力型 feature（command、selection、bulk…）；仍走 public |
| **Domain feature** | 实体能力（task、project、space…） |
| **Scene / 薄页** | URL 级接线；逻辑在 feature hooks，UI 块在 feature components |
| **QC** | Quick Create 独立窗；共享 L0–L2（model + 必要 hooks）；不共享主窗 layout |
| **ACL / 防腐** | 跨边界只经门面翻译，禁止穿透 |
| **Pilot β** | 先在 task + layout 路径落地内部分带与 lint，再铺开 |

*旧称对照（讨论期）：* modules→features · ui-kit→shared/components · app/shell→layout · pages→routes 薄页。

## 6. 新代码落点决策树（原则级）

```txt
1. 路由匹配 / loader / 薄页？           → routes/
2. 启动 Provider / QueryClient？        → app/bootstrap
3. 路径语义 / intent / 路由记忆？       → app/navigation
4. 侧栏顶栏主区 / 命令桥装配 / 槽位？    → layout/
5. 与业务无关的组件/hook/工具？        → shared/{components,hooks,lib}
6. 某能力的类型/纯规则/端口？          → features/X/model
7. 某能力的 invoke / Store / 事件 IO？ → features/X/api
8. 某能力的 Query / 用例 / 场景 facade？→ features/X/hooks
9. 某能力的业务界面？                  → features/X/components
10. 否则：是否该新 feature？禁止 shared「暂时放放」
```
