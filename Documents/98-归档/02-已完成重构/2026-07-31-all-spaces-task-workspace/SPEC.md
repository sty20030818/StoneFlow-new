# 所有空间任务执行台落地 - Spec

## 背景与目标

StoneFlow 已具备 `Scope = all | space` 路由与跨 Space 列表查询能力，但「所有空间」尚未按产品心智收口：导航与单 Space 镜像过度、文案不统一、任务行未必稳定露出 Space 归属，创建与项目入口边界也未钉死。

本任务把「所有空间」落地为**个人跨 Space 的任务执行台**：数据上是可见 Space 的 Task 并集，产品上主要服务「看任务量与优先级分布、改状态/优先级」，而不是第二个组织容器。

已确认的产品契约摘要：

| 决策 | 结论 |
|---|---|
| 定位 | Task 查询并集 / 执行台，不是实体 Space |
| 默认页「所有任务」 | 与单 Space **同一语义**（同一 list/viewKey 规则），仅 scope 不同 |
| 默认呈现 | 状态 Board；组内优先级可扫 |
| 项目 | V1 不管；侧栏项目树在 All 下不展开；不强调项目总览/独立事项入口 |
| 新建 | 允许；Space 选择器必须可见且可改 |
| View | 与单 Space 同一套系统 View + filter，仅 `scope` 不同 |
| 深链 | 桌面端用户几乎到不了 `/all/projects` 等；**不做强制重定向** |

## 范围

- 统一「所有空间」产品文案与侧栏切换心智。
- 收口 All scope 下的正式导航：主能力为「所有任务」「视图」；不把项目总览、独立事项宣传为 All 主入口；侧栏项目树在 All 下不展开。
- 默认打开 `/all/tasks`：跨 Space「所有任务」列表与单 Space 同语义、状态 Board、组内优先级可扫、每条可见 Space 归属。
- 在 All 内创建任务：必须显式选择 Space（可预填默认/上次 Space，不可静默无感）。
- 保持同一套系统 View / 自定义 View / filter 模型，在 `scope=all` 下可运行。
- 一等操作为改状态、改优先级及既有批量能力；与单 Space 任务集合场景复用，不新造第二套 Board。
- 同步产品与界面长期文档中与 All scope 冲突的描述。

## 不做什么

- 不把 All 做成完整镜像单 Space 的组织工作区（不建跨 Space 项目树、不把独立事项做成 All 主入口）。
- 不做收藏 Project、跨 Space 项目总览增强、日期轴默认首页、「需要关注」三块硬编排默认页。
- **不为** `/all/projects`、`/all/standalone` 等做强制 redirect 或删除路由（桌面端正常导航到不了；路由可继续存在但不作为正式能力宣传）。
- 不新增标签、多人共享 Space、账号体系或全局未归类容器。
- 不重做同步协议、不改 Task/Project 归属不变式（Task 永远属于具体 Space）。
- 不借机大范围重构 display-options / Board 架构；只做 All 契约所需的最小接线与展示修正。
- 不改变启动恢复策略的长期哲学（若需微调默认 path，仅限 All 相关一致性，不重做整个 memory 系统）。

## 用户场景与需求

### US-1：跨 Space 扫一眼工作负载

作为同时使用 3–5 个 Space 的个人用户，我想在「所有空间」的「所有任务」里看到各 Space 任务及其优先级/状态分布，以便判断整体压力并决定先推什么。

### US-2：在一处调整状态与优先级

作为用户，我想在所有空间列表里直接改任务状态和优先级（含多选批量），以便跨项目一起安排工作，而不必反复切换 Space。

### US-3：看清每条任务属于哪里

作为用户，我想在聚合列表中稳定看到每条任务所属 Space（及有则 Project），以便在跨上下文列表里敢直接操作。

### US-4：在聚合面创建但不建错归属

作为用户，我想在所有空间里新建任务时必须看到并可修改目标 Space，以便记录想法时不会静默落到错误上下文。

### US-5：用同一套 View/Filter 切片

作为用户，我想在所有空间使用与单 Space 同构的系统 View 和筛选，以便学习成本最低，而不是再学一套「全局专用视图语言」。

## 能力边界

- **数据语义**：`scope=all` 表示所有**可见且未软删** Space 下的 Task 并集；写入永不把 `all` 当作 `space_id`。
- **「所有任务」语义**：与单 Space 的「所有任务」**同一 list 规则**（同一 `viewKey` / placement 约定）；仅过滤范围变为跨 Space。不在 All 单独改成「仅未完成」数据集，以免名实不符。
- **默认呈现**：按状态分组（Board）；组内排序以优先级可扫为约束（见 PLAN）。
- **行级归属**：All 任务列表中每条任务固定能看到 Space 名；有 Project 时也能看到 Project 名。
- **导航**：All 下正式主入口为「所有任务」「视图」；页脚归档/回收站若沿用 scope 路径可保留聚合语义。项目总览与独立事项不作为 All 正式主能力（侧栏不展开项目树；主导航不强调或隐藏对应项）。
- **创建**：All 内允许创建 Task；Space 控件始终可见；禁止无 Space 提交。不在 All 内提供创建 Project 的主路径。
- **量级假设（验收参照）**：活跃 Space 约 3–5，未完成 Task 约 &lt;50；不以大数据虚拟列表为 V1 目标。

## Definition of Done

- 全部编号验收标准通过定向自动化测试和/或明确的手动验证步骤。
- All / 单 Space 切换、默认任务列表、创建归属、View 同构路径无阻塞性回归。
- 文案统一为「所有空间」；侧栏不再把项目总览/独立事项宣传为 All 主能力。
- 关联长期文档（P2 / A3 等，清单见 PLAN）已与本契约对齐。
- 受影响 TypeScript 检查、边界检查、格式检查、相关 Vitest 通过；若触及 Rust command 契约则对应 `cargo test` 通过。

## 验收标准

- **AC-1**：当用户从 Space 切换器进入「所有空间」时，系统应当进入 All scope 的默认工作路径，且界面主标签文案为「所有空间」（不得再出现「全部 Spaces」等混用文案）。
- **AC-2**：当用户位于 All scope 的「所有任务」页时，系统应当使用与单 Space「所有任务」相同的列表语义（同一 viewKey/placement 约定），仅将范围扩大为跨可见 Space，并默认按状态 Board 展示。
- **AC-3**：只要任务出现在 All「所有任务」列表中，系统应当使该任务的 Space 名称可被扫读；若任务属于 Project，还应当可扫读 Project 名称。
- **AC-4**：当用户在 All「所有任务」列表中修改单条任务的状态或优先级时，系统应当持久化该变更，并在列表中反映更新后的状态/优先级。
- **AC-5**：当用户在 All「所有任务」列表中多选任务并执行批量改状态或批量改优先级时，系统应当对选中任务应用同一变更（行为与单 Space 任务集合一致，仅 scope 不同）。
- **AC-6**：当用户在 All scope 打开「创建任务」时，系统应当展示可修改的 Space 选择器；当用户未选择有效 Space 时，系统不得成功创建任务。
- **AC-7**：当用户在 All scope 创建任务并选定 Space 后，系统应当把任务归属写入该 Space（Project/独立事项规则与现有创建契约一致），且不得写入虚构的 `all` 归属。
- **AC-8**：当用户位于 All scope 时，系统不得在侧栏项目列表中展开各 Space 的项目树；系统不得将「独立事项」作为 All 的正式主导航主入口（单 Space 下的独立事项入口保持不变）。
- **AC-9**：当用户在 All scope 打开系统 View（如今天、待处理、已逾期等既有系统 View）时，系统应当在 `scope=all` 下运行同一套 View 定义，而不是要求用户切换到单 Space。
- **AC-10**：当用户位于 All scope 时，主导航不得把「项目总览」宣传为与单 Space 等价的正式主能力（运行时隐藏或降级展示即可；不要求删除路由或做 URL 强制重定向）。

## 关联模块

- `src/app/navigation/`（scope 编码、默认落地、记忆 path）
- `src/layout/`（侧栏 Space 切换、主导航、文案、创建壳装配）
- `src/features/task/`（列表场景、Board、创建表单、批量）
- `src/features/display-options/`（默认分组/排序，仅最小必要）
- `src/features/view/`（系统 View 在 `scope=all` 下）
- `src/features/space/`（`setActiveScope`、可见 Space 列表）
- `src/features/project/`（All 下入口收敛，不新增项目能力）
- `src/features/lifecycle/`（归档/回收站 All 聚合若受导航影响则回归）
- `src/routes/_shell/`（薄路由；本任务不强制改深链行为）
- 后端既有 `list_tasks` / `run_task_view` scope 契约（优先复用，非必须改 schema）

## 当前技术方案

采用「**产品契约收口 + 复用既有 scope 查询与任务集合场景**」：不新增实体、不新增 IPC 协议族。「所有任务」在 All 与单 Space **同语义**；强化 All 下行级 Space 可见性与创建 Space 显式选择；导航层收敛项目/独立事项入口，**不做深链重定向**。细节见 [PLAN.md](PLAN.md)。
