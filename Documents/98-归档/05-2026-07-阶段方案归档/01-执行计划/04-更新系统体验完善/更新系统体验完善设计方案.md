# StoneFlow 更新系统体验完善设计方案

> 版本：v1
> 状态：已实现（P0–P2 + 状态单轨/迁移退役）
> 日期：2026-07-09
> 作用：在既有应用内更新基础设施上，收敛更新模式、补齐静默下载与系统状态 UI，形成长期可演进方案
> 前置文档：`Docs/01-执行计划/03-应用内更新系统/应用内更新系统技术方案.md`
> 适用范围：StoneFlow Desktop（Tauri v2）

---

## 0. 结论摘要

| 决策 | 内容 |
|------|------|
| 更新模式 | **三档**：手动检查 · 仅提醒 · 自动下载（删除「自动下载并安装」） |
| 自动下载语义 | **完全静默下载** → 完成后提醒重启；下载过程中不弹模态框 |
| UI 主路径 | **A Footer 系统状态轨** 为主 |
| 下载进度语言 | 借用 **B 进度环**（嵌在 footer 状态项内，不占 header） |
| 就绪 / 重启 | 借用 **C 按需 Status Chip**（就绪时强化 CTA，非阻塞） |
| 同步 | 迁入 / mirror 到 footer，与更新同属「系统状态」 |
| 重启策略 | **永不自动重启**；用户确认后 `restart_and_install` |
| 检查节奏 | 启动延迟检查 + 固定间隔（默认 6h）；本阶段间隔仍硬编码，预留设置扩展位 |

本方案是 **长期形态**，不是临时补丁：状态机、组件边界、模式行为表一次定清，实现可分批落地。

## 1. 背景与问题

### 1.1 已具备的能力（v1 基础）

- Tauri updater 签名校验、CDN/R2 静态 JSON 分发
- domain / usecase / runtime 分层与 IPC
- 设置页模式选择、手动检查、更新弹窗、跳过版本
- 启动 3s 后自动检查 + 每 6h 循环（`schedule_update_checker`）

### 1.2 当前瑕疵（审计结论）

| 问题 | 说明 |
|------|------|
| 四档名实不符 | `AutoDownload` 与 `AutoInstall` 代码同一分支，无行为差异 |
| 「自动」不静默 | 自动模式发现更新仍 `emit update-available` → 前端直接开大弹窗 |
| 后台下载无栖身之所 | 进度只在 `UpdateDialog`；无 shell 级指示 |
| 下载不可取消 | UI 禁止关闭，无 cancel API / 状态 |
| 模式差异薄弱 | 用户不进设置、不点检查时感知弱（节流 / Manual / 失败静默） |
| 并发竞态 | 自动下载进行中用户再点「立即更新」可双重 `download_and_install` |
| 同步与更新割裂 | 同步在 sidebar 底条，更新无系统入口 |

### 1.3 目标

1. **模式清晰**：三档、可预期、文案与行为一致
2. **静默可信**：自动下载不打断主工作流，但进度可感知
3. **就绪明确**：下载完成后用户一定知道「该重启了」
4. **系统状态统一**：footer 承载健康 / 同步 / 更新 / 版本
5. **可演进**：状态机与组件可扩展「导出中」「备份中」等同类后台任务

### 1.4 非目标（本阶段）

- 真正的静默自动重启 / 强制更新
- 差分包（delta）
- 检查间隔用户可配置 UI（仅预留字段与常量收口，默认仍 6h）
- Header 常驻下载按钮
- 移动端

## 2. 产品：三档更新模式

### 2.1 模式定义

| 模式 | `UpdateCheckMode` | 自动检查 | 发现更新 | 下载 | 就绪 |
|------|-------------------|----------|----------|------|------|
| **手动检查** | `manual` | 否 | 仅用户点「检查更新」 | 用户确认后下载 | 弹窗或 Chip 重启 |
| **仅提醒** | `notifyOnly`（默认） | 启动 + 定时 | **模态 `UpdateDialog`** | 用户点「立即更新」 | Dialog / Chip「重启」 |
| **自动下载** | `autoDownload` | 启动 + 定时 | **不弹窗**，立即静默下载 | 后台 + footer 环 | **Status Chip + footer 就绪态** |

删除：`autoInstall` / 「自动下载并安装」。

### 2.2 设置页文案（定稿）

| 模式 | 标题 | 描述 |
|------|------|------|
| 手动检查 | 手动检查 | 不自动检查。仅在你点击「检查更新」时查询。 |
| 仅提醒 | 仅提醒 | 启动后及定期自动检查。发现更新时弹窗提醒，由你决定是否下载。 |
| 自动下载 | 自动下载 | 自动检查并在后台静默下载。下载完成后提醒你重启生效。 |

### 2.3 迁移规则

- 已持久化且值为 `autoInstall` 的设置 → **读时迁移为 `autoDownload`** 并回写 store
- 设置 UI 不再渲染第四档
- domain 枚举移除 `AutoInstall`（或 `#[serde(other)]` 过渡一期后删除；推荐直接迁移 + 删除，避免双语义残留）

## 3. 交互总览

### 3.1 组合策略：A 为主 + B 环 + C Chip

```
┌─ Shell ──────────────────────────────────────────────────────────────┐
│ Header（不承担更新常驻控件）                                           │
│ Content                                                               │
│                                                                       │
│                    ┌─ Ready Chip（仅就绪时，可点稍后消失）─┐          │
│                    │  v0.2.1 已就绪          稍后   重启   │          │
│                    └──────────────────────────────────────┘          │
├─ Footer 系统状态轨 ───────────────────────────────────────────────────┤
│ ●健康  ·  同步 2m前 ↻  ·  ◎42% v0.2.1   │  v0.1.0  ·  ⌘K · C        │
│                         ↑ B 进度环嵌在此                               │
└───────────────────────────────────────────────────────────────────────┘
```

| 场景 | 主 UI | 辅助 |
|------|-------|------|
| 自动下载 · 下载中 | Footer 进度环 + 简短文案 | 点击 → 详情 Popover（版本、体积、说明摘要） |
| 自动下载 · 就绪 | **C Ready Chip**（强 CTA） | Footer 同步显示就绪态；可选一次 soft toast |
| 仅提醒 · 发现更新 | **UpdateDialog**（保留） | 可选 footer 小圆点「有更新」 |
| 仅提醒 / 手动 · 下载中 | Dialog 内进度条（可同步 mirror 到 footer 环） | — |
| 错误 | toast + footer / dialog 错误态 | 可重试 |

### 3.2 完全静默的边界

**自动下载模式下禁止：**

- 发现更新时打开 `UpdateDialog`
- 下载过程中抢焦点、阻断关闭主窗口以外的操作
- 自动调用 `restart`

**自动下载模式允许：**

- Footer 出现 / 更新进度环（非模态）
- 就绪时 Ready Chip + 一次 toast（`vX 已下载完成，重启后生效`）
- 用户主动点 footer / Chip 查看说明或重启

### 3.3 状态 × 模式矩阵

| `UpdateUiPhase` | manual | notifyOnly | autoDownload |
|-----------------|--------|------------|--------------|
| `idle` | 无更新 UI | 无 | 无 |
| `checking` | 仅设置页按钮 loading | 可无 shell UI | 可无 shell UI |
| `available` | Dialog（用户检查后） | **Dialog** | **跳过**，直接进入 downloading |
| `downloading` | Dialog 进度（+ footer 环 mirror） | 同左 | **仅 footer 环**（+ popover） |
| `ready` | Dialog 或 Chip | Dialog 或 Chip | **Chip + footer 就绪** |
| `error` | toast + 可重试 | 同左 | toast + footer 错误点 |

### 3.4 跳过版本

- **仅提醒**：Dialog「跳过此版本」→ 写入 `skipped_versions`，本版本自动检查不再提示
- **自动下载**：Popover / Chip 次要操作「跳过此版本」→ 取消后续自动下载（若已在下载见 §5.3 取消）；写入 skip
- **手动检查**：跳过列表不拦截手动检查结果（与现 usecase 一致：`manual=true` 不过滤 skip）

### 3.5 启动行为

1. App 启动 → `STARTUP_CHECK_DELAY_SECS`（3s）后自动检查（`manual=false`）
2. `manual` 模式：检查函数直接 no-op（不请求网络）
3. 其余模式：受 `AUTO_CHECK_INTERVAL_SECS`（6h）与 `last_checked_at` 节流
4. 前端 `useUpdateEvents` 必须在 shell 挂载后监听全局事件；启动检查延迟 3s，避免 listener 未就绪丢事件（若仍担心：后端在 listener 就绪前可缓存 last payload，见 §5.4）

## 4. UI 设计规格

### 4.1 Footer 系统状态轨（方案 A）

#### 4.1.1 信息架构

**左侧（系统状态，`min-w-0 flex-1`，可收缩）：**

1. **健康点**（现有 healthcheck）
2. **同步项**（从 sidebar strip mirror / 迁移）
3. **更新项**（仅 `phase ∈ {available, downloading, ready, error}` 时显示；`idle/checking` 默认可隐藏）

**右侧（元信息 + 快捷键）：**

1. **当前版本** `v0.1.0`（muted，`tabular-nums`）
2. 分隔点 ·
3. 快捷键提示（现有 ⌘K / C；窄宽时优先隐藏文案只留 Kbd，或折叠）

Footer 高度维持 **`h-7`（28px）**，不增高；信息靠密度与省略，不靠长文案。

#### 4.1.2 同步项

| 状态 | 展示 |
|------|------|
| 未配置 | `同步 · 未配置`（点按打开同步配置） |
| 空闲 | `同步 · 2 分钟前` + 可选 ↻ |
| 同步中 | 点 + `同步中`（pulse） |
| 错误 / 需处理 | 点 danger + 短文案；点按打开详情 |

**与 sidebar 关系（长期）：**

- Footer = 全局精简状态（主入口）
- Sidebar `SyncSidebarStatusStrip`：迁移期 **双写**；稳定后降级为「仅 blocked / 未配置时显示」，或改为点击 footer 同步项打开的 Popover 内容复用同一 presentation 层

#### 4.1.3 更新项 + 进度环（方案 B 嵌入）

**结构（从左到右）：**

```
[ ProgressRing 14–16px ] [ 文案 11px ]
```

| phase | 环 | 文案 | 点击 |
|-------|----|------|------|
| downloading | stroke 进度 0–100%；无 total 时 indeterminate 旋转 | `42%` 或 `下载中` | 打开 Download Popover |
| ready | 闭合环 + emerald 勾 | `v0.2.1 就绪` | 聚焦 Ready Chip 或打开 Restart Popover |
| available（notify） | 实心小点 / 空环 | `有更新` | 打开 UpdateDialog |
| error | 危险色环断点 | `更新失败` | 打开错误详情 + 重试 |

**进度环视觉（定稿）：**

- 直径：**14–16px** 可见；热区 **≥ 28–32px**（footer 内用 padding 扩 hit area）
- 轨道：`foreground/15`
- 进度弧：`foreground/70` 或 `primary` **低饱和**（下载中 **不用** 高饱和绿）
- 就绪：弧 `emerald-600`（dark: `emerald-400`），中心可选 check icon 9px
- stroke：**2px**；`stroke-linecap: round`
- 百分比文案：`tabular-nums`，避免布局抖动
- 动效：进度用 `stroke-dashoffset` transition ~200ms；indeterminate 用慢旋 `transform`；**禁止**外发光 / 霓虹

**Download Popover（下载中点击 footer 更新项）：**

- 标题：`正在下载 {version}`
- 进度条 + `12.4 MB / 28.0 MB`（`tabular-nums`）
- 可选：release notes 折叠摘要
- 操作：`取消下载`（若 §5.3 可用）· `后台继续`（关闭 popover）

#### 4.1.4 版本号

- 右侧常驻当前应用版本（来自 Tauri `getVersion` 或构建注入）
- Beta 渠道：版本旁小 badge `Beta`（与设置页一致，极小）
- 不展示「检查中」在版本号上，避免与更新项重复

### 4.2 Ready Chip（方案 C）

#### 4.2.1 出现条件

- `phase === ready`
- 且用户未在本会话点「稍后」dismiss 该 version

#### 4.2.2 位置与形态

- **主内容区底部居中**（footer 上方 8–12px），`pointer-events-auto`
- 非模态：不挡操作、无 scrim
- 形态：pill / 轻 elevation

```
┌─────────────────────────────────────────────┐
│  ●  v0.2.1 已就绪              稍后    重启  │
└─────────────────────────────────────────────┘
```

- 主按钮「重启」：solid / primary
- 「稍后」：ghost → dismiss Chip；**footer 就绪态保留**，可再次点开
- 首次进入 ready：chip `opacity + translateY(4px)` 入场；可选同步一次 `toast.success`
- 退出：更轻的 translateY + opacity

#### 4.2.3 与 Dialog 分工

| 入口 | 用 Dialog | 用 Chip |
|------|-----------|---------|
| 仅提醒 · 发现更新 | ✅ 主路径 | footer 可选 mirror |
| 用户手动「立即更新」下载完成 | 可继续留在 Dialog「重启」 | 若用户关 Dialog，Chip 兜底 |
| 自动下载完成 | ❌ 不自动开 Dialog | ✅ 主路径 |
| 设置页手动检查发现更新 | ✅ 可开 Dialog | — |

原则：**打断式决策（是否下载）用 Dialog；后台完成（是否现在重启）用 Chip。**

### 4.3 UpdateDialog（保留，职责收缩）

保留并用于：

1. `notifyOnly` / `manual` 的「发现更新」
2. 用户主动下载时的进度与错误（可与 footer 环双写）
3. 更新说明（markdown 轻量渲染，现有实现可复用）

**自动下载路径不再调用 `showUpdate()` 打开 Dialog。**

下载中：

- 允许关闭 Dialog（改为 mirror 到 footer），**或** 提供「取消」——与 §5.3 对齐
- 禁止「无取消且锁死关闭」的体验

### 4.4 动效与质感（约束）

- 只动画 `opacity` / `transform` / SVG `stroke-dashoffset`
- 按钮 `active:scale-[0.96]`
- 数字 `tabular-nums`
- 同心圆角：popover / chip 外层与内边距符合 outer = inner + padding
- 不用纯黑、不用紫色光晕、不用 emoji

### 4.5 无障碍

- Footer 更新项、`role="status"` / `aria-live="polite"` 播报就绪
- 进度环：`role="progressbar"` + `aria-valuenow/min/max`
- Chip 按钮可键盘聚焦；`Esc` 等同「稍后」
- 热区满足约 40×40 等效（footer 高度限制下用 invisible padding）

## 5. 后端与状态机

### 5.1 领域：`UpdateCheckMode` 收敛

```rust
pub enum UpdateCheckMode {
    Manual,
    NotifyOnly,
    AutoDownload,
}
```

- 删除 `AutoInstall`
- 默认仍为 `NotifyOnly`
- 设置加载时迁移旧值

### 5.2 运行时会话状态（建议新增）

当前只有「检查 + 无锁 download」。长期方案需要 **进程内 UpdateSession**：

```text
Idle
  → Checking
  → Available { info }          // notify/manual 等待用户
  → Downloading { info, prog }  // 单飞
  → Ready { version }           // 已预装，待重启
  → Error { message, retryable }
```

约束：

- **同一时刻最多一个 download**（Mutex / watch channel）
- `download_and_install` 入口若已在 Downloading → 返回已有会话或 no-op
- 自动模式：`Available` 对用户不可见，内部立刻转入 Downloading
- Ready 后再次自动检查：同版本不重复下载

事件建议（可在现有事件上演进）：

| 事件 | 载荷 | 用途 |
|------|------|------|
| `update-phase` | 统一 phase + 进度 + version | 前端单入口（长期优选） |
| 或保留 | `update-available` / `update-download-progress` / `update-downloaded` / `update-error` | 兼容；**autoDownload 不再对 available 开 Dialog** |

前端 store 与后端 phase 对齐，避免 Dialog / footer / chip 各写一套真相。

### 5.3 取消下载

**目标体验：** 下载中可取消。

**实现策略（分阶段）：**

| 阶段 | 行为 |
|------|------|
| P0 | UI 暴露「取消」入口；若插件无法中断，则「取消」= 放弃 UI 会话 + 忽略后续进度（best-effort）；文档标明可能仍会下完 |
| P1 | 调研 `tauri-plugin-updater` 是否支持分离 `download` + 取消；或改用可控 HTTP 下载 + 校验安装 API |
| P1+ | 真取消：abort 网络、清理临时文件、phase → Idle/Available |

本设计 **产品层必须预留取消**；P0 不可再「锁死 Dialog 且无出口」。

### 5.4 启动检查与事件时序

- 保持 3s 启动延迟 + 6h 间隔
- 自动模式发现更新：**只**走下载调度，emit progress / downloaded / error
- **不要**先 emit available 再下载（避免前端误开 Dialog）
- 可选：`UpdateSession` 快照 command `get_update_session`，前端挂载时 hydrate，防丢事件

### 5.5 `download_and_install` 去重

- 去掉「命令内再 check + adapter 内再 check」的双重检查（保留一次 check 或持有 Update 句柄）
- IPC `download_and_install` 与 bootstrap 自动下载共用同一 service 方法 + 会话锁

### 5.6 检查间隔（长期预留）

```rust
// domain
pub const AUTO_CHECK_INTERVAL_SECS: i64 = 6 * 60 * 60;
// 未来 UpdateSettings.check_interval_secs: Option<i64>
```

本阶段 **不**做设置 UI；常量保持单一来源。

### 6.3 模式分流（前端伪代码）

```ts
onAvailable(info) {
  if (checkMode === 'autoDownload') {
    // 正常应由后端直接下载且不发 available；
    // 若仍收到：忽略弹窗，仅确保 phase 进入 downloading
    return
  }

onProgress(p) {
  setPhase('downloading', p)
  // 不强制 openDialog
}

onDownloaded({ version }) {
  setPhase('ready', version)
  toast once
  show ReadyChip unless dismissed
```

## 7. 与 v1 技术方案的关系

| v1（03 文档） | 本方案 |
|---------------|--------|
| 四档模式含 AutoInstall | **三档**，删除 AutoInstall |
| 自动下载后「提示重启」 | 明确为 **静默下载 + Chip/footer**，非大弹窗 |
| 前端以 Dialog 为中心 | Dialog 仅决策下载；系统态在 footer/chip |
| 6h + 启动检查 | 保持；补齐事件与会话 |
| 不强制重启 | **保持** |

## 12. 附录

### 12.1 线框：自动下载完整路径

```
启动
  → 3s 后 check (auto)
  → 有更新
  → [不弹窗] start download (session lock)
  → Footer: ◎ 12% …
  → 用户可点开 Popover 看详情 / 取消
  → download complete
  → toast ×1
  → Ready Chip:「v0.2.1 已就绪 · 稍后 · 重启」
  → Footer: ◎就绪 v0.2.1
  → 用户点重启 → app.restart()
```

### 12.2 线框：仅提醒路径

```
启动 / 定时 check
  → 有更新
  → UpdateDialog（说明 + 跳过 + 立即更新）
  → 下载中：Dialog 进度 + footer 环 mirror
  → 完成：Dialog 重启 CTA；关闭后 Chip 兜底
```
