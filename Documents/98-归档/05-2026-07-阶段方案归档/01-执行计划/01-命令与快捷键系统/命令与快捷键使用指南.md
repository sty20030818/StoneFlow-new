> 以键盘为核心的任务流操作规范

---

## 1. 文档目标

StoneFlow 是一个以「快」为主旨的个人任务管理工具。它不应该只依赖按钮、菜单和鼠标操作，而应该允许用户通过键盘快速完成大部分高频任务。

本文件用于定义 StoneFlow 的命令体系、快捷键规则、使用场景、排序逻辑和扩展边界。

这是一份偏用户侧 / 产品侧的命令文档，目标是让产品、设计、开发和 AI 协作时都能明确：

- StoneFlow 有哪些核心命令；
- 哪些命令需要默认快捷键；
- 哪些命令只进入 Command Menu；
- 不同页面、不同选中状态下，命令应该如何出现和排序；
- 快捷键冲突、输入状态、弹窗状态应该如何处理。

---

## 2. 命令系统定位

### 2.1 Command 是一等公民

StoneFlow 的所有能力都应该优先被抽象为 Command。

快捷键只是 Command 的一个入口，不是功能本身。

也就是说：

- 一个功能可以没有快捷键，但应该可以在 Command Menu 中被搜索和执行；
- 一个功能如果足够高频、稳定、低风险，才值得绑定默认快捷键；
- Command Menu 是 StoneFlow 的全局操作中心；
- 快捷键是高频命令的加速入口。

### 2.2 Command Menu 与 Quick Create 分离

StoneFlow 中存在两个不同的快速入口：

| 入口 | 定位 | 典型场景 |
|---|---|---|
| Quick Create | 极快创建任务 | 快速输入任务标题、选择项目、设置优先级 |
| Command Menu | 操作整个软件 | 搜索、跳转、打开对象、执行命令、批量操作 |

二者可以共享底层命令系统，但不应该是同一个窗口。

Quick Create 只服务「创建」，Command Menu 服务「所有操作」。

### 2.3 快捷键不是越多越好

StoneFlow V1 不追求给每一个命令都绑定快捷键。

默认快捷键应该只覆盖：

- 高频创建；
- 高频导航；
- 高频搜索 / 打开；
- 任务的高频编辑；
- 任务的批量操作；
- 常用面板切换；
- 常用系统操作。

低频、危险、复杂、后期能力可以只存在于 Command Menu。

## 3. 核心设计原则

### 3.1 快捷键服务高频操作

默认快捷键只服务高频、稳定、低风险的命令。

例如：

- `C` 完成任务；
- `P` 修改优先级；
- `S` 修改状态；
- `D` 打开日期菜单；
- `M P` 移动到项目；
- `G I` 跳转收件箱；
- `O P` 打开某个项目。

复制 URL、复制 ID、导出、恢复、查看活动记录等低频操作，优先只放在 Command Menu。

### 3.2 上下文决定命令优先级

Command Menu 不应该是一个静态命令列表。

它应该根据当前上下文动态排序。

典型上下文包括：

- 当前页面；
- 当前 Space；
- 当前 Project；
- 当前 View；
- 是否选中了任务；
- 选中了一个任务还是多个任务；
- 当前焦点是否在输入框；
- 当前是否打开了 Preview Drawer / Detail Drawer / Modal。

### 3.3 输入状态下不抢普通按键

当用户正在输入任务标题、备注、搜索词或其他文本内容时，普通字母键不应该触发快捷键。

输入状态下仍可生效的快捷键主要是：

| 快捷键 | 作用 |
|---|---|
| `Esc` | 返回 / 关闭 / 取消 |
| `Cmd/Ctrl + Enter` | 保存 / 提交 |
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `Cmd/Ctrl + Z` | 撤销 |
| `Cmd/Ctrl + Shift + Z` | 重做 |

### 3.4 单键只给当前上下文最高频动作

单键快捷键应该谨慎使用。

例如：

| 快捷键 | 任务上下文 | 项目上下文 | 输入框上下文 |
|---|---|---|---|
| `R` | 重命名任务 | 重命名项目 | 输入字母 r |
| `S` | 修改任务状态 | 修改项目状态 | 输入字母 s |
| `A` | 归档任务 | 归档项目 | 输入字母 a |

同一个快捷键可以在不同对象上下文中执行同类操作，但不能在同一个上下文中产生歧义。

### 3.5 前缀快捷键保持克制

StoneFlow V1 只保留 5 个核心前缀：

| 前缀 | 含义 | 示例 |
|---|---|---|
| `N` | New，新建 | `N T`, `N P`, `N V` |
| `G` | Go to，跳转固定页面 | `G I`, `G T`, `G P` |
| `O` | Open，搜索并打开对象 | `O T`, `O P`, `O V` |
| `M` | Move，移动 | `M P`, `M S` |
| `F` | Filter，筛选 | `F P`, `F S`, `F D` |

不在 V1 引入过多前缀，避免学习成本过高。

### 3.6 `G` 与 `O` 必须区分

`G` 用于跳转固定页面。

`O` 用于搜索并打开具体对象。

例如：

| 快捷键 | 含义 |
|---|---|
| `G P` | 跳转到项目页面 |
| `O P` | 搜索并打开某个项目 |
| `G T` | 跳转到全部任务 |
| `O T` | 搜索并打开某个任务 |

这条规则必须保持稳定，否则后期命令体系会混乱。

### 3.7 `N` 作为创建前缀

StoneFlow 使用 `N` 作为 New / Create 前缀。

不使用 `C` 表示创建，因为 `C` 在 TODO 产品中更适合表示 Complete。

例如：

| 快捷键 | 含义 |
|---|---|
| `N T` | 新建任务 |
| `N P` | 新建项目 |
| `N V` | 新建视图 |
| `N S` | 新建空间 |

### 3.8 `Space` 用于预览

StoneFlow 中：

| 快捷键 | 含义 |
|---|---|
| `Space` | 打开 / 切换 Preview Drawer |
| `Enter` | 打开 Detail Drawer / 进入完整编辑 |
| `C` | 完成 / 取消完成任务 |

`Space` 不用于完成任务，而用于快速预览当前聚焦项。

## 4. 快捷键语法规则

### 4.1 单键快捷键

单键快捷键用于当前上下文最高频动作。

| 快捷键 | 动作 |
|---|---|
| `Space` | 预览当前项 |
| `Enter` | 打开 / 编辑当前项 |
| `C` | 完成 / 取消完成任务 |
| `P` | 修改优先级 |
| `S` | 修改状态 |
| `D` | 打开日期菜单 |
| `R` | 重命名 |
| `A` | 归档 |
| `X` | 选择当前项 |
| `Esc` | 返回 / 关闭 / 清空 |
| `Delete` | 删除 |
| `/` | 打开搜索 |

### 4.2 前缀快捷键

前缀快捷键用于可扩展命令。

用户先按前缀键，再按目标键。

例如：

```txt
G I = Go to Inbox
O P = Open Project
N T = New Task
M P = Move to Project
F S = Filter by Status
```

### 4.3 修饰键快捷键

修饰键快捷键用于全局、系统级、窗口级操作。

| 快捷键 | 动作 |
|---|---|
| `Cmd/Ctrl + K` | 打开 Command Menu |
| `Cmd/Ctrl + Enter` | 保存 / 提交 |
| `Cmd/Ctrl + /` | 查看快捷键 |
| `Cmd/Ctrl + ,` | 打开设置 |
| `Cmd/Ctrl + Z` | 撤销 |
| `Cmd/Ctrl + Shift + Z` | 重做 |
| `Cmd/Ctrl + D` | 复制任务 / 项目，视上下文而定 |

### 4.4 前缀快捷键规则

| 规则 | 说明 |
|---|---|
| 最大长度 | V1 只支持两段式，如 `G I`、`O P` |
| 超时时间 | 用户按下前缀后，短时间内未继续输入则取消 |
| 按错处理 | 取消当前前缀状态，并给出轻提示 |
| `Esc` | 取消当前前缀状态 |
| 输入框中 | 不触发前缀快捷键 |
| 状态提示 | 可在界面角落显示当前前缀，如 `G …` |

## 5. General 全局命令

全局命令在大多数页面都可用。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Open Command Menu | `Cmd/Ctrl + K` | 打开命令菜单 |
| Open Search | `/` | 打开当前搜索 |
| Back / Close | `Esc` | 返回、关闭弹层、清空选择 |
| Save or Submit | `Cmd/Ctrl + Enter` | 保存当前编辑或提交当前表单 |
| View Keyboard Shortcuts | `Cmd/Ctrl + /` | 查看快捷键帮助 |
| Open Settings | `Cmd/Ctrl + ,` | 打开设置 |
| Undo | `Cmd/Ctrl + Z` | 撤销上一步操作 |
| Redo | `Cmd/Ctrl + Shift + Z` | 重做操作 |

### 5.1 使用场景

- 用户想执行一个不记得快捷键的操作时，使用 `Cmd/Ctrl + K`；
- 用户想搜索当前页面或全局内容时，使用 `/`；
- 用户想退出当前状态时，使用 `Esc`；
- 用户想保存编辑时，使用 `Cmd/Ctrl + Enter`。

### 5.2 输入状态规则

在输入框中：

- `/` 不触发搜索，只输入字符；
- 普通字母不触发命令；
- `Esc`、`Cmd/Ctrl + Enter`、`Cmd/Ctrl + K` 仍可生效。

## 6. Navigation 导航命令

导航命令用于跳转固定页面。

统一使用 `G` 前缀。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Go to Inbox | `G I` | 跳转收件箱 |
| Go to All Tasks | `G T` | 跳转全部任务 |
| Go to Today | `G D` | 跳转今日任务 |
| Go to Upcoming | `G U` | 跳转未来任务 |
| Go to Focus | `G F` | 跳转专注视图 |
| Go to Views | `G V` | 跳转视图中心 |
| Go to Projects | `G P` | 跳转项目页面 |
| Go to Archive | `G A` | 跳转归档 |
| Go to Trash | `G X` | 跳转回收站 |
| Go to Settings | `G S` | 跳转设置 |

### 6.1 命名规则

- `G` 只表示 Go to；
- `G` 后面跟固定页面的首字母或约定字母；
- `G P` 是跳转项目页面，不是打开某个项目。

### 6.2 `G D` 的说明

`G D` 表示 Go to Today。

这里的 `D` 来自 Day，用于避免和 `G T = Go to All Tasks` 冲突。

## 7. Open 打开对象命令

打开对象命令用于搜索并打开某个具体对象。

统一使用 `O` 前缀。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Open Task | `O T` | 搜索并打开任务 |
| Open Project | `O P` | 搜索并打开项目 |
| Open View | `O V` | 搜索并打开视图 |
| Open Space | `O S` | 搜索 / 切换空间 |
| Open Recent | `O R` | 打开最近访问 |
| Open Favorite | `O F` | 打开收藏项，后期支持 |

### 7.1 使用场景

- 用户知道自己要找某个任务，但不知道它在哪个项目；
- 用户想快速进入某个项目；
- 用户想打开最近访问的任务或项目；
- 用户想搜索某个自定义视图。

### 7.2 与导航命令的区别

| 目标 | 使用 |
|---|---|
| 去固定页面 | `G` |
| 打开具体对象 | `O` |

例如：

```txt
G P = Go to Projects
O P = Open Project
```

## 8. New 创建命令

创建命令统一使用 `N` 前缀。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| New Task | `N T` | 新建任务 |
| New Task in Current Project | `N C` | 在当前项目中新建任务 |
| New Project | `N P` | 新建项目 |
| New View | `N V` | 新建视图 |
| New Space | `N S` | 新建空间，后期支持 |
| New Task from Template | Command only | 从模板新建任务，后期支持 |
| New Project from Template | Command only | 从模板新建项目，后期支持 |

### 8.1 为什么不用 `N` 单键新建任务

StoneFlow V1 不使用 `N` 单键直接新建任务。

原因：

- `N` 已经被定义为 New 前缀；
- `N` 单键会和 `N P`、`N V`、`N S` 等前缀命令产生等待和歧义；
- 极快创建任务由 Quick Create 全局窗口负责；
- 应用内结构化创建使用 `N T` 更清晰、稳定。

### 8.2 创建任务的两个入口

| 入口 | 适合场景 |
|---|---|
| Quick Create | 快速捕获一条任务 |
| `N T` | 在主应用内结构化创建任务 |
| `N C` | 在当前项目内快速创建任务 |

## 9. List / Board 列表与看板命令

列表 / 看板命令用于在任务列表、项目列表、看板列之间移动、选择、预览和打开内容。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Peek Focused Item | `Space` | 预览当前聚焦项 |
| Open Focused Item | `Enter` | 打开当前聚焦项 |
| Select Item | `X` | 选择当前项 |
| Select All Visible Items | `Cmd/Ctrl + A` | 选择当前列表所有可见项 |
| Clear Selection | `Esc` | 清空选择 |
| Move Up | `↑` | 焦点上移 |
| Move Down | `↓` | 焦点下移 |
| Move Left | `←` | 看板中移动到左侧列 |
| Move Right | `→` | 看板中移动到右侧列 |
| Toggle Layout View | `Cmd/Ctrl + B` | 切换 List / Board |
| Show Display Options | `Shift + V` | 打开展示选项 |

### 9.1 不支持 Vim-like 默认快捷键

StoneFlow V1 不默认支持：

```txt
J = Down
K = Up
GG = Top
G = Bottom
```

原因：

- StoneFlow 不是程序员专用工具；
- 方向键更符合通用用户习惯；
- 避免与 `G` 前缀导航体系冲突。

后期可作为可选设置支持。

### 9.2 预览与打开的区别

| 操作 | 快捷键 | 说明 |
|---|---|---|
| Peek | `Space` | 打开右侧预览栏，偏只读和轻操作 |
| Open | `Enter` | 打开详情编辑，进入完整编辑状态 |

## 10. Task 任务命令

任务命令是 StoneFlow 最核心的一组命令。

### 10.1 单选任务命令

当用户选中或聚焦一个任务时，可使用以下命令：

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Peek Task | `Space` | 预览任务 |
| Open Task Detail | `Enter` | 打开任务详情 |
| Complete / Uncomplete Task | `C` | 完成 / 取消完成任务 |
| Rename Task | `R` | 重命名任务 |
| Change Priority | `P` | 修改优先级 |
| Change Status | `S` | 修改状态 |
| Open Date Menu | `D` | 打开日期菜单 |
| Set Planned Date | `Shift + D` | 快速设置计划时间 |
| Set Reminder | `H` | 设置提醒 |
| Move to Project | `M P` | 移动到项目 |
| Move to Space | `M S` | 移动到空间 |
| Archive Task | `A` | 归档任务 |
| Delete Task | `Delete` | 删除任务 |
| Duplicate Task | `Cmd/Ctrl + D` | 复制任务 |
| Copy Task Title | `Cmd/Ctrl + Shift + C` | 复制任务标题 |

### 10.2 多选任务命令

当用户选中多个任务时，Command Menu 和快捷键优先服务批量操作。

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Complete Selected Tasks | `C` | 批量完成 / 取消完成 |
| Change Priority | `P` | 批量修改优先级 |
| Change Status | `S` | 批量修改状态 |
| Open Date Menu | `D` | 批量设置日期 |
| Move to Project | `M P` | 批量移动到项目 |
| Move to Space | `M S` | 批量移动到空间 |
| Archive Selected Tasks | `A` | 批量归档 |
| Delete Selected Tasks | `Delete` | 批量删除 |
| Duplicate Selected Tasks | `Cmd/Ctrl + D` | 批量复制 |

### 10.3 日期菜单规则

`D` 不直接等同于「设置截止日期」。

`D` 用于打开 Date Menu。

Date Menu 中包含：

- 截止时间；
- 计划时间；
- 提醒时间；
- 今天；
- 明天；
- 本周；
- 自定义；
- 清除日期。

`Shift + D` 可作为「设置计划时间」的快捷入口。

### 10.4 任务 Command-only 命令

以下命令进入 Command Menu，但 V1 不绑定默认快捷键：

| 命令 | 原因 |
|---|---|
| Copy Task URL | 低频 |
| Copy Task ID | 低频 |
| Copy Task as Markdown | 低频 |
| Restore Task | 只在回收站等特殊场景出现 |
| Show Task Activity | 后期能力 |
| Convert Task to Project | 后期能力 |
| Add Note | 可通过详情面板完成 |
| Add Tag | 标签系统后期支持 |
| Remove Due Date | 可在日期菜单中完成 |
| Open Task in New Window | 后期能力 |

## 12. Views / Filters 视图与筛选命令

筛选命令用于当前页面的数据收敛。

视图命令用于打开、创建、保存和管理视图。

### 12.1 筛选快捷键

| 命令 | 快捷键 | 说明 |
|---|---|---|
| Add Filter | `F` | 添加筛选 |
| Filter by Priority | `F P` | 按优先级筛选 |
| Filter by Status | `F S` | 按状态筛选 |
| Filter by Date | `F D` | 按日期筛选 |
| Filter by Project | `F J` | 按项目筛选 |
| Clear All Filters | `Shift + F` | 清空所有筛选 |

### 12.2 `F J` 的说明

`F P` 已用于 Filter by Priority。

为了避免冲突，Filter by Project 使用 `F J`。

其中 `J` 来自 proJect。

## 16. 快捷键冲突与优先级规则

### 16.1 页面上下文优先

同一个快捷键可以在不同对象上下文中执行同类操作。

例如：

| 场景 | `R` 的含义 |
|---|---|
| 选中任务 | Rename Task |
| 选中项目 | Rename Project |
| 输入框中 | 输入字母 r |

### 16.2 输入框优先

只要当前焦点处于输入框、文本域、富文本编辑器中，普通字母键必须优先作为文本输入。

快捷键系统不能抢占用户输入。

### 16.3 Modal / Drawer 优先

如果当前存在弹窗、菜单或抽屉：

- 快捷键优先作用于当前弹层；
- 当前弹层无法处理时，才向外层传递；
- 危险操作不应该穿透弹层执行。

### 16.4 Esc 层级规则

`Esc` 的处理顺序：

```txt
候选菜单 / 下拉菜单
> Modal 弹窗
> Command Menu
> Detail Drawer
> Preview Drawer
> 当前选择
> 当前页面返回
```

### 16.5 Delete 操作规则

`Delete` 是危险操作，需要符合以下规则：

- 选中任务时删除任务；
- 选中项目时删除项目；
- 多选时批量删除；
- 输入框中不触发删除命令，只删除文本；
- 删除项目等高风险操作可以要求二次确认；
- 普通任务删除可进入回收站，不必每次确认。

## 20. 后续扩展

### 20.1 用户自定义快捷键

后期支持用户自定义快捷键。

需要保留：

- 默认快捷键；
- 用户自定义快捷键；
- 是否启用；
- 是否与其他命令冲突；
- 是否恢复默认。

### 20.2 最近使用命令权重

Command Menu 后期可以根据用户行为调整排序。

例如：

- 用户经常使用 Move to Project，则该命令排序提高；
- 用户经常打开某个项目，则该项目在 `O P` 中排序提高；
- 用户经常使用某个筛选器，则该筛选器在 Command Menu 中更靠前。

### 20.3 AI / Smart Actions

后期可加入智能命令。

例如：

- 整理收件箱；
- 拆分任务；
- 总结项目；
- 推荐下一步；
- 自动生成任务计划；
- 优化任务标题；
- 根据任务生成子步骤。

这些命令初期只进入 Command Menu，不绑定默认快捷键。

### 20.4 更多页面专属命令

后期如果出现 Calendar、Timeline、Review、Statistics 等页面，可以为页面增加专属命令。

但页面专属命令必须遵守以下规则：

- 不破坏全局快捷键语义；
- 不抢占任务高频单键；
- 优先在当前页面上下文中展示；
- 低频能力只进入 Command Menu。

## 21. 最终约定

StoneFlow V1 的快捷键体系采用以下核心约定：

```txt
Cmd/Ctrl + K = Command Menu
全局热键 = Quick Create

N = New
G = Go to fixed page
O = Open/search object
M = Move
F = Filter

Space = Preview
Enter = Open/Edit
C = Complete
P = Priority
S = Status
D = Date Menu
R = Rename
A = Archive
X = Select
Esc = Back/Clear/Close
```

V1 的目标不是让所有命令都有快捷键，而是让所有能力都进入 Command，让最高频的操作拥有稳定、可记忆、可持续扩展的快捷键。

StoneFlow 的命令系统应该让用户逐渐形成这样的使用习惯：

```txt
想创建：N
想跳转：G
想打开：O
想移动：M
想筛选：F
想操作当前任务：C / P / S / D / R / A
想找不到功能：Cmd/Ctrl + K
```

这套规则是 StoneFlow 键盘驱动体验的基础。
