> **日期：** 2026-07-14

**Goal：** 把启动恢复、最后路由、scope 内上次位置、最近浏览、前进后退的职责边界收口清楚，形成长期可维护的导航模块。

**Architecture：** TanStack Router 继续作为 URL 与浏览器历史真相源；TanStack Query 只负责业务数据加载；Tauri Store 只负责本机导航恢复持久化；Zustand 只保留非 URL 的 Shell UI 状态。新增模块只做边界收口，不引入第二套路由状态源。

**Tech Stack：** React · TanStack Router · TanStack Query · Tauri Store · Zustand（既有 Shell UI store）· Vitest

## Global Constraints

- 不引入新依赖。
- 不把导航状态塞进 TanStack Query。
- 不用 Zustand 接管 URL、当前路由、浏览器历史。
- 不把前进/后退、最近浏览下沉到 Rust runtime。
- 不扩大到 drawer 重构、route masking、navigation blocking、Shell UI 重画。
- 不保留 `tanstackCompat` 或替代兼容层。
- URL 是唯一页面位置真相源；持久化只负责启动恢复和 scope 切换辅助。
- 每个阶段都必须有独立测试或明确的静态验证。

## 2. 推荐长期形态

统一到一个模块：`src/app/navigation/`。

```txt
src/app/navigation/
  shellRoute.ts
  scope.ts
  intents.ts
  routePaths.ts
  routeMemory.ts
  routeMemoryStore.ts
  useRememberCurrentShellRoute.ts
  sessionRouteHistory.ts
```

职责边界：

- `shellRoute.ts`：把 URL 解析成 StoneFlow 的 `ShellRoute` / `AppRoute` 语义。
- `scope.ts`：从 route 推导当前 scope。
- `intents.ts`：业务导航意图转 path。
- `routePaths.ts`：底层 canonical path builder。
- `routeMemory.ts`：纯函数。负责 normalize、validate、resolve startup path、resolve scope remembered path。
- `routeMemoryStore.ts`：Tauri Store 边界。负责读写 `shell.navigation.restore`，并隐藏 store key、迁移、save 细节。
- `useRememberCurrentShellRoute.ts`：route file 使用的 hook。只负责把当前 TanStack location 写入 route memory store。
- `sessionRouteHistory.ts`：会话内最近浏览和 header back/forward 可用性。只服务 Shell Header UI，不持久化。

不做的事：

- 不做 `NavigationProvider`。
- 不做全局 `navigationStore`。
- 不做自定义 history stack 替代 TanStack Router。
- 不做 `routing` 或 `navigation-runtime` 空目录分层。
- 不做 barrel re-export；调用点直接 import 需要的文件。

## 4. 技术取舍

## 4.1 为什么不用 TanStack Query 管历史

Query 适合服务端/异步业务数据缓存，例如 root loader 读取 visible spaces。导航恢复是本机设备状态，不是远端资源，也没有 stale/cache/invalidation 语义。放进 Query 会让“页面位置”伪装成“数据请求”，长期更难理解。

## 4.2 为什么不用 Zustand 管当前路由

当前路由必须由 URL 和 TanStack Router 决定。Zustand 可以保存 sidebar 展开、active section 这类 UI 派生状态，但不能保存“当前页面在哪里”。否则会形成 URL 与 store 双真相源。

## 4.3 为什么不用 Tauri/Rust 管前进后退

前进后退是 WebView 内的 history 行为，TanStack Router 已经接管。Rust runtime 只适合处理桌面生命周期、IPC 和本地持久化，不应该理解前端 route tree。

## 4.4 为什么代码目录可以合并，但语义不能合并

它们用户表面都叫“历史”，但语义不同：

- 启动恢复：跨会话、持久化、只保存每个 scope 的最后路径。
- 最近浏览：当前会话、Header UI、展示多个访问过的页面。
- 前进后退：浏览器 history stack，由 router history 决定。

所以代码目录统一到 `src/app/navigation`，但文件职责仍拆开：`routeMemoryStore.ts` 管持久化，`sessionRouteHistory.ts` 管会话 UI，TanStack Router history 管前进后退。

## 6. 风险与回滚

| 风险 | 触发点 | 处理 |
|---|---|---|
| 启动落错页面 | `resolveStartupPath` 搬迁或 import 改错 | 保留 routeMemory 单测；根路由 loader 不改语义 |
| scope 切换不恢复 | `resolveRememberedPathForScope` import 或 store key 改错 | 不改 store path/key；先只拆文件 |
| 最近浏览与 back/forward 不一致 | session history reducer 改动 | 保留 `sessionRouteHistory.test.tsx` 的 back/forward 用例 |
| 测试 harness 缺 provider | 路由相关测试直接渲染页面 | 同补丁更新测试 wrapper，不把 provider-only 改动做一半 |
| 目录合并漏 import | 删除 `routing` / `navigation-runtime` 后仍有旧路径 | `rg "@/app/(routing|navigation-runtime)|navigation-runtime|app/routing" src` 必须无输出 |

回滚策略：每个 phase 单独提交。Phase 1/2 是文件搬迁，失败时可回滚该提交，不影响业务数据和本地 store 内容。
