# StoneFlow Quick Create 产品交互方案

> **版本**：v1.0
> **状态**：产品交互落地稿
> **适用范围**：StoneFlow 独立窗口中的 Quick Create 面板
> **核心结论**：Quick Create 是一个 **创建优先、搜索辅助、参数轻量外显** 的快速任务入口，不是重型 Command Center。

---

## 0. 一句话结论

StoneFlow Quick Create 的核心不是「万能命令中心」，而是：

```txt
快速创建任务
轻量设置参数
辅助搜索任务 / 项目
必要时进入主窗口继续编辑
```

最终交互模型：

```txt
打开 Quick Window
  ↓
输入任务标题
  ↓
第一优先级：创建任务
  ↓
下方辅助展示全局搜索结果
  ↓
Enter 创建并关闭
Cmd/Ctrl + Enter 创建并打开详情
Shift + Enter 创建并继续创建
```

整体结构：

```txt
Quick Create Panel
├─ 顶部主输入行
│  ├─ 优先级下拉
│  ├─ 任务标题输入框
│  ├─ 项目下拉
│  └─ 更多参数按钮
│
├─ 展开参数行
│  ├─ 状态下拉
│  ├─ 截止时间下拉
│  ├─ 计划时间下拉
│  ├─ 提醒时间下拉
│  └─ 空间下拉
│
├─ 创建预览行
│  ├─ 创建动作
│  ├─ 任务标题
│  └─ 参数摘要
│
├─ 结果区
│  ├─ 空输入：最近任务 / 最近项目
│  └─ 有输入：全局搜索结果
│
└─ Footer 快捷键提示
```

## 1. 产品定位

### 1.1 Quick Create 是什么

Quick Create 是 StoneFlow 的快速任务捕获窗口。

它解决的问题是：

- 用户不想打开完整主窗口，只想快速创建任务。
- 用户想在创建前快速选择项目、优先级、时间等关键参数。
- 用户想避免重复创建，顺手看到相关任务和项目。
- 用户想连续录入多个任务。
- 用户想创建后立即打开详情继续编辑。

### 1.2 Quick Create 不是什么

Quick Create 暂时不是：

- Raycast 式万能命令中心。
- AI 入口。
- Sticky 管理入口。
- 插件系统入口。
- 完整项目管理页面。
- 完整任务编辑器。
- 主窗口的替代品。

### 1.3 产品关键词

```txt
创建优先
搜索辅助
轻量参数
键盘优先
快速关闭
支持连续创建
主窗口承接复杂编辑
```

## 2. 核心设计原则

### 2.1 创建优先

Quick Create 的默认行为必须稳定：

```txt
输入内容 → Enter → 创建任务
```

用户不需要判断当前处于「创建模式」还是「搜索模式」。

创建动作永远是第一优先级。

### 2.2 搜索辅助

搜索存在的目的不是替代创建，而是辅助创建：

- 发现相似任务。
- 避免重复创建。
- 快速跳转已有任务。
- 快速跳转已有项目。

搜索结果不能抢占默认创建路径。

### 2.3 不做 Tab 模式切换

不采用：

```txt
Create Mode / Search Mode Tab 切换
```

原因：

- 多一个模式会增加认知负担。
- 用户需要先判断自己是创建还是搜索。
- 创建和搜索容易重新互相干扰。

最终采用：

```txt
上方创建
下方搜索
```

### 2.4 参数外显，但不拥挤

第一行只放最高频字段：

```txt
优先级 / 标题 / 项目 / 更多参数
```

低频但重要的字段放到展开参数行：

```txt
状态 / 截止时间 / 计划时间 / 提醒时间 / 空间
```

### 2.5 主窗口负责复杂编辑

Quick Create 不是完整编辑器。

复杂字段、描述、子任务、附件、备注等能力应由主窗口任务详情承接。

对应快捷键：

```txt
Cmd/Ctrl + Enter → 创建并打开任务详情
```

### 2.6 Space 是项目范围的过滤上下文

项目下拉不展示所有项目，只展示当前 Space 下的项目。

```txt
当前 Space → 当前 Space 下的项目列表
```

这样可以避免项目过多，也符合 StoneFlow 的顶级语境设计。

## 5. 顶部主输入行设计

### 5.1 主输入行结构

```txt
[优先级下拉] [任务标题输入框] [项目下拉] [更多参数按钮]
```

### 5.2 优先级下拉

选项：

```txt
无优先级
P0
P1
P2
P3
```

默认：

```txt
无优先级
```

展示建议：

| 值 | 展示 |
|---|---|
| 无优先级 | `—` 或 `无优先级` |
| P0 | `P0` |
| P1 | `P1` |
| P2 | `P2` |
| P3 | `P3` |

交互规则：

- 点击优先级 chip 打开下拉。
- 键盘可上下选择。
- 选择后关闭下拉并回到输入框。
- 创建预览行实时更新。

### 5.3 任务标题输入框

placeholder 建议：

```txt
输入任务…
```

或者更柔和：

```txt
写下任务…
```

输入规则：

- 为空时不显示创建行。
- 有内容时显示创建预览行。
- 输入内容触发全局搜索。
- 搜索结果展示在下方，但不影响默认创建。

### 5.4 项目下拉

默认项目：

```txt
收件箱 Inbox
```

项目下拉范围：

```txt
当前 Space 下的所有项目
```

不展示所有 Space 的全部项目。

项目下拉内容建议：

```txt
收件箱
独立事项
项目 A
项目 B
项目 C
```

说明：

- 收件箱是 Inbox。
- 独立事项是无项目。
- 普通项目属于当前 Space。

交互规则：

```txt
点击项目下拉
  ↓
展示当前 Space 下的项目
  ↓
选择项目
  ↓
更新创建预览行
  ↓
焦点回到输入框
```

### 5.5 更多参数按钮

默认折叠。

点击后展开第二行。

规则：

- 不记住上次展开状态。
- 每次打开 Quick Create 默认折叠。
- 展开后按钮变为收起状态。
- 再次点击收起。

## 6. 展开参数行设计

### 6.1 展开参数行结构

```txt
[状态 ▾] [截止时间 ▾] [计划时间 ▾] [提醒时间 ▾] [空间 ▾]
```

暂不包含：

```txt
+ 项目
```

### 6.2 状态下拉

选项：

```txt
待执行
进行中
已完成
```

默认：

```txt
待执行
```

规则：

- 状态不是主字段。
- 默认在展开区才显示。
- 创建预览行需要展示状态。
- 连续创建时保留状态。

### 6.3 截止时间下拉

字段含义：

```txt
任务必须完成的最后时间。
```

点击后选项：

```txt
今天
明天
本周
自定义
```

规则：

- 默认空。
- 不设置时创建预览行不展示。
- 设置后展示为 `截止 今天` / `截止 明天`。
- 连续创建时保留。

### 6.4 计划时间下拉

字段含义：

```txt
计划什么时候处理这个任务。
```

点击后选项：

```txt
今天
明天
本周
自定义
```

规则：

- 默认空。
- 不设置时创建预览行不展示。
- 设置后展示为 `计划 今天` / `计划 明天`。
- 连续创建时保留。

### 6.5 提醒时间下拉

字段含义：

```txt
什么时候提醒用户处理或查看这个任务。
```

点击后选项：

```txt
今天
明天
本周
自定义
```

规则：

- 默认空。
- 不设置时创建预览行不展示。
- 设置后展示为 `提醒 今天` / `提醒 明天`。
- 连续创建时保留。

### 6.6 空间下拉

选项：

```txt
用户已有 Spaces
```

规则：

```txt
切换 Space
  ↓
项目下拉列表刷新为新 Space 下的项目
  ↓
当前项目重置为收件箱 Inbox
```

原因：

- 项目属于 Space。
- 跨 Space 保留项目会造成语境不一致。
- 收件箱是最安全的默认项目。

## 7. Space / Project 规则

### 7.1 概念定义

| 概念 | 定义 |
|---|---|
| Space | StoneFlow 顶级语境 |
| Project | Space 下的项目 |
| Inbox / 收件箱 | 默认任务入口，用于未整理任务 |
| 独立事项 | 无项目任务，不属于具体项目 |

### 7.2 默认项目

默认项目固定为：

```txt
收件箱 Inbox
```

打开 Quick Create 时：

```txt
默认 Space = 当前主页面 Space
默认 Project = 收件箱 Inbox
```

### 7.3 项目下拉范围

项目下拉只展示：

```txt
当前 Space 下的项目
```

包含：

- 收件箱 Inbox。
- 独立事项。
- 当前 Space 下的普通项目。

不包含：

- 其他 Space 的项目。
- 已归档项目，默认不展示。
- Trash 中的项目。

### 7.4 切换 Space 后项目处理

规则：

```txt
用户切换 Space
  ↓
项目列表刷新
  ↓
当前项目重置为该 Space 的收件箱 Inbox
```

不保留旧项目。

原因：

- 项目不能跨 Space。
- 强行保留旧项目会产生隐性错误。
- 收件箱是最安全 fallback。

## 8. 创建预览行设计

### 8.1 定位

创建预览行是主操作入口。

它回答两个问题：

```txt
按 Enter 会创建什么？
这个任务会带哪些参数？
```

### 8.2 出现规则

```txt
输入框为空 → 不显示创建预览行
输入框有内容 → 显示创建预览行
```

### 8.3 默认焦点

输入框有内容时：

```txt
创建预览行默认 focused
```

这样保证：

```txt
输入 → Enter → 创建
```

### 8.4 创建行结构

推荐：

```txt
＋ 创建任务：整理 Quick Create 交互方案
  无优先级 · 待执行 · 产品研发 / 收件箱 · 截止 明天 · 计划 今天 · 提醒 今天
```

更紧凑版本：

```txt
＋ 整理 Quick Create 交互方案
  创建任务 · 无优先级 · 待执行 · 产品研发 / 收件箱 · 截止 明天
```

### 8.5 字段展示规则

| 字段 | 是否展示 | 说明 |
|---|---:|---|
| 标题 | 是 | 创建核心 |
| 优先级 | 是 | 默认展示无优先级 |
| 状态 | 是 | 默认待执行 |
| Space / Project | 是 | 例如 `产品研发 / 收件箱` |
| 截止时间 | 有值展示 | 无值不展示 |
| 计划时间 | 有值展示 | 无值不展示 |
| 提醒时间 | 有值展示 | 无值不展示 |

### 8.6 创建行右侧提示

默认：

```txt
↵ 创建
```

如果当前 focus 在搜索结果上，footer 和行内提示应变成：

```txt
↵ 打开
```

## 9. 结果区设计

### 9.1 空输入状态

当输入框为空时展示：

```txt
最近任务
最近项目
```

数量：

```txt
最近任务 3 条
最近项目 3 条
```

最近任务排序建议：

```txt
最近打开 / 最近更新 / 最近创建
```

最近项目排序建议：

```txt
最近打开 / 当前 Space 优先 / 活跃项目优先
```

### 9.2 有输入状态

当输入框有内容时展示：

```txt
搜索结果
├─ 任务
└─ 项目
```

数量：

```txt
任务 3 条
项目 3 条
```

### 9.3 搜索范围

已确认：

```txt
全局搜索
```

含义：

- 搜索所有 Space 下的任务。
- 搜索所有 Space 下的项目。
- 结果项需要显示所属 Space，避免语境混淆。

示例：

```txt
任务：完善 Quick Window 键盘导航
产品研发 / StoneFlow 开发 · P1 · 今天

项目：设计系统整理
产品研发 · 12 个任务
```

### 9.4 搜索结果行为

任务结果：

```txt
Enter / 点击 → 打开任务详情
```

项目结果：

```txt
Enter / 点击 → 打开项目页面
```

搜索结果不影响默认创建，除非用户显式选中搜索结果。

### 9.5 焦点规则

默认：

```txt
输入内容后 → 创建行 focused
```

按方向键：

```txt
↓ → 进入第一个搜索结果
↑ → 返回创建行
```

Enter 行为：

```txt
创建行 focused → 创建任务
任务结果 focused → 打开任务详情
项目结果 focused → 打开项目页面
```

## 10. 快捷键交互

### 10.1 基础快捷键

| 快捷键 | 行为 |
|---|---|
| Enter | 创建并关闭 |
| Cmd/Ctrl + Enter | 创建并打开任务详情 |
| Shift + Enter | 创建并继续创建 |
| Esc | 第一下清空输入，第二下关闭 |
| ↑ / ↓ | 在创建行和结果项之间移动 |
| Click | 点击对应按钮 / 结果项 |

### 10.2 参数快捷键

P0 不做参数快捷符号，统一使用显式 chip / popover 交互。

P1 以后可增强：

| 快捷键 | 行为 |
|---|---|
| `!` | 打开优先级选择 |
| `#` | 打开项目选择 |
| `$` | 打开空间选择 |

P0 暂不支持日期快捷符号。

原因：

- `v6` 原型已经切到显式参数交互，不再把符号触发作为主入口。
- 日期字段有三个：截止时间、计划时间、提醒时间。
- 过早设计符号容易混乱。
- 日期先通过展开参数行操作。

### 10.3 Esc 行为

已确认：

```txt
输入框有内容
  ↓
Esc 第一下：清空输入
  ↓
Esc 第二下：关闭窗口
```

如果有弹层打开：

```txt
Esc 第一下：关闭弹层
Esc 第二下：清空输入或关闭窗口
```

优先级：

```txt
关闭弹层 > 清空输入 > 关闭窗口
```

### 10.4 Footer 快捷键提示

默认：

```txt
↑↓ 选择   ↵ 创建   ⇧↵ 连续创建   ⌘↵ 创建并打开   Esc 清空/关闭
```

如果当前 focus 在搜索结果：

```txt
↑↓ 选择   ↵ 打开   Esc 清空/关闭
```

如果打开参数弹层：

```txt
↑↓ 选择   ↵ 确认   Esc 关闭弹层
```

## 11. 创建后行为

### 11.1 Enter：创建并关闭

流程：

```txt
输入任务标题
  ↓
Enter
  ↓
Helper 发送 quick.create
  ↓
Core 创建任务
  ↓
返回 created task
  ↓
Quick Create 显示短暂成功反馈
  ↓
窗口自动关闭
```

成功反馈建议：

```txt
✓ 已创建：整理 Quick Create 方案
```

反馈时间建议：

```txt
200ms - 400ms
```

### 11.2 Cmd/Ctrl + Enter：创建并打开任务详情

流程：

```txt
输入任务标题
  ↓
Cmd/Ctrl + Enter
  ↓
Core 创建任务
  ↓
Quick Window 关闭
  ↓
Main Window 显示
  ↓
打开刚创建任务的详情 Drawer
```

适合场景：

- 用户需要继续补描述。
- 用户需要添加子任务。
- 用户需要修改更多字段。
- 用户需要立即开始处理。

### 11.3 Shift + Enter：创建并继续创建

流程：

```txt
输入任务标题
  ↓
Shift + Enter
  ↓
Core 创建任务
  ↓
输入框清空
  ↓
参数全部保留
  ↓
继续输入下一条
```

保留字段：

- 优先级。
- 状态。
- Space。
- Project。
- 截止时间。
- 计划时间。
- 提醒时间。

清空字段：

- 标题。
- 当前搜索结果。
- 创建行。

### 11.4 连续创建计数

已确认：连续创建时显示创建数量。

建议展示：

```txt
已创建 1 条，继续输入下一条
已创建 2 条，继续输入下一条
已创建 3 条，继续输入下一条
```

展示位置：

- 创建预览行位置。
- 或输入框下方轻提示。
- 或 footer 左侧状态提示。

推荐：

```txt
输入框下方 / 创建行位置显示轻提示
```

示例：

```txt
✓ 已创建 3 条，继续输入下一条
```

关闭窗口后，计数重置。

### 11.5 撤销设计，P0 暂不做

已确认：支持撤销设计，但先不做。

未来设计方向：

```txt
创建成功后短暂显示：已创建 · 撤销
```

可能规则：

- Enter 创建并关闭时，是否还能撤销需要谨慎。
- 连续创建时更适合显示撤销。
- 撤销应通过 Core 执行，不在 Helper 本地回滚。

P0 不实现撤销，只预留 UI 和协议空间。

```txt

## 17. UI 设计建议

### 17.1 总体风格

方向：

```txt
浅色
克制
Linear 风格
轻量浮层
高信息清晰度
不过度拟物
不过度命令中心化
```

### 17.2 面板尺寸建议

| 项 | 建议 |
|---|---|
| 宽度 | 700 - 760px |
| 折叠态高度 | 260 - 360px，根据结果数量变化 |
| 展开态高度 | 320 - 420px |
| 圆角 | 12 - 16px |
| 阴影 | 中轻量浮层阴影 |
| 位置 | 屏幕上方约 18% - 24% |

### 17.3 第一行视觉层级

第一行最高权重：

```txt
优先级 chip < 输入框 > 项目 chip > 更多按钮
```

输入框是视觉中心。

### 17.4 展开参数行视觉层级

第二行应该更轻：

```txt
状态 / 时间 / 空间 都是 secondary chips
```

不要和第一行同等重量。

### 17.5 创建行视觉层级

创建行应该是主 CTA。

建议：

- 背景轻微强调。
- 左侧 `+` icon。
- 标题较清楚。
- 参数摘要弱一些。
- 右侧显示 `↵ 创建`。

### 17.6 结果区视觉层级

搜索结果比创建行弱。

建议：

- 分组标题用中文。
- 行高比创建行略小。
- 任务和项目 icon 区分。
- 结果项 hover / focus 清晰。

### 17.7 Footer

Footer 要根据状态动态变化。

默认：

```txt
↑↓ 选择   ↵ 创建   ⇧↵ 连续创建   ⌘↵ 创建并打开   Esc 清空/关闭
```

弹层中：

```txt
↑↓ 选择   ↵ 确认   Esc 关闭
```

## 18. Core 接口依赖

### 18.1 初始化数据

Quick Window 打开时需要：

```txt
quick.getInitialState
```

返回：

```ts
type QuickInitialState = {
  currentSpaceId: string;
  defaultProjectId: string; // Inbox
  spaces: SpaceSummary[];
  projectsInCurrentSpace: ProjectSummary[];
  recentTasks: TaskSummary[];
  recentProjects: ProjectSummary[];
};
```

### 18.2 获取 Space 下项目

```txt
project.listBySpace
```

请求：

```ts
type ListProjectsBySpaceRequest = {
  spaceId: string;
};
```

返回：

```ts
type ListProjectsBySpaceResponse = {
  projects: ProjectSummary[];
  inboxProject: ProjectSummary;
  noProjectOption: ProjectSummary;
};
```

### 18.3 全局搜索

```txt
quick.search
```

请求：

```ts
type QuickSearchRequest = {
  query: string;
  limitPerType: number;
  include: Array<"task" | "project">;
};
```

返回：

```ts
type QuickSearchResponse = {
  tasks: TaskSummary[];
  projects: ProjectSummary[];
};
```

### 18.4 创建任务

```txt
quick.create
```

请求：

```ts
type QuickCreateTaskRequest = {
  idempotencyKey: string;
  title: string;
  priority: "none" | "P0" | "P1" | "P2" | "P3";
  status: "todo" | "doing" | "done";
  spaceId: string;
  placement:
    | { kind: "inbox" }
    | { kind: "noProject" }
    | { kind: "project"; projectId: string };
  dueTime?: TimeInput;
  plannedTime?: TimeInput;
  reminderTime?: TimeInput;
  source: "quick-create";
};
```

返回：

```ts
type QuickCreateTaskResponse = {
  task: TaskSummary;
};
```

### 18.5 创建并打开详情

可以由 Helper 顺序调用：

```txt
quick.create
  ↓
app.openTaskDetail
```

或者 Core 提供聚合接口：

```txt
quick.createAndOpen
```

P0 推荐使用聚合接口，减少跨进程往返和中间状态。

## 22. 最终方案摘要

StoneFlow Quick Create 最终采用：

```txt
创建优先
搜索辅助
无 Tab 模式切换
顶部主输入行极简
展开参数行承载低频字段
创建预览行作为主 CTA
全局搜索作为辅助区
Enter 创建并关闭
Cmd/Ctrl + Enter 创建并打开详情
Shift + Enter 连续创建
Esc 第一下清空，第二下关闭
```

最重要的设计边界：

```txt
