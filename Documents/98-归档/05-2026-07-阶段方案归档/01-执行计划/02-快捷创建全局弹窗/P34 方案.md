# StoneFlow Quick Create P3-P4 实施计划

## Summary
P3 这轮不再扩协议，而是把现有 Quick v2 主链收口成“服务边界清晰、前端可直接消费”的稳定实现；P4 直接重建 Quick Create 前端，按 `v6` 原型的结构和交互语义落地，但视觉样式映射到项目现有 Token，不追求逐像素复制。

已锁定的关键决策：
- 搜索结果不能抢默认创建路径。
- 输入非空时默认焦点始终在“创建预览行”。
- 三个时间字段本轮只做“日期级”，使用 `yyyy-MM-dd`。
- P4 直接迁移到 `features/quick-create`，不再把新实现继续放在 `quick-capture` 语义下。

## Implementation Changes
### P3 服务层收口
- 保持 `QuickCreateService` 只负责业务数据编排，不把 Tauri `AppHandle`、窗口恢复、事件发射塞进 service。
- `QuickCreateService` 固定提供：
  - `getInitialState`
  - `listProjectsBySpace`
  - `search`
  - `create`
  - `resolveOpenTarget` 或等价“取 task/project 打开详情所需上下文”的能力
- `helper_runtime` 继续负责：
  - `quick.createAndOpen`
  - `quick.openTarget`
  - 恢复主窗口
  - 发出 `stoneflow://command/open`
- `search` 固定裁剪为 task 3 条、project 3 条，且默认不让结果影响创建主路径。
- `getInitialState` 固定返回：
  - 当前 scope
  - 默认 space
  - 默认 placement
  - 所有可见 spaces
  - 当前 space 的项目选项
  - recent tasks / recent projects
- `listProjectsBySpace` 固定返回 `inbox / noProject / projects` 三段，不让前端自己拼伪选项。
- P3 顺手补 service 测试，不再改 wire shape，当前 `quick.openTarget` 保留为正式接口。

### P4 前端重建
- 新建 `features/quick-create`，至少拆成：
  - `ui/QuickCreatePage`
  - `ui/QuickCreateRoot`
  - `ui/QuickCreateInputRow`
  - `ui/QuickCreateAdvancedRow`
  - `ui/QuickCreateCreateRow`
  - `ui/QuickCreateResults`
  - `ui/QuickCreateFooter`
  - `model/QuickCreateProvider`
  - `model/quickCreateReducer` 或同级 action reducer
  - `api/quickCreate.ts`
- 状态采用“窗口内局部 Provider + reducer/action”方案，不用 app 级全局 zustand。
- Provider 统一管理：
  - 标题
  - priority
  - status
  - spaceId
  - placement
  - due/scheduled/reminder
  - advanced row open
  - active popover
  - results / recents
  - focus target
  - submit state
  - continuous create count
- API 层只暴露前端语义方法：
  - `getInitialState`
  - `listProjectsBySpace`
  - `search`
  - `create`
  - `createAndOpen`
  - `openTarget`
  不在页面里直接散落 `invoke(...)` 字符串。
- 路由和文件命名统一切到 `quick-create`；旧 `quick-capture` 页面文件、pattern 命名、route import 在本轮一起迁走，不留新代码继续引用旧目录。

### 交互与组件规则
- 第一行固定：优先级 chip、标题输入、项目 chip、更多参数按钮。
- 第二行折叠区固定：状态、截止时间、计划时间、提醒时间、Space。
- 输入为空：
  - 不显示创建预览行
  - 结果区展示 recent tasks / recent projects
  - Footer 显示默认快捷键提示
- 输入非空：
  - 显示创建预览行
  - 同时触发全局搜索
  - 默认焦点在创建预览行
  - `Enter` 创建并关闭
  - `Cmd/Ctrl+Enter` 创建并打开
  - `Shift+Enter` 创建并继续创建
- 搜索结果只有在用户显式用方向键移入后才接管 `Enter`，此时：
  - task 结果 `Enter` 打开任务详情
  - project 结果 `Enter` 打开项目页
  - `ArrowUp` 可回到创建预览行
- `Esc` 优先级固定：
  - 先关 popover
  - 再清空输入
  - 再关闭窗口
- Space 切换后，项目重置为该 Space 的 Inbox。
- 项目 popover 只显示当前 Space 的项目选项，并带局部搜索框。
- 时间字段用现有 `Popover + Calendar/DatePicker` 体系，但交互表现做成 chip；落库值统一是 `yyyy-MM-dd`。
- 连续创建成功后：
  - 标题清空
  - priority/status/space/placement/三个日期全部保留
  - 显示“已连续创建 N 条”提示
  - 焦点回到标题输入
- 视觉实现以 `v6` 的布局层级为准：
  - 创建预览行为主 CTA
  - 搜索结果视觉权重低于创建行
  - Footer 提示动态随焦点变化
  - 样式映射现有 StoneFlow Token、基础 Button/Popover/Kbd，不新引设计依赖。

## Public Interfaces / Types
- 前端新增 `features/quick-create/api/quickCreate.ts`，作为 helper Quick v2 的唯一调用入口。
- 前端 Quick Create 本地状态类型新增：
  - `QuickCreateDraft`
  - `QuickCreateFocusTarget`
  - `QuickCreateSubmitAction`
  - `QuickCreateResultItem`
- `commandOpen` 事件协议保持现状，但 P4 需要把任务打开路径完全按 `placement` 处理，不再由旧页面逻辑兜底。
- 不新增新的 Rust 协议方法；继续使用现有 Quick v2 + `quick.openTarget`。

## Test Plan
- Rust：
  - `getInitialState` 在 `all` / `space` scope 下返回正确默认值。
  - `listProjectsBySpace` 返回 inbox、noProject 和当前 Space projects。
  - `search` 裁剪为 3+3，且不把 completed 结果混进默认展示。
  - `create` 正确透传 `placement` 与三个日期字段。
  - `open target` / `createAndOpen` 能返回主窗口导航所需上下文。
- Frontend：
  - 初始打开默认聚焦标题输入。
  - 空输入显示 recent 区，不显示创建行。
  - 非空输入显示创建行且默认 focused。
  - 有搜索结果时 `Enter` 仍创建；`ArrowDown` 进入结果后 `Enter` 才打开。
  - `Shift+Enter` 会保留参数、清空标题并累计计数。
  - `Cmd/Ctrl+Enter` 调 `createAndOpen`。
  - `Esc` 依次关闭弹层、清空输入、关闭窗口。
  - Space 切换后项目重置为 Inbox。
  - 项目 popover 只显示当前 Space 的项目。
  - Footer 文案随焦点从“↵ 创建”切到“↵ 打开”。
- 回归：
  - `commandOpen` 事件测试继续覆盖 task/project/inbox/no-project 路径。
  - 路由迁移后 `#/quick-create` 正常渲染，旧 `quick-capture` 不再作为长期入口。

## Assumptions
- 本轮只做 P3-P4，不把 P5 的全部 polish 一次塞进来；但 `Esc`、三种创建动作、焦点优先级这些 P4 必要交互会一起做。
- 时间字段本轮只支持日期级，不支持时分，也不做自然语言解析。
- 不新增依赖，复用现有 `Popover`、`DatePicker/Calendar`、`zustand` 之外的基础设施。
- 旧 `quick-capture` 目录和命名在本轮前端重建时一并迁走，不继续留作新实现宿主。
