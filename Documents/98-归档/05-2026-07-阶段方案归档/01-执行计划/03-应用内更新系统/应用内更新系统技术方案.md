# StoneFlow 应用内更新系统技术方案

> 版本：v1（历史底稿）
> 作用：定义应用内更新模块的分发、签名、分层与发布流程
> 适用范围：StoneFlow Desktop (Tauri v2)
> 最后更新：2026-07-01
>
> ⚠️ **产品行为与模式以 `04-更新系统体验完善` 为准。**  
> 本文中「四档 / AutoInstall / 固定 6h」等描述已过时，请勿再按此实现。

---

## 1. 目标与约束

### 1.1 目标

- 实现应用内自动更新能力，用户无需手动下载安装包
- 支持 **三档**更新模式：手动检查、仅提醒、自动下载（**无**自动安装档）
- 支持双更新渠道：Stable（正式版）和 Beta（测试版）
- 支持版本跳过（用户可以跳过不想安装的版本）
- 更新过程对用户透明，不打断正常使用
- 严格遵循项目现有整洁架构（domain/usecase/storage/runtime）

### 1.2 约束

- 分发渠道：用户自有 CDN + 对象存储 + 静态 JSON（方案 D）
- 更新签名：使用 Tauri 官方签名机制（ed25519），不可关闭
- 更新检查：启动延迟检查 + **可配置间隔**（默认 6 小时；手动检查不受节流限制）
- 不强制重启：所有模式下，下载完成后都由用户决定何时重启
- Sidecar（stoneflow-sync-worker）随主程序 bundle 一起更新，不需要独立更新逻辑

### 1.3 非目标

- 不做差分更新（delta update / patch），Tauri updater v2 不原生支持，且应用体积较小（< 60MB），全量下载成本可接受
- 不做强制更新（版本低于某值无法使用），当前阶段不需要
- 不做灰度发布/按比例推送，静态 JSON 方案不支持，后续需要时可升级为动态服务端
- 移动端（iOS/Android）更新不在本方案范围内

## 2. 分发方案选型

### 2.1 选型对比

| 维度 | GitHub Releases (方案 A) | CDN + 对象存储 (方案 D) |
|---|---|---|
| 成本 | 公共仓库免费 | Cloudflare R2 免费额度内零成本 |
| 国内访问 | 慢，可能超时 | 可控，可接国内 CDN |
| 配置成本 | 零（tauri-action 全自动） | 需要写 CI 上传脚本 |
| 回滚能力 | 需发新版本 | 覆盖 JSON 即可回滚 |
| 多渠道支持 | 需绕 tag 或多 repo | 直接多 JSON 文件 |
| 下载速率限制 | GitHub API 有速率限制 | 无 |
| Release Notes | 自动生成 | 需自己维护 |

### 2.2 最终选择

**方案 D：CDN + 对象存储 + 静态 JSON**

原因：用户已有域名、CDN、对象存储，零成本获得更快更稳的下载速度、多渠道支持和紧急回滚能力。

### 2.3 Endpoint 设计

```
Stable: https://cdn.yourdomain.com/updates/stable/latest.json
Beta:   https://cdn.yourdomain.com/updates/beta/latest.json
```

安装包路径：
```
# Updater 下载的格式（Tauri 自动生成）
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}.app.tar.gz       # macOS
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}.app.tar.gz.sig   # macOS 签名
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}-setup.exe        # Windows NSIS
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}-setup.exe.sig    # Windows 签名
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}.AppImage         # Linux
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}.AppImage.sig     # Linux 签名

# 用户手动下载的安装包（可选上传）
https://cdn.yourdomain.com/updates/stable/StoneFlow_{version}_{arch}.dmg              # macOS DMG
```

## 4. 领域模型（domain）

`domain/src/update.rs` 纯值对象和枚举，无任何 I/O 依赖：

```rust
/// 更新检查模式（用户设置）
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum UpdateCheckMode {
    Manual,       // 不自动检查，仅手动触发
    NotifyOnly,   // 启动+定时检查，弹窗提示，用户决定下载
    AutoDownload, // 静默后台下载，完成后提示重启（无 AutoInstall）
}

impl Default for UpdateCheckMode {
    fn default() -> Self { Self::NotifyOnly }
}

/// 更新渠道
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum UpdateChannel {
    Stable,
    Beta,
}

impl Default for UpdateChannel {
    fn default() -> Self { Self::Stable }
}

/// 更新状态（传输到前端）
#[derive(Debug, Clone, Serialize)]
#[serde(tag = "status", rename_all = "camelCase")]
pub enum UpdateStatus {
    Idle,
    Checking,
    UpdateAvailable { version: String, body: Option<String>, pub_date: Option<String> },
    UpToDate,
    Downloading { downloaded: u64, total: Option<u64> },
    Downloaded { version: String },
    Error { message: String },
}

/// 更新相关设置（持久化）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct UpdateSettings {
    pub check_mode: UpdateCheckMode,
    pub channel: UpdateChannel,
    pub skipped_versions: Vec<String>,
    pub last_checked_at: Option<i64>, // unix timestamp 秒
}
```

**领域规则：**
- 版本比较使用 semver
- Beta 渠道通过 semver 预发布标签判断（如 `0.2.0-beta.1`）
- `last_checked_at` 用于 6 小时节流
- `skipped_versions` 中记录的版本在非手动检查时不提示

## 5. Usecase 层（Port + 编排）

`usecase/src/update.rs` 定义 port（trait）和业务编排，不依赖 Tauri。

### 5.1 Port 定义

```rust
/// 更新检查返回的信息
#[derive(Debug, Clone)]
pub struct UpdateInfo {
    pub version: String,
    pub body: Option<String>,
    pub pub_date: Option<String>,
}

/// 更新操作 Port —— 由 runtime 层实现
pub trait UpdatePort: Send + Sync {
    async fn check(&self, channel: UpdateChannel) -> Result<Option<UpdateInfo>, UsecaseError>;
    async fn download_and_install(
        &self,
        on_progress: impl Fn(u64, Option<u64>) + Send + 'static,
    ) -> Result<(), UsecaseError>;
    async fn restart(&self) -> Result<(), UsecaseError>;
}

/// 设置持久化 Port —— 由 storage 层实现
pub trait UpdateSettingsPort: Send + Sync {
    async fn load(&self) -> Result<UpdateSettings, UsecaseError>;
    async fn save(&self, settings: &UpdateSettings) -> Result<(), UsecaseError>;
}
```

### 5.2 UpdateService

```rust
pub struct UpdateService<P: UpdatePort, S: UpdateSettingsPort> {
    port: P,
    settings_port: S,
}
```

核心方法：

| 方法 | 职责 |
|---|---|
| `check_update(manual: bool)` | 核心检查逻辑：节流检查、版本比对、跳过版本过滤、更新 last_checked_at |
| `download_and_install(on_progress)` | 委托给 port 执行下载，推送进度 |
| `restart()` | 委托给 port 重启应用 |
| `set_check_mode(mode)` | 更新检查模式设置 |
| `set_channel(channel)` | 更新渠道设置 |
| `skip_version(version)` | 将版本加入跳过列表 |
| `get_settings()` | 读取当前设置 |

**check_update 编排逻辑：**
1. 加载设置
2. 非手动模式下：如果 mode == Manual，返回 None；如果距上次检查 < 6 小时，返回 None
3. 调用 port.check(channel) 向远端查询
4. 更新 last_checked_at
5. 非手动模式下：如果版本在 skipped_versions 中，返回 None
6. 返回 UpdateInfo 或 None

## 7. Runtime 层（Adapter + Commands + 调度）

### 7.1 TauriUpdateAdapter

`runtime/src/services/update.rs` 封装 `tauri-plugin-updater`：

- 根据 channel 动态设置 endpoint URL（运行时覆盖 tauri.conf.json 的静态配置）
- `check()`：构建 updater → 设置渠道 endpoint → 调用 check → 映射为 UpdateInfo
- `download_and_install()`：获取 update → 调用 download_and_install → 通过回调推送进度
- `restart()`：调用 `app.restart()`

**渠道 endpoint 映射：**
```rust
fn endpoint_for_channel(channel: UpdateChannel) -> &'static str {
    match channel {
        UpdateChannel::Stable => "https://cdn.yourdomain.com/updates/stable/latest.json",
        UpdateChannel::Beta => "https://cdn.yourdomain.com/updates/beta/latest.json",
    }
}
```

### 7.2 Tauri Commands

`runtime/src/commands/update.rs` 暴露以下 IPC commands：

| Command | 参数 | 返回 | 说明 |
|---|---|---|---|
| `check_update` | `manual: bool` | `Option<UpdateInfo>` | 检查更新 |
| `download_and_install` | `onEvent: Channel<UpdateEvent>` | `()` | 下载并安装（通过 channel 推送进度） |
| `restart_and_install` | 无 | `()` | 重启应用完成安装 |
| `skip_version` | `version: String` | `()` | 跳过指定版本 |
| `set_check_mode` | `mode: UpdateCheckMode` | `()` | 设置检查模式 |
| `set_channel` | `channel: UpdateChannel` | `()` | 设置更新渠道 |
| `get_update_settings` | 无 | `UpdateSettings` | 获取当前设置 |

**UpdateEvent（通过 Channel 推送到前端）：**
```rust
#[derive(Clone, Serialize)]
#[serde(tag = "event", content = "data", rename_all = "camelCase")]
pub enum UpdateEvent {
    StatusChanged { status: UpdateStatus },
}
```

**全局事件（通过 app.emit 广播）：**

| 事件名 | Payload | 触发时机 |
|---|---|---|
| `update-available` | `UpdateInfo` | 自动检查发现新版本时 |
| `update-downloaded` | `{ version: String }` | 自动下载完成时 |
| `update-error` | `{ message: String }` | 检查/下载出错时 |

### 7.3 自动检查调度

在 `bootstrap.rs` 的 app setup 中启动后台任务：

```rust
tauri::async_runtime::spawn(async move {
    // 启动时延迟 3 秒检查（避免影响启动速度）
    tokio::time::sleep(Duration::from_secs(3)).await;
    loop {
        check_and_notify(app_handle.clone()).await;
        tokio::time::sleep(Duration::from_secs(6 * 60 * 60)).await;
    }
});
```

`check_and_notify` 逻辑：
1. 调用 `update_service.check_update(manual=false)`
2. 如果有更新：
   - NotifyOnly 模式：emit `update-available`
   - AutoDownload/AutoInstall 模式：自动开始下载，下载过程中 emit 进度事件，下载完成后 emit `update-downloaded`
3. 如果出错：emit `update-error`（静默，不弹窗打扰）

### 7.4 Composition 组装

在 `composition.rs` 中：
1. 创建 `TauriUpdateAdapter`
2. 创建 `StoreUpdateSettingsAdapter`
3. 创建 `UpdateService`
4. 通过 `.manage()` 注册为 Tauri State
5. 在 `generate_handler![]` 中注册所有 update commands

## 8. 前端设计

### 8.1 IPC Facade（`api/index.ts`）

封装所有 invoke 调用，提供类型安全的 API：

```typescript
checkUpdate(manual?: boolean): Promise<UpdateInfo | null>
downloadAndInstall(onEvent: (event: UpdateEvent) => void): Promise<void>
restartAndInstall(): Promise<void>
skipVersion(version: string): Promise<void>
setCheckMode(mode: UpdateCheckMode): Promise<void>
setChannel(channel: UpdateChannel): Promise<void>
getUpdateSettings(): Promise<UpdateSettings>
onUpdateAvailable(cb: (info: UpdateInfo) => void): UnlistenFn
onUpdateDownloaded(cb: (payload: { version: string }) => void): UnlistenFn
onUpdateError(cb: (payload: { message: string }) => void): UnlistenFn
```

### 8.2 状态管理（`useUpdateStore.ts`）

使用 zustand 管理全局更新状态：

```typescript
interface UpdateState {
  status: UpdateStatus;
  version?: string;
  body?: string;
  downloaded: number;
  total?: number;
  settings: UpdateSettings;
  dialogOpen: boolean;

  check: (manual?: boolean) => Promise<void>;
  download: () => Promise<void>;
  installAndRestart: () => Promise<void>;
  skip: () => Promise<void>;
  setMode: (mode: UpdateCheckMode) => Promise<void>;
  setChannel: (channel: UpdateChannel) => Promise<void>;
  dismiss: () => void;
}
```

### 8.3 UpdateProvider

在 `AppProviders.tsx` 中挂载：
1. 初始化时加载设置
2. 监听 `update-available` 事件：根据当前模式决定弹窗或自动下载
3. 监听 `update-downloaded` 事件：弹窗提示重启
4. 监听 `update-error` 事件：静默记录，不打扰用户

### 8.4 更新弹窗（UpdateDialog）

使用项目现有的 Radix UI Dialog 组件。支持三态：

**状态 1：发现新版本（NotifyOnly 模式）**
- 图标：蓝色下载图标
- 标题：`发现新版本 v{version}`
- 副标题：`发布于 {date} · 大小 {size}`
- 内容：Release notes（可滚动区域）
- 按钮：`跳过此版本`（ghost，左对齐）/ `稍后提醒`（secondary）/ `立即下载`（primary）

**状态 2：下载中**
- 图标：蓝色加载图标
- 标题：`正在下载 v{version}`
- 内容：进度条 + `{downloaded} / {total} ({percent}%)`（tabular-nums）
- 按钮：`后台下载`（ghost）/ 取消按钮禁用

**状态 3：下载完成，等待重启**
- 图标：绿色对勾
- 标题：`更新已准备就绪`
- 副标题：`v{version} 已下载完成，重启 StoneFlow 以完成更新`
- 提示横幅：绿色背景，"重启后将自动安装，更新不会影响您的数据"
- 按钮：`稍后重启`（ghost）/ `立即重启`（success，绿色）

### 8.5 弹窗交互细节

- 弹窗使用 Radix Dialog，支持 ESC 关闭（等同于"稍后提醒"）
- 进度条使用 `tabular-nums` 防止数字跳动
- 进度数字使用等宽字体
- 按钮点击有 `scale(0.96)` 反馈
- 弹窗出现使用 stagger 动画：图标 → 标题 → 内容 → 按钮
- "后台下载"按钮关闭弹窗但下载继续，下载完成后通过 toast 或再次弹窗提示

### 8.6 四种模式行为定义

| 模式 | 自动检查 | 发现更新时 | 下载 | 下载完成后 |
|---|---|---|---|---|
| Manual | 否 | 不弹窗 | 用户在设置页手动触发 | 弹窗提示重启 |
| NotifyOnly（默认） | 启动+6h | 弹窗提示 | 用户点击"立即下载" | 弹窗提示重启 |
| AutoDownload | 启动+6h | 后台自动下载 | 自动，弹窗最小化显示进度 | 弹窗提示重启 |
| AutoInstall | 启动+6h | 后台自动下载 | 自动，更显著的完成弹窗 | 弹窗提示重启 |

关键区别：所有模式下载完成后都必须用户确认重启，不强制重启。AutoInstall 和 AutoDownload 的区别在于弹窗提示的显著程度。

### 8.7 设置页集成（UpdateSettings）

在 `features/settings/SettingsPage.tsx` 中增加"更新"分区：

- **更新检查模式**：4 个 radio 按钮（手动/提醒/自动下载/自动安装），使用 segmented control 样式
- **更新渠道**：2 个 tab（Stable/Beta），Beta 旁标注"包含实验性功能"
- **当前版本**：显示版本号（mono 字体）
- **检查更新**：手动检查按钮，显示检查状态（检查中/已是最新/有新版本）
- **上次检查**：显示上次检查时间的友好格式

## 9. 签名与安全

### 9.1 密钥生成

```bash
cargo tauri signer generate -w ~/.tauri/stoneflow.key
```

- 私钥：`~/.tauri/stoneflow.key`（本地保存，不提交到仓库）
- 公钥：输出到控制台，填入 `tauri.conf.json` 的 `plugins.updater.pubkey`

### 9.2 密钥管理

- 私钥存放在 GitHub Secrets 中：`TAURI_SIGNING_PRIVATE_KEY`
- 如果私钥有密码，同时设置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
- 本地构建也需要设置环境变量（不设置则不生成签名产物，updater 不工作）
- **私钥丢失 = 无法发布更新**，必须安全备份

### 9.3 安全策略

- 生产环境 endpoint 必须是 HTTPS（Tauri 强制）
- 所有更新包必须经过 ed25519 签名验证，未签名或签名不匹配的包会被拒绝
- `dangerousInsecureTransportProtocol` 不开启
- 公钥硬编码在 app 内，不可被远程替换

## 10. CI/CD 发布流程

### 10.1 触发条件

- 推送 `v*` tag 时触发发布流程（如 `v0.2.0`）
- tag 必须以 `v` 开头，后跟 semver 版本号
- Beta 版本使用 `v0.2.0-beta.1` 格式

### 10.2 Workflow 步骤

```yaml
name: publish
on:
  push:
    tags:
      - 'v*'

jobs:
  publish-tauri:
    strategy:
      fail-fast: false
      matrix:
        include:
          - platform: macos-latest
            args: '--target aarch64-apple-darwin'
          - platform: macos-latest
            args: '--target x86_64-apple-darwin'
          - platform: ubuntu-22.04
            args: ''
          - platform: windows-latest
            args: ''
    runs-on: ${{ matrix.platform }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: lts/* }
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.platform == 'macos-latest' && 'aarch64-apple-darwin,x86_64-apple-darwin' || '' }}

      - name: install dependencies (ubuntu only)
        if: matrix.platform == 'ubuntu-22.04'
        run: |
          sudo apt-get update
          sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf

      - name: install frontend dependencies
        run: bun install

      - name: build tauri app
        uses: tauri-apps/tauri-action@v1
        env:
```

### 10.3 latest.json 格式

```json
{
  "version": "0.2.0",
  "notes": "新增应用内自动更新功能\n修复 Quick Create 浮窗定位问题\n优化任务拖拽性能",
  "pub_date": "2026-07-01T10:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "<base64 签名>",
      "url": "https://cdn.yourdomain.com/updates/stable/StoneFlow_0.2.0_aarch64.app.tar.gz"
    },
    "darwin-x86_64": {
      "signature": "<base64 签名>",
      "url": "https://cdn.yourdomain.com/updates/stable/StoneFlow_0.2.0_x64.app.tar.gz"
    },
    "windows-x86_64": {
      "signature": "<base64 签名>",
      "url": "https://cdn.yourdomain.com/updates/stable/StoneFlow_0.2.0_x64-setup.exe"
    },
    "linux-x86_64": {
      "signature": "<base64 签名>",
      "url": "https://cdn.yourdomain.com/updates/stable/StoneFlow_0.2.0_amd64.AppImage"
    }
  }
}
```

**关键注意事项：**
- macOS 上 updater 使用 `.app.tar.gz`（不是 `.dmg`），因为 Tauri updater 需要直接替换 .app bundle
- Windows 上推荐使用 NSIS（`.exe`），WiX（`.msi`）也可以
- Linux 使用 AppImage
- `signature` 字段是 `.sig` 文件的内容（base64），不是文件路径或 URL
- `latest.json` 的 `Cache-Control` 建议设置为 `max-age=300`（5 分钟），平衡即时性和 CDN 缓存

### 10.4 Beta 渠道发布

- Tag 格式：`v0.2.0-beta.1`
- CI 检测到预发布版本时，将 JSON 上传到 `updates/beta/latest.json`
- 用户在设置中切换到 Beta 渠道后才能收到

## 11. 错误处理

### 11.1 错误分类

| 错误场景 | 处理方式 |
|---|---|
| 网络不可用/超时 | emit `update-error`，静默记录，下次检查重试，不弹窗 |
| 签名验证失败 | emit `update-error`，记录错误，视为更新不可信，拒绝安装 |
| 下载中断 | 进度回调停止，弹窗显示错误状态，提供"重试"按钮 |
| 安装失败 | 弹窗显示错误，提供"重试"和"稍后"按钮 |
| 服务端返回 204 | 无更新，静默结束 |
| 服务端返回非 2xx | 尝试 endpoints 数组中的下一个 URL，全部失败则静默报错 |

### 11.2 错误展示原则

- 自动检查过程中的错误不弹窗打扰用户（静默记录日志）
- 用户主动操作（手动检查、手动下载）的错误通过弹窗明确提示
- 错误信息对用户友好（"无法连接到更新服务器"而不是原始错误码）
- 错误详情（error message）记录到日志，方便排查

## 12. tauri.conf.json 配置

```json
{
  "bundle": {
    "createUpdaterArtifacts": true
  },
  "plugins": {
    "updater": {
      "pubkey": "<BASE64_PUBLIC_KEY>",
      "endpoints": [
        "https://cdn.yourdomain.com/updates/stable/latest.json"
      ],
      "windows": {
        "installMode": "passive"
      }
    }
  }
}
```

说明：
- `endpoints` 中默认填 stable 渠道 URL，运行时根据用户设置动态覆盖
- `windows.installMode: "passive"`：Windows 上显示进度条但不需要用户交互
- `pubkey` 在密钥生成后填入
- `createUpdaterArtifacts: true`：构建时生成 `.app.tar.gz`/`.sig` 等 updater 专用产物

### 12.1 Capabilities

`capabilities/main.json` 添加：
```json
{
  "permissions": ["updater:default"]
}
```
