# R10 全量验证与常青文档 - Spec

## 目标

完成跨模块验收，将已实现事实同步到常青文档，并归档本轮任务期文档。

## 范围

- 执行 Rust、前端、同步、离线删除、批量操作、性能与手动核心路径验证。
- 更新根架构、`src-tauri` 架构、A1、A2 与受影响模块 README/ARCHITECTURE/DESIGN。
- 核对任务文档与实际实现，记录偏差、剩余风险和已验证证据。
- 归档 R0-R10 与总重构计划。

## 不做什么

- 不把未实现的移动端、提醒、附件、账号系统写成当前事实。
- 不为历史决策批量补 ADR。

## 当前上下文

- R0-R9 的各自测试只能证明局部正确；本阶段负责验证跨模块契约、两设备同步和文档事实是否真正一致。
- 常青文档不能提前写计划，只能在最终代码和验收完成后记录当前状态。

## 验收矩阵

- 本地业务：Space 默认替代、Project/Task WorkState、排序、View、批量操作、删除/恢复、Activity。
- 同步：首次基线、常规 delta、离线编辑、长期离线删除、LWW、远端幂等、鉴权/schema 错误与重试。
- 性能：与 R0 对比 worker 启动消失、payload/阶段耗时降低；确认正常同步不走全量基线。
- 边界：commands 不直连 storage、application 不依赖基础设施、platform 不含业务逻辑、旧路径无残留。
- 文档：根架构、`src-tauri` 架构、A1/A2、模块 README/ARCHITECTURE/DESIGN 与代码逐项核对。

## 实施设计

1. 先运行自动化校验并分类新增失败与既有无关问题。
2. 用至少两份独立本地库/设备 ID 演练同步顺序，不以单库 mock 替代删除与 cursor 测试。
3. 从 tracing 聚合阶段耗时，和 R0 基线对比；若未达到目标，回到实际瓶颈任务修复，不在 R10 堆优化。
4. 根据最终代码更新长期文档；任务 SPEC/TASKS 记录实际偏差后归档。

## 退出条件

- 验收标准均有命令、测试或人工路径证据。
- 常青文档仅描述已落地架构与实现。
- 活跃任务索引清理，任务期文档进入归档。

## 验证

- `cargo fmt --check`、严格 Clippy、workspace tests。
- `bun typecheck`、`bun lint`、`bun format:check` 与定向前端测试。
- 两设备/两库同步演练及同步性能对比。

## 风险

- 文档更新必须最后进行，避免把未落地的 R10 修复写成当前事实。
- 若远端 Turso 真机演练受网络或凭证阻塞，需明确记录未验证范围，不能用本地测试假装覆盖。
