# R0 备份与基线 - Tasks

## 当前阶段

待开始。这是唯一允许接触旧数据的准备任务；只有备份完整、可读且记录完成后，后续任务才能执行破坏性重写。

## 阶段一：冻结写入并定位数据资产

目标：准确知道旧本地 SQLite、同步元数据和远端 Turso 数据在哪里，避免漏备份 WAL 或误删用户数据。

- [ ] 关闭 StoneFlow，确认没有残留进程、sync worker 或活跃 SQLite writer。
- [ ] 解析并记录本地数据库、WAL、SHM、日志、远端配置及同步 cursor 的实际路径与版本信息。
- [ ] 记录当前 Git commit、Cargo workspace member、Tauri 配置和依赖锁定文件摘要，作为可回退代码基线。
- [ ] 只记录路径、版本和校验摘要；token、URL 私密参数和用户正文不得写入 Git 文档。

验收：已形成可复查的资产清单，且关闭应用后不存在活跃 writer。

## 阶段二：制作并验证本地备份

目标：保留一个自洽的本地 SQLite 快照，能够在新重构失败时只读检查或人工恢复。

- [ ] 复制 SQLite 主文件、WAL、SHM 到带时间戳且不在仓库内的备份目录。
- [ ] 对原库与备份分别运行 `PRAGMA integrity_check`，记录结果、文件大小和 SHA-256 摘要。
- [ ] 用独立只读连接打开备份，记录关键表及实体计数，确认 WAL 内容没有遗漏。
- [ ] 对备份做一次最小恢复演练：在临时目录打开副本并查询关键数据，不修改源库。

验收：备份可独立打开、完整性通过，关键计数与源库一致；备份位置和校验信息已写入完成记录。

## 阶段三：导出并验证远端 Turso 基线

目标：在删除旧同步链路前可恢复远端数据面和 change metadata。

- [ ] 使用已有受控凭证导出远端 DDL、业务数据、同步表与必要索引定义到仓库外安全位置。
- [ ] 用独立只读连接或临时实例验证导出能被读取，并核对关键表计数与源端一致。
- [ ] 记录远端 schema 版本、change log/cursor 的规模和导出时间，但不记录凭证。
- [ ] 若远端导出失败，停止后续删除性任务，先解决导出能力而不是以本地库替代远端备份。

验收：远端 DDL 和数据可独立检查；导出证据完整；敏感信息未进入仓库。

## 阶段四：采集工程与同步性能基线

目标：为 R7 的“秒级增量同步”提供可比较数据，而不是凭主观体感判断优化效果。

- [ ] 记录 `cargo fmt --check`、Clippy、workspace tests、Bun typecheck/lint/format 的当前结果与已知失败。
- [ ] 在空闲同步和产生少量 mutation 后分别记录 worker 启动、本地读取、上传、下载、应用与总耗时。
- [ ] 记录 payload 大小、远端往返次数、实体数量和本地库规模；不采集任务正文。
- [ ] 标记无法在当前环境测得的项目，避免以后将缺失数据误当作零。

验收：性能数据可与 R7 的 phase 日志直接比较；现有工程失败有明确起点，不被误归因给重构。

## 阻塞

- 需要运行时可用的远端 Turso 凭证；凭证不得写入本文件或 Git。
- 任一备份验证失败时，不得进入 R1 或删除任何旧数据、worker 和 migration。
