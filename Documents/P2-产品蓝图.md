## 核心功能模块

| 模块名称 | 职责 | V1 包含 | 备注 |
|----------|------|---------|------|
| 全局捕获 | 通过全局入口快速创建任务 | 是 | StoneFlow 的核心入口能力 |
| Inbox 整理 | 承接新任务并引导补齐必选信息 | 是 | 任务离开 Inbox 前必须完成整理 |
| Focus 聚合视图 | 承载 Focus、Upcoming、最近添加、高优先级等执行视图 | 是 | 以 tabs 组织多个视图 |
| Project 管理 | 承接任务的长期归宿，按项目管理任务 | 是 | 支持一层子项目 |
| Task Drawer | 展示和编辑任务详情 | 是 | 右侧 Drawer 打开 |
| 资源挂载 | 给任务附加文档链接、本地文件、本地文件夹 | 是 | 第一版只做挂载和一键打开 |
| Trash 回收站 | 承接已删除的 Project 与 Task | 是 | 恢复机制待后续明确 |
| 自定义视图规则 | 用户自定义 Focus 规则页 | 部分 | 第一版先以内置 tabs 为主，保留扩展能力 |
| 团队协作 / 同步 | 多人、账号、云同步 | 否 | V1 明确不包含 |

## 核心用户路径

### 路径 1：全局捕获并整理进项目

1. 用户通过全局入口唤起 StoneFlow。
2. 用户一句话输入任务标题，快速创建任务。
3. 系统将任务放入当前 Space 的 `Inbox`。
4. 用户进入 `Inbox`，为任务补齐必选信息：
   - 优先级
   - 所属 Project
   - 状态 `todo`
5. 用户可选补充标签、截止时间、备注。
6. 任务离开 `Inbox`，进入目标 `Project`。
7. 用户后续在 `Project` 或 `Focus` 视图中继续处理任务。

最终状态：

- 任务从“快速记录”进入“可执行系统”。

### 路径 2：通过 Focus 驱动日常执行

1. 用户进入当前 Space 下的 `Focus` 页面。
2. 用户在不同 tabs 间切换：
   - `Focus`
   - `Upcoming`
   - `最近添加`
   - `高优先级`
3. 用户查看当前最值得处理的任务集合。
4. 用户可进行批量操作或点击单个任务。
5. 点击任务后，右侧打开 `Task Drawer`。
6. 用户在 Drawer 中查看和修改任务核心信息。
7. 完成任务后，状态从 `todo` 改为 `done`。

最终状态：

- 用户通过聚合视图完成日常聚焦和执行，而不是在多个页面来回找任务。

### 路径 3：项目内持续推进任务

1. 用户进入某个 `Project`。
2. 页面顶部显示项目摘要区：
   - 名称
   - 状态
   - 备注
   - 轻量进度
   - 创建时间
   - 更新时间
3. 用户在项目内查看按状态分组的任务列表。
4. 用户点击某个任务，打开右侧 Drawer。
5. 用户修改任务详情、挂载资源或完成任务。
6. 系统自动更新项目的进度展示。

最终状态：

- 项目成为任务的长期归宿与组织容器，执行在任务层完成。

### 路径 4：删除与回收

1. 用户删除某个任务或项目。
2. 系统将其移动到 `Trash`。
3. 用户可在 `Trash` 中查看已删除对象。

最终状态：

- 删除对象不会立刻消失，系统保留回收站语义。

## 状态模型

### Task 状态

第一版先极简为两态：

- `todo`
- `done`

状态转换：

- `todo` → 用户完成任务 → `done`
- `done` → 用户重新打开任务 → `todo`

### Task 位置流转

任务不仅有状态，还有位置流转：

- 全局捕获 → `Inbox`
- `Inbox` 整理完成 → 某个 `Project`
- `Project` 内任务可同时被多个视图引用
- 删除后进入 `Trash`

说明：

- `Inbox` 不是状态，而是位置/模块
- `Focus / Upcoming / 最近添加 / 高优先级` 不是存储层，而是视图层

### Project 状态

第一版 `Project` 需要状态字段，但具体状态集合在后续文档中继续收口。

当前只确认：

- `Project` 不是纯静态目录
- `Project` 需要能表达自身状态

### Inbox 约束

- 任务在 `Inbox` 中默认状态就是 `todo`
- 任务离开 `Inbox` 前，必须补齐：
  - 优先级
  - 所属 Project
  - 状态 `todo`

## UI 形态定义

- **平台**：macOS 桌面端
- **布局模式**：顶部 Space Tabs + 左侧 Sidebar + 中间主内容区 + 右侧 Task Drawer
- **核心交互范式**：
  - 全局捕获优先
  - 键盘优先
  - 列表与视图切换优先
  - 点击任务打开 Drawer，而不是跳转独立详情页
- **页面组织方式**：
  - Sidebar 中优先暴露系统模块和项目树
  - Focus 作为聚合容器统一承载多个执行视图
  - Project 作为长期任务归宿
- **反馈要求**：
  - 操作后需要即时反馈
  - 完成任务时需要明显但克制的成就反馈
  - 产品整体允许有存在感和推进感，而不是绝对安静
- **响应式要求**：
  - 需要适配不同桌面窗口宽度
  - 第一版不考虑移动端和 Web 响应式

## 当前蓝图约束

- 第一版必须坚持 `Space -> Project -> Task` 主结构。
- `Inbox` 是特殊系统模块，不是普通 Project。
- `Focus` 是聚合容器，不是单一页面。
- `Project` 第一版支持一层子项目，不扩展无限层级。
- `Task` 第一版只保留 `todo / done` 两态。
- `Resource` 第一版只做挂载和一键打开，不做复杂预览。
