# 头像菜单更新检查与关于窗口 - Spec

## 背景与目标

StoneFlow 已具备应用内检查、下载、安装更新及更新记录能力，但头像菜单中的“检查更新”和“关于 StoneFlow”仍是不可用占位。设置页的手动检查还直接重复了更新调用路径，容易与新菜单入口形成双轨状态流。

本任务开放这两个入口，并把主动检查收敛为更新域的唯一用户动作。关于信息以紧凑 Dialog 提供版本信息、更新相关快捷操作及四个外部链接占位；不虚构或打开尚未配置的外部地址。

## 范围

- 启用头像菜单“检查更新”，接入既有更新状态机与更新 Dialog。
- 将设置页与头像菜单的主动检查收敛为更新域唯一入口。
- 新增 `app-info` feature，承载应用版本读取、关于窗口与外部链接配置。
- 启用头像菜单“关于 StoneFlow”，以 shell overlay 装配紧凑 Dialog。
- 在关于窗口展示官网、反馈、隐私政策、许可证四项不可点击的配置占位。
- 将生产构建的 updater 不安全 HTTP 开关与开发 Mock 能力隔离。

## 不做什么

- 不新增主导航、设置子路由、命令面板命令或独立“关于”页面。
- 不实现用户资料、账户体系、反馈提交、许可证内容、隐私政策页面或网站跳转。
- 不改变更新渠道、自动检查频率、下载、跳过版本、安装或重启的既有业务规则。
- 不提供假 URL、隐式跳转、遥测、在线版本说明或新的后端 IPC command。

## 用户场景与需求

### US-1：主动检查更新

作为 StoneFlow 用户，我想从头像菜单主动检查更新，以便无需进入设置页即可确认当前应用是否有新版本。

### US-2：一致的检查结果

作为用户，我想让头像菜单和设置页显示相同的检查过程与结果，以便不会因入口不同而得到冲突的更新提示或重复请求。

### US-3：查看应用信息

作为用户，我想从头像菜单查看当前 StoneFlow 版本和相关入口，以便在需要支持、更新或核对版本时获得明确的信息。

### US-4：待后续配置的外部信息

作为产品维护者，我想先展示外部链接入口的位置但不绑定 URL，以便后续补充官网、反馈、隐私政策和许可证信息时只改一处配置。

## 能力边界

- “检查更新”只触发一次已有的手动检查动作；发现新版本时复用既有 `UpdateDialog`，不新增第二个更新 Dialog。
- 检查进行中时，所有触发同一动作的控件必须不可再次触发；关于窗口中的检查按钮与头像菜单共享该状态。
- 关于窗口中的版本号以运行中 Tauri 应用返回的版本为准；非 Tauri 预览或读取失败时展示明确的不可用状态，不伪造版本号。
- 四项外部链接在配置值为 `null` 时保持禁用且不发起网络或系统 opener 调用；配置真实 HTTPS URL 后才可用。
- updater 的 HTTP Mock 仅能在开发路径启用；生产构建必须不携带不安全传输配置，且继续拒绝 HTTP 更新端点。

## Definition of Done

- 所有验收标准经过定向自动化测试或明确的手动验证。
- 头像菜单、设置页、更新 Dialog、页脚版本信息和关于窗口无功能回归。
- 没有遗留的手动检查双实现、旧版本组件归属或长期兼容转发层。
- 受影响 TypeScript 检查、边界检查、格式检查、测试与 Rust 更新相关检查通过。
- 关于链接仅以占位配置交付；真实地址和真实 release 包安装验证不在本任务中擅自执行。

## 验收标准

- **AC-1**：当用户在头像菜单选择“检查更新”时，系统应当调用更新域唯一的手动检查动作。
- **AC-2**：当手动检查发现新版本时，系统应当展示既有更新 Dialog；当未发现新版本时，系统应当显示“当前已是最新版本”的既有成功提示。
- **AC-3**：只要手动检查处于进行中，系统应当禁用头像菜单、设置页和关于窗口中所有再次检查控件。
- **AC-4**：当用户在头像菜单选择“关于 StoneFlow”时，系统应当打开非路由的关于 Dialog，并可通过关闭控件恢复原工作界面。
- **AC-5**：当 Tauri 可提供版本号时，关于 Dialog 和页脚应当展示同一版本；当版本读取失败时，系统应当展示版本不可用状态且保持 Dialog 可关闭。
- **AC-6**：当官网、反馈、隐私政策或许可证链接未配置时，系统应当将对应入口显示为不可用占位，且不得打开 URL。
- **AC-7**：当后续为任一外部链接配置真实 HTTPS URL 时，系统应当仅通过 `app-info` 的集中配置使对应入口可用，而无需修改菜单、Dialog 结构或更新 feature。
- **AC-8**：当构建生产应用时，系统应当不启用 updater 的不安全 HTTP 传输配置；当开发 Mock 使用 HTTP 时，系统应当只在开发路径启用该能力。

## 当前技术方案

采用“更新域唯一主动检查 Hook + `app-info` 独立 feature + shell overlay 装配”的方案。涉及状态机收敛、跨 feature 归属迁移和 Tauri 开发/生产配置隔离，具体设计、备选方案与风险见 [PLAN.md](PLAN.md)。
