## 1. 目标心智（一句话）

```txt
启动接线在 app · 铬架在 layout · URL 薄页在 routes ·
能力在 features（model/api/hooks/components + public）·
纯零件在 shared · 样式在 styles
```

依赖**只允许向「更稳定、更无业务」的方向**；跨 feature 只走 **public**。

## 2. 目标 `src/` 分层图

### 2.1 顶层树（冻结示意 · 非 Migrate 逐步 diff）

```txt
src/
├── main.tsx                      # 入口：bootstrap → RouterProvider
│
├── app/                          # COMPOSITION · 组合根（保持瘦）
│   ├── bootstrap/                # AppProviders、QueryClient 创建与默认选项
│   └── navigation/               # path 语义、intent、route memory、session history
│                                 # （非视觉；不塞进 layout）
│
├── layout/                       # 应用铬架（原 app/layouts/shell 目标位）
│   ├── AppLayout.tsx             # 侧栏 + 顶栏 + 主区骨架
│   ├── header/
│   ├── sidebar/
│   ├── overlays/                 # 壳级抽屉/层挂载点（装配，非业务实现）
│   ├── command-bridge/           # 组合各 feature public 的 command 实现切片
│   └── entity-scene/             # 零业务槽位编排（board/header/…）
│
├── routes/                       # TanStack file routes + 薄页（无顶层 pages/）
│   ├── __root.tsx
│   ├── index.tsx
│   ├── settings.tsx
│   ├── quick-create.tsx          # 可挂 QC 运行时（实现仍在 features/quick-create）
│   ├── -*.ts(x)                  # 非路由 colocated（TanStack `-` 忽略）
│   └── _shell/
│       ├── route.tsx             # 路由 layout：<AppLayout><Outlet /></AppLayout>
│       └── …/index.tsx           # 各 URL 薄页
│
├── features/
│   └── <name>/                   # 垂直切片（可删单位）
│       ├── model/                # 类型、纯 rules、ports（可按 O2 省略空夹）
│       ├── api/                  # 仅 IO：invoke / Store / listen
│       ├── hooks/                # Query/Mutation/facade（应用层）
│       ├── components/           # 业务 UI
│       └── index.public.ts       # B′ 唯一对外入口（见 §4、O3）
│
├── shared/                       # 与业务实体无关
│   ├── components/               # 含 base(shadcn)、main-card、通用 board/row 壳等
│   ├── hooks/                    # 无实体语义的通用 hook（少而精）
│   └── lib/                      # cn、date、normalize-error…
│
├── styles/                       # token / base / utilities（现有架构可保留）
├── test/                         # 测试基建（renderWithRouter 等）
├── ARCHITECTURE.md               # 短契约（Migrate 后回写目标态摘要）
└── CONVENTIONS.md
```

### 2.2 两层「layout」勿混

| 名称 | 路径 | 职责 |
|------|------|------|
| **产品铬架** | `src/layout/**` | 侧栏、顶栏、主区、EntityScene、CommandBridge、壳 overlay 装配 |
| **路由 layout** | `routes/_shell/route.tsx` 等 | 尽量一行挂载 `AppLayout` + `Outlet` |

### 2.3 Feature 内分层（职责 → 夹名）

| 职责带 | 目录 | 允许 | 禁止 |
|--------|------|------|------|
| Domain | `model/` | 类型、纯函数、Port 接口 | React、`@tauri`、其它 feature 私有 |
| Infra | `api/` | invoke、Store、listen、DTO→model | React 组件、业务 JSX |
| Application | `hooks/` | queryOptions、useQuery/useMutation、list-scene facade | 直接给外 feature 深 export 私有文件 |
| Experience（业务 UI） | `components/` | 渲染；调本 feature hooks；用 shared | `invoke`、import 其它 feature 私有路径 |
| Public | `index.public.ts` | re-export 允许外用的 hooks/types/注册面 | re-export 整棵 components 私有树 |

**Feature 内依赖方向（硬）：**

```txt
components → hooks → api → model
components → shared
hooks      → model · api · shared（谨慎）· 其它 feature 的 public
api        → model · @tauri/* · shared/lib（工具级）
model      → （纯）偶发其它 feature public 的类型-only（尽量少）
```

### 2.4 各顶层「负责 / 不负责」

| 顶层 | 负责 | 不负责 |
|------|------|--------|
| **app** | 启动、全局 Provider 树、导航语义与记忆 | 侧栏 UI、实体规则、list-scene |
| **layout** | 铬架 UI、槽位、命令桥**装配**、壳级挂载 | 实体 Query 编排、task 业务板实现 |
| **routes** | 匹配、loader、redirect、薄页接线 | 厚业务组件、invoke |
| **features** | 某一产品能力的全栈（model→ui） | 全局壳骨架、全局纯 UI 库 |
| **shared** | 无业务纯 UI/工具 | 任何 app/layout/features 依赖、实体规则 |
| **styles** | 视觉 token 与全局样式 | 业务逻辑 |
| **test** | 测试 helper | 生产路径依赖 test |

## 3. 依赖允许 / 禁止矩阵

### 3.1 顶层矩阵

图例：✅ 允许 · ⚠️ 仅 public / 装配 · ❌ 禁止 · — 同层自用

| 从 \ 到 | app | layout | routes | features | shared | styles |
|---------|-----|--------|--------|----------|--------|--------|
| **app** | — | ✅ 可引用 layout 入口做 Provider 组合 | ⚠️ 少（router 挂载） | ⚠️ **仅 public** | ✅ | ✅ |
| **layout** | ❌（避免环；导航用 app/navigation 的纯模块可 ✅） | — | ❌ | ⚠️ **仅 public** | ✅ | ✅ |
| **routes** | ⚠️ navigation intents / path helpers | ✅ AppLayout / EntityScene | — | ⚠️ **仅 public** + 薄组合 | ✅ | ✅ |
| **features** | ❌ | ❌ | ❌ | ⚠️ **仅对方 public** | ✅ | ✅ |
| **shared** | ❌ | ❌ | ❌ | ❌ | — | ✅（token 类） |
| **styles** | ❌ | ❌ | ❌ | ❌ | ❌ | — |

**说明：**

- `layout → app/navigation`：允许依赖**纯导航模块**（path/intent），禁止 layout 依赖 app 里「再包一层业务」的东西。  
- `routes → app/navigation`：薄页发 intent / 读 path 语义时允许。  
- `features → app|layout|routes`：**永久禁止**（可删除性）。

### 3.2 Feature ↔ Feature（B′）

| 允许 | 禁止 |
|------|------|
| `import { … } from '@/features/task'`（经 `index.public.ts` 解析） | `from '@/features/task/components/...'` |
| public 导出的 hooks、model 类型、command 注册用最小面 | public 导出整包私有 components 树「图方便」 |
| platform feature 被 domain/scene 依赖 public | scene 为图省事深 import domain 私有 adapter |

**删除检查：** 卸 feature X 时，全局搜 `features/X` 应只剩：其自身树、引用其 **public** 的装配点（layout/routes/app）、以及路由文件。

### 3.3 特殊边

| 边 | 规则 |
|----|------|
| **components → api** | ❌ 必须经 hooks |
| **routes 薄页 → api** | ❌ 必须经 public hooks / queryOptions |
| **layout → api** | ❌ |
| **shared → features** | ❌（SHR-D1 目标态为零） |
| **QC feature** | 可依赖 task 等 **public**；❌ 依赖 `layout/**` 主窗壳 |
| **测试文件** | 可深 import 被测模块私有路径；生产代码不可 |

### 3.4 目标强制手段（Migrate 落地，T1 定性）

1. **eslint-plugin-boundaries** 或 **dependency-cruiser**（按上表）  
2. CI：禁止外部匹配 `features/*/components/**`、`features/*/api/**`（测试与同 feature 内除外）  
3. `index.public.ts` 为唯一合法跨 feature 入口（见 O3）

## 4. Public vs Private 约定

### 4.1 命名与位置

| 面 | 路径 | 谁可以 import |
|----|------|----------------|
| **Public** | `features/<x>/index.public.ts` | app、layout、routes、其它 features、测试 |
| **Private** | `features/<x>/{model,api,hooks,components}/**` | **仅**同 feature 内（及该 feature 自己的测试） |

别名（可选，T5 可细化）：`@/features/task` → 指向 public（tsconfig paths）。

### 4.2 Public 应导出什么

| 宜导出 | 不宜导出 |
|--------|----------|
| 列表/详情 **facade hooks**（如 `useTaskListScene`） | 内部 hook 碎片（`useTaskBoardSelectionInternal`） |
| `queryOptions` / key 工厂中**供 loader 使用**的稳定面 | 任意内部 query 文件路径 |
| 跨 feature 需要的 **model 类型**、纯 rules | 半成品 DTO、api 原始 response |
| command / sidebar **注册描述**或 slice 工厂 | Command 实现细节焊死 layout 类型 |
| 少量「官方」components（若真是产品对外块） | 默认整树 components |

### 4.3 与「少 barrel」的关系（P11）

- **跨边界**需要一个稳定入口 → `index.public.ts` **是边界，不是鼓励** feature 内部再套多层 barrel。  
- **feature 内部**优先直接 import 具体文件（Vercel `bundle-barrel-imports`）。  
- public 文件保持**短列表显式 export**，禁止 `export * from './components'`。

### 4.4 旧夹名映射（As-Is → To-Be）

| As-Is 常见 | To-Be |
|------------|--------|
| `features/*/api`（invoke） | `api/`（收窄为只 IO） |
| `features/*/query` | 并入 `hooks/`（可子目录 `hooks/queries`） |
| `features/*/model` 或 types | `model/` |
| `features/*/ui` | `components/` |
| `features/*/core` | 视内容：`model` 或 `hooks` |
| `shared/ui` | `shared/components` |
| `app/layouts/shell` | `layout/` |
| `app/layouts/entity-scene` | `layout/entity-scene` |
| `app/layouts/main-card` | `shared/components/main-card` |

## 5. T0 开放问题关闭（O1–O3）

### O1 · 细目录与 navigation 位置 — **关闭**

| 项 | 结论 |
|----|------|
| 顶层集合 | `app` · `layout` · `routes` · `features` · `shared` · `styles` · `test` |
| navigation | 保留 **`app/navigation`**（语义非视觉；与 T0 决策树一致） |
| layout 子树 | 最低集：`AppLayout` · header · sidebar · overlays · command-bridge · entity-scene；T4 可再拆文件，**不改顶层名** |

### O2 · 小 feature 夹级强度 — **关闭（渐进强制）**

| 规模 | 要求 |
|------|------|
| **试点 / 中大型**（task、project、command、quick-create…） | 四夹齐全（空夹可暂缺，但**出现代码时**落入正确夹） |
| **薄 scene 壳**（仅薄页接线） | **不要**为壳再建 feature；逻辑进 owner feature，页在 `routes` |
| **极小工具 feature** | 允许暂时只有 `hooks`+`api` 或 `components`+`hooks`；**一旦有 invoke 必须进 api，一旦有类型规则必须进 model** |
| **禁止** | 有 invoke 却写在 components；为「好看」建空 domain 殿堂 |

### O3 · public 形态 — **关闭**

| 项 | 结论 |
|----|------|
| 对外入口 | **每个 feature 恰好一个** `index.public.ts`（或 `public.ts`，试点统一 `index.public.ts`） |
| 拆分 | public 文件内可 `export { x } from './hooks/foo'` 显式列出；**不**建 `public/` 多入口给外部用 |
| 禁止 | `export *` 扫整目录；外部 deep import 私有路径 |

## 6. 与 As-Is 差异摘要 + Gap 如何消失

### 6.1 结构对照

| 区域 | As-Is | To-Be | 主要 Gap |
|------|-------|-------|----------|
| 壳 | `app/layouts/shell` God ~1.2k LOC | `layout/*` 分装 + routes 一行挂载 | SHELL-D1 |
| 命令焊死 | Shell 内巨型 actions | `layout/command-bridge` + feature public slices | PLAT-D2 |
| 列表页 | 三页复制编排 | `features/task/hooks` list-scene + routes 薄页 | SCN-D1 |
| shared 反向 | resolver / dialog / form → app/features | 迁出 shared；shared 仅纯能力 | **SHR-D1** |
| 路由栈 | 文档曾写 react-router（漂移） | TanStack file routes + 薄页 | DRIFT-001（文档） |
| 布局文档 | layouts ARCHITECTURE 过时 | 目标改写 layout 短契约 | DRIFT-004–006 |
| MainCard / EntityScene | app/layouts 混业务 | MainCard→shared；EntityScene→layout | 分层清晰 |
| feature 互依 | 网状深 import | 仅 public（B′） | RING-META 等 |
| Query / invoke | 组件偶发直打 | api 唯一 IO；hooks 唯一数据门面 | DATA-D* / 裸 invoke |
| QC | 部分可碰主壳 | 禁止依赖 layout | 边界 |
| monorepo | 单包 | 仍单包 | — |

### 6.2 SHR-D1 目标态（P0）

| 现状问题文件（类） | 目标落点 |
|--------------------|----------|

## 8. 新代码决策树（与 T0 对齐 · 可执行版）

```txt
1. 路由匹配 / loader / 薄页？            → routes/
2. 启动 Provider / QueryClient？         → app/bootstrap
3. 路径语义 / intent / 路由记忆？        → app/navigation
4. 侧栏顶栏主区 / 命令桥装配 / 槽位壳？   → layout/
5. 与业务无关的组件 / hook / 工具？      → shared/{components,hooks,lib}
6. 类型 / 纯规则 / ports？               → features/X/model
7. invoke / Store / listen？             → features/X/api
8. Query / 用例 / list-scene facade？    → features/X/hooks
9. 业务界面？                            → features/X/components
10. 要给外模块用？                       → 写入 features/X/index.public.ts（显式）
11. 否则停：新 feature 或拒绝「先扔 shared」
```
