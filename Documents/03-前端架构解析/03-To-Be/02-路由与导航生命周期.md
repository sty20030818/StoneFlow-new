## 1. 目标结论（先读这段）

| 能力 | 真相源（目标 = 基本沿用现状，边界更硬） |
|------|----------------------------------------|
| 当前 URL | TanStack Router（hash history） |
| 浏览器前进/后退 | `router.history.go`（session history 只读+调度） |
| 启动恢复 / scope 记忆 | `app/navigation` 纯规则 + Tauri Store 边界 |
| 最近浏览 UI | 会话内存（不持久化） |
| 业务数据 | Query（loader `ensureQueryData` 预热） |
| 路径拼接 / 产品语义 | `routePaths` / `shellRoute` / **intents** |

**三分职责（冻结）：**

```txt
routes/**           → URL 匹配 · loader · redirect · 路由 layout · 薄页
app/router          → createRouter · hash · Register · preload 默认
app/navigation/**   → 解析 · 拼 path · intent · 恢复/记忆 · session history
layout/**           → 铬架 UI；消费 parse/sessionHistory；不写 Store 规则
features/**         → 只发 intent / 用 public hooks；不碰 history / Store 导航 key
```

**目标态相对 As-Is 的增量（非推倒）：**

1. 薄页在 `routes` 内组合 feature **public**（不深 import 私有 UI 路径为常态）。  
2. `_shell/route` → 挂 `layout/AppLayout`（铬架上提后）。  
3. navigation → layouts/config 的标签耦合 → T4/Migrate 改为 layout 注入或 shared 纯展示元数据（不阻塞 T2 时序）。  
4. routeMemory 校验 task/project：**经 feature public/api 端口**（可保留行为，方向符合 B′）。  
5. settings **不进** route memory：**Accept**（T0 D-settings-mem）。

## 2. 生命周期时序（目标态）

### 2.1 冷启动 → 恢复工作区

```txt
main.tsx
  → app/bootstrap（QueryClient + AppProviders）
  → RouterProvider(router, context: { queryClient })

命中 path `/`（routes/index）
  → loader:
       1. ensureQueryData(spaces.visible)     // 启动依赖可见空间
       2. resolveStartupPath({ spaces })      // navigation：读 Store + 纯规则 + 可选实体校验
       3. throw redirect({ to: path, replace: true })
  → pending UI：「正在恢复…」（route 级，非业务页）

进入 /_shell/... 目标 path
  → routes/_shell/route：<AppLayout><Outlet /></AppLayout>
  → scope layout（all | spaces/$spaceId）：
       useRememberCurrentShellRoute(scope)   // 此后 location 变化可写记忆
  → 叶子薄页：loader（若有）+ feature public facade
```

**约束：**

- `/` **只做跳板**，不渲染业务壳。  
- Store **不**成为当前 URL；只提供「上次可恢复 path」。  
- `replace: true` 避免启动跳板进 history 栈污染 back。

### 2.2 进入 scope 后的 remember

```txt
用户位于可记忆 shell path
  → scope layout 已挂 useRememberCurrentShellRoute(scope)
  → location 变化（effect）
  → isRememberableShellPath？否 → no-op
  → createNextShellRouteMemory → LazyStore set + save
```

**可记忆（目标保持）：**

- `/all/{inbox|tasks|views|projects|no-project|archive|trash}` 及 space 对称  
- view / task / project **详情** path  

**不可记忆（目标保持 · Accept）：**

- `/`、`/quick-create`  
- **settings 全路径**  
- unknown / bare `/all`  

→ 从设置返回 scope 时，恢复的是进入设置前的 **work path**。

### 2.3 Session 最近浏览与 Header back/forward

```txt
layout 装配 useShellSessionRouteHistory
  → 跟踪 rememberable entries（内存）
  → goBack / goForward → router.history.go(±1)
  → 下拉跳转 → navigate({ to: entry.path })  // typed / 字符串 path 与现状一致即可
```

**约束：**

- Tauri Store **不参与** back/forward。  
- 不在 features 内自建第二套 history。  
- 展示名/图标：目标由 layout 侧配置或注入；navigation 核心不依赖「重 UI config」（渐进，见 §8）。

### 2.4 业务导航（唯一推荐路径）

```txt
feature / layout 控件
  → openTaskDetail / openSection / openSettings / …  （app/navigation/intents）
  → 得到 canonical path（或 navigate 参数）
  → router.navigate / <Link to=…>
```

**禁止：**

- 在 feature 里手搓 `/spaces/${id}/tasks/${id}` 字符串（漏 canonical / 漏 scope）。  
- 用 Zustand 镜像「当前路由」。  
- 用 Query 存导航历史。

### 2.5 详情深链（task / project）

```txt
routes/.../tasks/$taskId（或 project）
  → loader:
       ensureVisibleSpaces
       ensureTaskDetailRouteData | ensureProjectDetailRouteData
         → ensureQueryData(detail queryOptions)   // 来自 feature public/hooks
         → space 不一致 → redirect replace 到实体所在 space path
         → 不可见/不存在 → 错误态（route error / 页级 state），非静默白屏
  → 薄页：挂 TaskPage / ProjectPage（feature components via public 或 routes 直挂过渡期）
```

**all 侧 project detail：** 保持「总是校正到 `/spaces/:spaceId/...`」的产品行为（As-Is 已有）。

### 2.6 Quick Create 窗

```txt
独立 hash 路由 /quick-create
  → 不进 shell remember
  → 不挂 AppLayout 主铬架
  → 实现在 features/quick-create；❌ 依赖 layout/**
```

### 2.7 Settings

```txt
legacy /settings → redirect → /all/settings/$section（last section · session 级）
scope 内 /…/settings / /…/settings/$section
  → section 非法 → redirect 默认 section
  → 不写入 route memory（Accept）
```

## 3. 模块职责清单

### 3.1 `app/router`（保留形态）

| 配置 | 目标值 | Router BP |
|------|--------|-----------|
| history | `createHashHistory()`（Tauri） | — |
| routeTree | 生成物 `routeTree.gen` | `org-file-based-routing` |
| context | `{ queryClient }` | `ctx-root-context` / loader 注入 |
| defaultPreload | `'intent'` | `preload-intent` |
| defaultPreloadStaleTime | `0`（可 T3 再调） | `preload-stale-time` |
| scrollRestoration | `true` | `router-default-options` |
| Register | 全局 router 类型 | `ts-register-router` |

**不负责：** path 语义、恢复规则、页面 UI、Query 默认 stale（bootstrap）。

### 3.2 `routes/**` 只做什么

| 允许 | 禁止 |
|------|------|
| file route 声明、pathless `_shell` | 自建最近浏览列表 |
| `loader` / `beforeLoad` redirect | 直接读写 Tauri Store 导航 key |
| `validateSearch` + 默认值 | 手搓复杂业务 path（应走 intents/routePaths） |
| `ensureQueryData(public queryOptions)` | 厚业务 UI（>薄组合） |
| 薄页：facade hook + layout EntityScene 填槽 | 裸 `invoke` |
| `useRememberCurrentShellRoute` 在 **scope layout** | 在每个叶子重复 remember |
| errorComponent / notFound | 第二套 history store |

**薄页模板（目标）：**

```tsx
// routes/_shell/all/inbox/index.tsx（示意）
export const Route = createFileRoute('/_shell/all/inbox/')({
  component: InboxRoute,
})

function InboxRoute() {
  const scene = useTaskListScene({ scope: 'inbox' }) // feature public
  return (
    <EntityScene board={<TaskBoard {...scene.boardProps} />} />
  )
}
```

列表页 **无强制 loader**（数据可在 facade 内 useQuery）；**详情 / 启动** 必须用 loader 预热或校验。

### 3.3 `app/navigation/**` 只做什么

| 文件（沿用） | 职责 |
|--------------|------|
| `shellRoute.ts` | URL → `AppRoute` / `ShellRoute`（纯） |
| `scope.ts` | route → `Scope`（纯） |
| `routePaths.ts` | canonical path 拼接（纯） |
| `intents.ts` | 业务意图 → path / navigate 目标 |
| `routeMemory.ts` | 记忆 normalize/validate/启动解析（纯规则 + 校验端口） |
| `routeMemoryStore.ts` | Tauri Store I/O 唯一边界 |
| `useRememberCurrentShellRoute.ts` | layout/route 调用的写记忆 hook |
| `sessionRouteHistory.ts` | 会话最近浏览 + back/forward 可用性 |

**不负责：** 侧栏 DOM、Query 缓存策略、实体业务规则（校验「是否存在」可调 api，但规则表在 navigation）。

**依赖方向目标：**

```txt
navigation → shared（类型/工具）
navigation → features/*/public 或 api 端口（实体校验、settings section key）
navigation ↛ layout 重 UI   （渐进：session 标签解耦）
features → navigation/intents、scope（允许）
layout → navigation（parse、sessionHistory、intents）
routes → navigation（startup、remember、detail helpers 用 intents）
```

### 3.4 `layout/**` 在导航中的角色

| 做 | 不做 |
|----|------|
| 渲染侧栏/顶栏；调用 intents | 实现 `isRememberableShellPath` |
| 装配 sessionHistory 到 Header | 读写 `shell.navigation.restore` |
| scope 展示与切换 UX | 复制 parseShellRoute 分叉逻辑 |

### 3.5 业务只发 intent

| 场景 | 调用 |
|------|------|
| 打开任务 | `openTaskDetail` / 等价 intent |
| 打开项目 | `openProjectDetail` / `openCanonicalProjectDetail` |
| 切 section | `openSection` |
| 开设置 | `openSettings` |
| 开视图 | `openView` |
| 命令板导航目标 | `openShellNavigationTarget` |

新增导航入口时：**先加 intent + routePaths + shellRoute 识别**，再挂 UI。

## 4. Loader 与 Query 边界

### 4.1 何时必须 loader

| 场景 | loader 职责 | BP |
|------|-------------|-----|
| 启动 `/` | spaces + resolveStartupPath + redirect | `load-use-loaders` |
| Task/Project 详情 | `ensureQueryData` detail + space 一致性 redirect | `load-ensure-query-data` · `ts-query-options-loader` |
| 依赖「实体必须存在才渲染」的页 | ensure + 错误映射 | `load-error-handling` |

### 4.2 何时可省略 loader

| 场景 | 做法 |
|------|------|
| Inbox / All Tasks 等列表 | facade `useQuery`；可选 intent preload 已预热 |
| Settings section | 无实体预取；非法 section redirect 即可 |
| QC | 窗级自有数据，不走主壳 loader |

### 4.3 ensureQueryData 规则

```txt
✅ loader 内：
   queryClient.ensureQueryData( taskDetailQueryOptions(id) )  // 从 feature public/hooks 导出

❌ loader 内：
   手写 queryFn 调 invoke
   大段业务 if/else（除 redirect 条件）
   写入 Zustand「当前任务」作为导航真相
```

**queryOptions 归属：** `features/<entity>/hooks`（或过渡期 `query/`），经 **public** 给 routes 用。

### 4.4 并行与 waterfall

- 独立 ensure **并行**（`Promise.all`）——对齐 Vercel `async-parallel` 与 Router `load-parallel`。  
- 详情依赖 spaces 列表时：先 spaces（或并行 pull 后校验），避免重复串行无缓存请求。  
- 非关键数据：**不要**堵在关键 path 的 loader 里（`load-deferred-data` 精神）。

### 4.5 Detail helpers 位置

| 现状 | 目标 |
|------|------|
| `routes/_shell/-detail-route-helpers.tsx` | **可保留在 routes 旁**（`-` 前缀 colocated），因强绑 route redirect 形状 |
| 过厚时 | 校验纯函数下沉 feature hooks；redirect 仍留 routes |

不把 detail redirect 逻辑塞进 `shared`。

## 5. Search 与 Params 契约

### 5.1 原则

- **凡进 URL 的 search 必须 `validateSearch`**（`search-validation`）。  
- 提供 **defaults**（`search-defaults`）。  
- 类型从 route 推断；消费用 `Route.useSearch()` / `from` 收窄（`ts-use-from-param`）。  
- 抽屉/模态若用 search：与 path 职责划清，避免同一事实 path+search 双写。

### 5.2 已知 / 目标契约表

| 区域 | 载体 | 契约要点 | 备注 |
|------|------|----------|------|
| **Task / Project 详情** | **path params** | `spaceId` + `taskId` / `projectId` | 主详情以 path 为准（As-Is） |
| **Settings** | **path param** `section` | 枚举 `SettingsSectionKey`；非法 → 默认 section | 非 search |
| **Activity debug** | **search** | entityType / id / limit 等 normalize | `routes/-activity-debug-search.ts` |
| **Drawer 式 task/project** | 若未来/已有 search 键 | 必须 validate；与 path 详情二选一为真相 | T2：**不新增**第二套未校验 search；产品若用 drawer 须单独立项 |
| **QC** | 窗路由为主 | 不进主壳 search 契约 | |

> Gap/讨论中的「抽屉 task/project search」：以**代码现存 validateSearch 为准**；目标原则是「有 search 必校验」。Migrate 若统一 drawer，单独立项，不在 T2 发明键名。

### 5.3 Params

- 动态段与 `routePaths` / intents **同一套 canonical**。  
- space 与实体 space 不一致 → **redirect replace**，不渲染错误 space 下的「假成功」。

## 6. 路由树目标形态（心智 · 非搬家表）

```txt
routes/
  __root.tsx                 # error/notFound 壳；Outlet
  index.tsx                  # / 启动恢复
  quick-create.tsx
  settings.tsx               # legacy → all settings
  debug.activity.tsx
  -*.ts(x)                   # colocated 非路由
  _shell/
    route.tsx                # pathless → AppLayout + Outlet
    -scoped-shell-route-layout.tsx
    -detail-route-helpers.tsx
    all/
      route.tsx              # scope=all + remember
      inbox/ index…          # 薄页（可逐步由 .tsx 文件迁到目录 index）
      tasks/ …
      projects/ …
      views/ …
      settings/ …
      …
    spaces/
      $spaceId/
        route.tsx            # scope=space + remember
        …对称叶子
```

**org- BP：**

- `org-file-based-routing`：继续 file routes  
- `org-pathless-layouts`：`_shell`  
- `org-index-routes`：`/all/` → tasks；`/spaces/:id/` → inbox  
- 空目录 `routes/debug`、`routes/spaces`（若仍在）：Migrate **删除**（KISS）

## 7. 导航 UX 规则（nav- / preload-）

| 规则 | 目标 |
|------|------|
| 声明式跳转 | 优先 `<Link>`（`nav-link-component`） |
| 命令式 | `useNavigate` + 来自 intents 的 path（`nav-use-navigate`） |
| 激活态 | 侧栏用 Router active / 或 parseShellRoute 比较 canonical（`nav-active-states`） |
| Preload | 保持 intent；重页可对 Link 依赖 loader（`preload-intent`） |
| 遮罩路由 | 若 modal URL 需要再开 `nav-route-masks`；**当前不强制** |

## 9. 变更检查清单（目标开发纪律）

新增或修改导航时：

```txt
[ ] shellRoute 能 parse
[ ] routePaths 能生成 canonical
[ ] intents 有对应意图（业务入口走 intent）
[ ] routeMemory：是否 rememberable 已显式决定
[ ] sessionHistory：展示名是否需要 layout 配置
[ ] 详情：loader ensure + space redirect
[ ] search：有则 validateSearch + defaults
[ ] 无 features 写 history；无 shared 写导航 Store
[ ] bun run check（typecheck/lint/test navigation）
```
