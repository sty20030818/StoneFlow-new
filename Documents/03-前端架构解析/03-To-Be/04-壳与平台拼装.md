## 1. 目标结论（先读这段）

**As-Is 问题一句话：** `ShellLayout.tsx` ~1271 行 = Provider 树 + Command 巨型 actions + bulk 接线 + Chrome + Overlays + 业务旁路，**删/换任一平台能力都要改巨石**。

**To-Be 一句话：** 壳是 **薄编排 + 注册表装配**；能力来自 feature **public**；命令实现是 **可组合 slices**，不是焊死在 layout 的 34 方法接口实现体。

```txt
目标装配栈（主窗工作路径）

app/bootstrap          QueryClient · AppProviders（Tooltip/Toaster）
routes/_shell/*        scope · remember · 一行挂 AppLayout
layout/
  ShellRouteBoundary   workspace sync · nav 衍生 store · ShellRouteProvider · 非法 space
  ShellProviders       仅嵌套 platform Providers + bulk 注入点
  command-bridge/      组合各 feature 提供的 command slices → runtime
  AppLayout / chrome   Header · Sidebar · Main(Outlet) · Footer
  overlays/            创建弹窗 · 危险确认宿主 · Update · 系统状态等挂载
  entity-scene/        零业务槽位（页内使用）

features/*             实现 + index.public 导出「可注册面」
```

**QC 窗：** 不挂本栈；仅用 app bootstrap 子集 + 自有 runtime。

## 2. Provider 树：全局 vs Shell-only

### 2.1 全局（所有窗 / 全路由）

| Provider / 能力 | 位置（目标） | 为何全局 |
|-----------------|--------------|----------|
| `QueryClientProvider` | `app/bootstrap` / App | 数据缓存；与 Router context **同实例** |
| `TooltipProvider` | `app/bootstrap` AppProviders | 横切 UI |
| `Toaster` | 同上 | 横切反馈 |
| Router | `RouterProvider` | URL 真相 |

**禁止**再往全局塞：selection、bulk、command runtime、page filter、task preview（QC 与 debug 不需要，且增加耦合）。

### 2.2 Shell-only（仅主工作区铬架）

| Provider | 来源 feature（概念） | 装配位置 | 暴露约定 |
|----------|----------------------|----------|----------|
| CommandSelection | selection | `layout/ShellProviders` | state/actions/meta |
| SubmitRegistry | submit | 同上 | 注册/解析提交目标 |
| PageFilter | filter | 同上 | 页筛选 |
| DangerConfirm | danger-confirm | 同上 | confirm() Promise API |
| TaskPreview | task（detail） | 同上 | 预览开关与目标 |
| BulkAction | bulk-action | 同上 + **adapters 注入** | runner + adapter |
| Sidebar（几何） | shared/components | chrome 内层 | 折叠/宽 |
| SyncStatus | sync | chrome 内层（Footer） | 状态展示 |
| ShellRoute | layout boundary | `ShellRouteBoundary` | 当前 ShellRoute 快照 |
| Command runtime / shortcut layer | command | bridge 旁，非全局 | 执行与快捷键 |

顺序目标（可微调，但**稳定且文档化**）：

```txt
ShellRouteProvider                    # 最外：当前 route 语义
  CommandSelectionProvider
    SubmitRegistryProvider
      PageFilterProvider
        DangerConfirmProvider
          TaskPreviewProvider
            BulkActionProvider(adapters from public)
              SidebarProvider
                SyncStatusProvider
                  CommandShortcutLayer   # 读 bridge + selection
                  Chrome + Main(Outlet)
                  Overlays
```

### 2.3 不在 Provider 树的东西

| 项 | 做法 |
|----|------|
| 导航恢复 Store | `app/navigation`，非 React Provider |
| Entity 列表数据 | Query hooks，页内订阅 |
| God `shellCommandActions` 单对象 | **拆 slices** 后由 bridge 聚合 |

## 3. 四块职责：Providers · Bridge · Chrome · Overlays

### 3.1 总览

| 块 | 目标路径 | 负责 | 不负责 |
|----|----------|------|--------|
| **ShellProviders** | `layout/ShellProviders.tsx`（名可变） | 嵌套 Provider；接收 bulk adapters / 可选 slots | 实现命令业务、画侧栏 DOM |
| **CommandBridge** | `layout/command-bridge/` | 把各 feature **public slices** 打成 runtime 所需 actions；接线 `useCommandRuntime` | 具体「归档任务」算法（在 task public） |
| **Chrome** | `layout/header|sidebar|…` · `AppLayout` | 视觉铬架；读 intents / sessionHistory / route | invoke、巨型 useMemo actions |
| **Overlays** | `layout/overlays/` | 挂载创建对话框、Update、系统芯片等 **宿主** | 对话框字段业务（feature components） |
| **EntityScene** | `layout/entity-scene/` | 主区槽位编排 | Task DTO / Query |

**薄编排根（取代 1271 行巨石）：**

```tsx
// 示意：layout/AppShell.tsx
export function AppShell({ children }: { children: React.ReactNode }) {
  return (
    <ShellProviders bulk={bulkRegistration}>
      <CommandBridgeHost />
      <AppLayout
        header={<ShellHeader />}
        sidebar={<ShellSidebar />}
        footer={<ShellFooter />}
        overlays={<ShellOverlays />}
      >
        {children}
      </AppLayout>
    </ShellProviders>
  )
}
```

### 3.2 CommandBridge（灭 PLAT-D2）

**As-Is：** `ShellCommandActions` ~34 方法一整段 `useMemo` 焊在 ShellLayout。

**To-Be：**

```txt
features/command          → 定义 Command 类型、runtime、菜单 UI、**actions 接口的窄协议**
features/task|project|…   → public 导出 commandSlice / handlers（或 register 函数）
layout/command-bridge     → composeSlices([...]) → useCommandRuntime({ actions })
```

| 规则 | 说明 |
|------|------|
| 壳 **不**实现领域命令体 | 只组合 |
| 新命令 | feature 内加 handler + 在 bridge **显式注册一行**（或 feature public 的 `getCommandSlice()`） |
| 删除 feature | 去掉注册行 + public；**不**改 bridge 内核 |
| 与 RING-CMD | 实现依赖单向：task public ← bridge；command **不** import task 私有 components |

**切片建议分组（逻辑，非强制文件名）：**

| Slice | 内容来源 |
|-------|----------|
| `navSlice` | navigation intents |
| `taskSlice` | task public |
| `projectSlice` | project public |
| `bulkSlice` | bulk-action public |
| `filterSlice` | filter public |
| `submitSlice` | submit public |
| `spaceSlice` | space public（CRUD 入口） |

接口形状字段级可在 Migrate 定；T4 冻结 **组合模式** 而非 34 字段清单。

### 3.3 Bulk / Submit / Selection / Filter 注册

| 能力 | 注册方式 | 壳侧 |
|------|----------|------|
| **Selection** | 页/board 向 context 注册当前选择 | Provider 只持注册表 |
| **Submit** | 表单/详情注册 submit target | 命令「保存」走 registry |
| **Filter** | 页注册 page filter | 命令与 UI 读 context |
| **Bulk** | 壳注入 **adapters**（task/project/lifecycle）来自各 feature public | `BulkActionProvider` 不 hardcode 实体规则 |
| **DangerConfirm** | 调用方 `confirm(options)` | 宿主 Dialog 在 overlays 或 provider 内 |

**反模式：** 在 Chrome 里 `if (section === 'inbox')` 写死 bulk 行为。

### 3.4 Chrome

| 子块 | 职责 |
|------|------|
| Header | 标题、back/forward（sessionHistory）、搜索触发、命令板入口 |
| Sidebar / SettingsSidebar | 导航 intents；读 route 衍生状态 |
| Main | `Outlet` / children |
| Footer | sync 状态、版本等 |

**Header 重 props（SHELL-D7）：** 目标用 **compound / 分区子组件 + context**，禁止继续堆 boolean 与 20+ props（Composition `architecture-avoid-boolean-props`）。

**config 体积（SHELL-D8 / NAV）：** 导航标签/图标配置留 layout 或 `layout/config`；**navigation 语义模块不依赖重 UI config**（T2 已记渐进 Fix）。

### 3.5 Overlays

| 挂载 | 实现归属 |
|------|----------|
| 创建 Task/Project 对话框壳 | overlays 宿主；字段/提交 **feature** |
| CustomDate 等 | 同上 |
| Update 对话框 | update feature UI + 壳挂载 |
| SystemStatusChip | 薄；数据来 sync/update public |
| Command 菜单 UI | command feature；由 shortcut/runtime 打开 |

**create-dialog 迁出 shared（SHR-D1）：** 宿主进 `layout/overlays` 或 feature；shared 只留纯无业务零件。

### 3.6 EntityScene / MainCard（回顾）

| 部件 | 位置 |
|------|------|
| MainCard | `shared/components` |
| EntityScene | `layout/entity-scene` |
| Board | `features/*/components` |
| list-scene 数据 | `features/task/hooks` |

页：`routes` 薄页填槽，**不**在 layout 写列表 Query。

## 5. Composition 对齐

| 规则 | 壳上落地 |
|------|----------|
| 组合 > 布尔扩展 | Header/Sidebar 用子组件与 slot，不用 `showX &&` 参数爆炸 |
| Provider 接口 | 一律 `state` / `actions` / `meta`（稳定引用） |
| children 组合 | AppLayout `children` = 主区；overlays 并列 slot |
| 显式变体 | Settings 模式用 `SettingsSidebar` 变体，而非 Sidebar 上堆 settings boolean |
| 无组件内子组件 | Chrome 文件拆分，避免 ShellLayout 内联 10 个 function 组件长期堆积 |

## 6. 新平台能力接入检查清单

新增「全局壳能力」（命令、快捷键、批量、全局弹层、状态条…）时：

```txt
[ ] 1. 是否真需要 shell-only Provider？能页内 local 则不要抬到壳
[ ] 2. 能力实现是否在 features/<name>/ 且仅 public 外露？
[ ] 3. 若需命令：是否提供 slice / handlers，而非改 bridge 内核算法？
[ ] 4. 是否在 layout 注册表 / ShellProviders 增加**一行**装配（非复制 200 行进 Chrome）？
[ ] 5. QC 是否必须？默认否；是则 QC 独立 public，不挂主壳 Provider
[ ] 6. 是否引入 layout → feature 私有路径？禁止
[ ] 7. 是否 shared 反向依赖？禁止
[ ] 8. 删除该 feature 时：注册行 + route（若有）是否足够？写进 public 旁删除清单
[ ] 9. Provider 是否只暴露 state/actions/meta？
[ ] 10. bun run check；必要时补壳行为冒烟（命令开、bulk、侧栏）
```

**禁止默认动作：** 「先写在 ShellLayout 底部，以后再拆」。

## 7. 与 app / routes / features 的边界

| 从 | 到 | 规则 |
|----|-----|------|
| layout | features | **仅 public** |
| layout | app/navigation | 纯语义、intents、sessionHistory OK |
| layout | shared | 纯 UI OK |
| features | layout | **禁止** |
| routes | layout | 挂 AppShell / EntityScene OK |
| app/bootstrap | layout | 不强制；壳由 route 挂载 |
