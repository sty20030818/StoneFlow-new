## 1. 目标

把 `ShellLayout.tsx`（~1271 行）从「上帝文件」拆成 **可独立打开的装配块**，命令动作从「单文件巨型 `useMemo<ShellCommandActions>`」变为 **可组合 bridge + 明确切片**。

**本史诗结束时：**

1. `ShellLayout.tsx`（或等价 `AppShell.tsx`）**≤ ~150–200 行**，只做编排 `Providers → BridgeHost → Chrome → Overlays`。  
2. Provider 嵌套 + bulk adapters 在独立文件。  
3. `ShellCommandActions` 的实现在 `command-bridge/`（可先仍是「切片函数返回 Partial 再 merge」，不必一次改 command feature 公共协议）。  
4. 创建弹窗 / CustomDate / Update / StatusChip 在 `overlays/` 宿主组件。  
5. 行为与 M-2 前一致；`bun run check` 绿；主窗冒烟通过。  

**目录策略（本刀）：** 仍在 `src/app/layouts/shell/` 下拆分，**不**强制本刀完成 `src/layout/` 顶层搬家（可列为 M-2 后或 β 命名史诗）。命名可先用 To-Be 概念：

## 4. 子切片（强制顺序）

### PR-A · 物理拆分 · **行为零变**

**目标：** 只搬家，不改逻辑字符串。

| 步骤 | 内容 |
|------|------|
| A1 | 抽出 `ShellProviders.tsx`：现 `ShellLayout` 的 Provider 嵌套 + children 插槽 |
| A2 | 抽出 `bulk/useShellBulkRegistration.ts`（或 `ShellBulkActionBoundary.tsx`）：现 BulkActionBoundary 全文 |
| A3 | 抽出 `ShellLayoutContent.tsx`：现 Content 全文（含 command useMemo 与 JSX） |
| A4 | `ShellLayout.tsx` 变为：`Providers → BulkBoundary → Content` 三行级编排 |
| A5 | `bun run check`；冒烟 §7（全套） |

**验收 A：** 行数从 Content 文件体现；`ShellLayout.tsx` 明显变短；**git diff 逻辑应极少**（主要是 import/export）。

**回滚：** revert PR-A。

---

### PR-B · CommandBridge · **抽 actions，接口可暂不变**

**目标：** 消灭「Content 内 300+ 行 actions useMemo」；仍实现同一 `ShellCommandActions`。

| 步骤 | 内容 |
|------|------|
| B1 | 建 `command-bridge/useShellCommandBridge.ts`：输入 shell 所需 deps（navigate、stores、bulk runner、preview、filter…），输出 `{ actions, … }` 或直接 `ShellCommandActions` |
| B2 | **推荐先**整段剪切 useMemo 进 bridge 单文件（行为锁），再 **B3** 按域切 `slices/*` |
| B3 | ✅ 已落地 `slices/{menu,create,layer,submit,nav,preview,filter,taskMeta,bulk}` |
| B4 | ✅ `composeShellCommandActions` + DEV 缺字段断言 |
| B5 | Content 只：`const actions = useShellCommandBridge(deps)` → `useCommandRuntime` |
| B6 | 可选：command 根 barrel 去掉 `export *`（PLAT-D1）— **仅当不影响测试/import** |
| B7 | `bun run check` + 命令冒烟（§7.2 命令专表） |

**B 阶段 deps 注入纪律：**

- bridge **可以** import dialog store、navigation intents、bulk、filter（壳装配层合法）。  
- **不要**在 bridge 里新写 board/Query 列表逻辑。  
- 新增命令：优先新 slice 文件 + compose 一行，**禁止**再把 50 行塞回 Content。

**验收 B：** Content 内无 `useMemo<ShellCommandActions>` 大块；快捷键/命令板/归档删除/提交/筛选与拆前一致。

**回滚：** revert PR-B（A 可保留）。

### PR-C · Overlays + 薄编排定型

**目标：** Chrome 与 Overlays 分离；ShellLayout 薄。

| 步骤 | 内容 |
|------|------|
| C1 | 建 `overlays/ShellOverlays.tsx`：CreateDialogShell 宿主、CustomDateDialog、UpdateDialog、SystemStatusChip（及仅壳挂载的层） |
| C2 | Content 保留：SidebarProvider 树、Header/Sidebar/Main、CommandShortcutLayer、command menu 入口若绑在 chrome |
| C3 | 梳理 props：Overlays 需要的 open/close/space 状态从 Content 传入或读 store（**优先 store/selectors**，减 prop 钻） |
| C4 | `ShellLayout.tsx` 最终形： |

```tsx
export function ShellLayout(props) {
  return (
    <ShellProviders>
      <ShellBulkBoundary {...scopeProps}>
        <ShellCommandBridgeHost {...}>  {/* 或 Content 内调 bridge */}
          <ShellChrome {...}>
            {children}
          </ShellChrome>
          <ShellOverlays />
        </ShellCommandBridgeHost>
      </ShellBulkBoundary>
    </ShellProviders>
  )
}
```

（具体组件名可微调；**职责**对齐 Providers / Bridge / Chrome / Overlays。）

| C5 | 更新 `ARCHITECTURE.md` 一小节「M-2 后文件图」 |
| C6 | 全量 check + §7 冒烟 |

**验收 C：** 打开 `ShellLayout.tsx` 可一屏读完编排；Overlays 文件独立；无行为回归。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 拆文件漏闭包依赖导致 runtime undefined | A 先整文件搬；B 整段 actions 再切；每 PR 全量测试 |
| hooks 顺序变化 | 不改变 Provider 嵌套顺序（T4 表） |
| 命令 enabled 变 false | 对比 `shell-command-adapter.test` + 手工命令板 |
| 循环依赖 shell ↔ command | bridge 单向：shell → command runtime；command **不** import ShellLayout |
| 大 diff 难 review | **强制 3 PR**；A 纯移动用 `git mv` 痕迹清晰 |
