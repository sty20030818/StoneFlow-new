# 装配三角 · 纯化优化清单（navigation / routes / layout）

> 2026-07-17  
> 前提：**T2** + 全模块纯化规范（[`05-模块设计规范.md`](./05-模块设计规范.md)）  
> 作用：在「可以破坏」前提下，列出 **还可以优化什么**、**怎么和别的模块协作**；供后续改造排期，不立刻写代码。

---

## 1. 总优化方向

| 方向 | 含义 |
|------|------|
| **减职责** | 任何「顺手做的业务」迁出 |
| **减重复** | 双树、双 path、双命令入口合并 |
| **减真相** | 可写 nav store、镜像路由一律压掉 |
| **减上帝** | Bridge 切片中心 → 注册式 |
| **加端口** | ShellContext、path 方言、public 显式化 |
| **加协作契约** | 谁注册、谁挂载、谁 navigate 写进规范 |

## 2. navigation · 还能优化什么

### 2.1 已对齐的目标

- 只做：parse · build path · 纯 intent · memory · session history  
- 大文件拆分（shellRoute / routeMemory / sessionHistory）  
- 业务策略（openTask 方式等）→ domain  

### 2.2 额外优化点

| ID | 优化 | 协作影响 | 优先级 |
|----|------|----------|--------|
| N-opt-1 | **Intent 分级**：`path-only` vs `policy`；policy 禁止留在 navigation | task/project/settings 提供 policy API | P0 |
| N-opt-2 | **单一 Path API 面**：文档化「只允许从这些函数生成工作区 path」；ESLint 可扫字符串 `'/all/'` `'/spaces/'`（可选） | layout/command/feature 一律改调用 | P1 |
| N-opt-3 | **parse 结果缓存 hook**：`useShellRoute()` 读 router state + parse，替代可写 nav store | layout 高亮/传参只读此 hook | P0（配合去 store） |
| N-opt-4 | **Memory 与 History 零交叉**：测例锁定「前进后退不写 Store」 | Header 只绑 session API | P0 已接近，保持 |
| N-opt-5 | **面包屑数据注入接口**固定：`resolveBreadcrumb({ route, labels })`，labels 由 layout/feature 填 | project/task 提供 title；navigation 不 Query | P1 |
| N-opt-6 | **与 Router 类型对齐**：canonical path 与 file route `to` 逐步可推导，减少 magic string | routes 改树时同步 path builder | P1（单树后做） |
| N-opt-7 | settings 分区读写继续 **仅 contract**，navigation 不依赖 settings 整包 | settings 三入口保持 | 已部分做到 |

### 2.3 navigation 协作契约（目标）

```txt
任何换页：
  caller → navigation.build*|open*（path-only）→ router.navigate|redirect|Link

需要「当前语义」：
  useShellRoute() / parseShellRoute(location)  （只读）

需要记路径：
  仅 scope route 调 useRemember* ；规则在 navigation
```

**禁止：** feature 内 `navigate('/spaces/'+id+...)`；layout 写 memory Store。

## 3. routes · 还能优化什么

### 3.1 已对齐的目标

- 薄页、loader 门闸、单工作区树、旧 URL redirect  
- 详情 ensure 用 feature queryOptions  

### 3.2 额外优化点

| ID | 优化 | 协作影响 | 优先级 |
|----|------|----------|--------|
| R-opt-1 | **Route Context 承载 scope + shellRoute**（或 scope + 派生）供 layout/loader 共用 | 减少 props 层层传；layout 读 `Route.useRouteContext()` | P0（单树时一并做） |
| R-opt-2 | **叶子模板代码生成或共享 factory**（在单树前可先减 all/spaces 复制） | 降低漏改 | P1 过渡 |
| R-opt-3 | **search 全面校验**（zod）：settings section、entity drawer、debug | entity-detail / settings contract | P1 |
| R-opt-4 | **loader 错误与 intents 回退 path 统一** | navigation fallback helpers | P1 |
| R-opt-5 | **pending/error UI** 收到 `routes/-feedback` 或 shared 模式组件 | 视觉一致 | P2 |
| R-opt-6 | **lazy route** 对 settings/QC/重页 | 首屏 | P2 |
| R-opt-7 | **ensure\*Route 下沉 feature public**（可选）：`task.ensureDetailRouteData` | routes helper 更薄；门闸规则与领域同处 | P1 |
| R-opt-8 | 产品钉死：**all 是否提供 task detail 叶**；目标树一次设计 | task / navigation path | 讨论项 |

### 3.3 routes 协作契约（目标）

```txt
routes 薄页 → 只 import feature page/public + navigation
loader → feature queryOptions / ensure* public
redirect → navigation path 或 Router 相对 to
layout 挂载 → 单一 Shell 入口读 route context
```

**禁止：** route 文件 200 行业务；loader 裸 invoke；深路径 feature。

## 4. layout · 还能优化什么

### 4.1 已对齐的目标

- 保留铬架分层；去掉业务 Bridge 中心；ShellContext；巨石拆文件；Settings 内容外迁  

### 4.2 额外优化点

| ID | 优化 | 协作影响 | 优先级 |
|----|------|----------|--------|
| L-opt-1 | **ShellContext 正式化**：`{ scope, shellRoute, capabilities? }` 只读；替代散落 props + 可写 nav store | 全壳与注册命令的 ctx | P0 |
| L-opt-2 | **Command 宿主极薄**：只挂 Runtime/Menu/ShortcutLayer + `getContext()` | command feature；handlers 在 domain | P0 |
| L-opt-3 | **Overlay 注册表**（可选进阶）：feature 注册「可挂载 overlay id」；壳只 map 渲染 | QC 除外；创建/更新对话框 | P2 |
| L-opt-4 | **Sidebar 数据门面**：`useShellChromeData` 严格 facade；菜单动作 100% intent/public | project/space/lifecycle public | P0 |
| L-opt-5 | **徽章/偏好** 只走 settings/task 等 Query API（已刀过的保持） | settings | 保持 |
| L-opt-6 | **EntityScene adapters** 仅映射 props→feature Board；零额外业务 | task/project/lifecycle boards | P1 |
| L-opt-7 | **目录 L-C**：`chrome/` `bridge-host/` `overlays/` 物理归位 | 可随拆文件 | P1 |
| L-opt-8 | **禁止 layout 测业务规则**；测装配与「点击调用了 intent」 | 测试策略 | P1 |
| L-opt-9 | Provider 树 **排序文档化**（selection→submit→filter→danger→preview→bulk） | 避免乱序回归 | P1 |
| L-opt-10 | Footer/Sync/Update **只挂 public 组件** | sync/update feature | 已大致如此 |

### 4.3 layout 协作契约（目标）

```txt
layout ──ShellContext──► 注册中的 feature handlers / 子树
layout ──intent──► navigation ──► Router
layout ──public hooks──► 侧栏数据
feature ──register(commands|overlays)──► platform/command 或 shell host
feature ──×──► layout（禁止）
```

## 5. 三角之间 + 对外模块 · 协作矩阵

| 场景 | navigation | routes | layout | 其他 feature |
|------|------------|--------|--------|----------------|
| 冷启动 | memory 解析 path | index redirect | 尚未挂或挂恢复后壳 | space 列表 ensure |
| 侧栏导航 | build path | 匹配薄页 | Sidebar 触发 intent | — |
| 命令改状态 | 一般不换页 | — | 宿主 context | **task 等 handler** |
| 命令打开实体 | path-only | 详情 loader | — | **policy 在 domain** 再调 path |
| 列表页 | — | 薄挂载 | EntityScene 槽 | **list-scene wiring** |
| 创建任务 | 可选跳转 path | — | Overlay host | **TaskCreateContent** |
| 设置 | section path | settings 叶 | mode 骨架 | **settings page/panels** |
| 抽屉 | search 契约可在 entity-detail | 可选 search validate | Drawer 壳 | **entity-detail + task/project** |
| 卸载 task | 无强依赖 | 删 task 叶 | 摘注册/摘菜单项数据源 | 删 feature |

## 6. 纯化「完成」定义（装配三角）

三角可称为 **目标态达标** 当且仅当：

1. navigation **无** domain 策略代码；path 单入口习惯形成  
2. routes **单树**（或已排期最后一刀但设计冻结）；叶子薄；loader 只门闸  
3. layout **无** 业务 command slice 表；有 ShellContext；铬架巨石 &lt; 门禁或拆完  
4. 任意新 feature 可按 [`05-模块设计规范`](./05-模块设计规范.md) 自注册协作，**不必改 navigation 核心**  
5. 规范与 ARCHITECTURE/CONVENTIONS 已交叉链接
