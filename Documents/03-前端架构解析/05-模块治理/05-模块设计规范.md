## 1. 总则（一句话）

```txt
每个模块只干一类事；对外只开最小门面；依赖只指向更稳定侧；
状态分轨（URL / Query / UI）；壳装配不拥有领域；可删、可测、可组合。
```

| 词 | 要求 |
|----|------|
| **纯化** | 模块内无「顺手塞」的跨职责代码；灰区写清迁出方向 |
| **职责单一** | 改需求时，默认只动一个模块 |
| **高内聚** | 相关规则/IO/UI 垂直放在同一 feature 内 |
| **低耦合** | 跨模块只经 public / intent / context 端口 |
| **可删除性** | 卸模块 = 摘薄页 + 摘注册 + 摘壳挂载，不改他人私有 |

## 2. 模块类型与职责（唯一分类）

| 类型 | 放哪 | 只负责 | 禁止 |
|------|------|--------|------|
| **domain** | `features/*` | 实体/聚合：model·api·hooks·components | 主壳骨架、全局命令 runtime 框架 |
| **platform** | `features/*` | 跨页能力（command runtime、selection…） | 某实体的完整列表业务 |
| **scene** | 薄 `features/*` 或仅 routes | 厚页 UI；数据仍走 domain public | 私有 api 深路径给别人 |
| **window** | `features/*` + 独立 route | 独立窗完整栈 | 共享 main layout store |
| **composition** | `app/*` | 启动、Provider 工厂、**导航方言** | 业务 UI、实体规则 |
| **chrome** | `layout/*` | 铬架、宿主、ShellContext | 业务命令实现表、实体策略 |
| **routing** | `routes/*` | 匹配、loader 门闸、薄挂载、redirect | 厚业务、壳 UI |
| **shared** | `shared/*` | 无业务归属的零件/工具 | 实体规则、import features/layout/app |
| **styles** | `styles/*` | token / 全局样式 | 业务逻辑 |

**新增代码先选类型，再选目录。** 选不出来 = 设计未完成，禁止先建夹再想。

## 3. Feature 内部四层（domain/platform 强制心智）

```txt
components  →  hooks  →  api  →  model
     └────────── shared（仅工具/纯 UI）
```

| 层 | 纯化标准 |
|----|----------|
| **model** | 类型、纯规则、ports；无 React、无 `@tauri` |
| **api** | 仅 IO：invoke / Store / listen / DTO 映射 |
| **hooks** | Query/Mutation/facade；编排用例 |
| **components** | 只渲染；调本模块 hooks 与 shared |
| **public** | `index.ts`（+ 可选 contract/page）；**显式 export**；禁止 `export *` 扫树 |

跨 feature：**只** `@/features/<name>` 或 `/contract` `/page`。
校验：`bun run lint:boundaries`。

## 4. 状态三轨（全模块）

| 真相 | 归谁 | 禁止 |
|------|------|------|
| 当前在哪 / 打开谁（导航向） | **URL**（Router path + validated search） | Zustand/Query 镜像官方路由 |
| 可回源数据 | **TanStack Query**（经 feature hooks） | store 复制列表当真相 |
| UI 瞬态 | local / 明确 Provider / 少量 scoped store | 塞进 Query；双写无主从 |

## 5. 端口与协作（怎么和别人合作）

### 5.1 允许的依赖方向

```txt
routes / app / layout  →  features(public) · navigation · shared
features/A             →  shared · features/B(public only)
layout                 →  navigation · features(public) · shared
features               →  navigation(intent/path) · 不 → layout
shared                 →  （无业务树）
```

### 5.2 协作端口一览

| 从 → 到 | 怎么连 | 例子 |
|---------|--------|------|
| UI/命令 → 换页 | **navigation intent / path builder** → Router | `openSection` |
| 壳 → 业务 | **ShellContext**（只读 scope/route）+ 调 public | 侧栏要项目列表 → `useProjectSidebar…` |
| 业务 → 命令系统 | **feature 自注册** handler（T2） | task 注册 complete/archive |
| 路由 → 数据门闸 | loader + **feature queryOptions** | `ensureQueryData` |
| 页 → 列表架子 | feature list-scene + **EntityScene 槽位 props** | 不在 Scene 内拉全域业务 |
| 弹层 | layout **host** + feature **content 组件** | CreateDialogShell + TaskCreateContent |

### 5.3 禁止的协作

- feature import `layout/**`
- layout/routes 深路径进 feature 私有
- 两处手拼同一 path
- 命令在 Sidebar onClick 与 command 菜单各写一套业务
- shared 为「方便」吸收 task 规则

## 6. 装配三角目标（T2 摘要 · 纯化版）

详见 [`04-长期目标-装配三角.md`](./04-长期目标-装配三角.md)。

| 模块 | 纯化后一句话 |
|------|----------------|
| **navigation** | 产品路径方言 + 记忆 + 会话历史；**无业务策略** |
| **routes** | 单工作区树 + scope context + 薄页 + loader 门闸 |
| **layout** | 铬架 + 宿主 + ShellContext；**无业务 command 实现表** |

**命令：** feature 注册，不在 layout 堆 slices 上帝表。
**策略：** 如 openTask → 所在 domain public。
**双树：** 目标合并；旧 URL redirect。

## 7. 每个新模块 / 改造模块的设计检查表

设计或 PR 必须能回答（写在模块卡或 PR 描述）：

1. **类型**是表 §2 哪一类？
2. **一句话职责**与 **明确不负责**？
3. **public 最小集**（符号或分组）？谁消费？
4. **依赖谁 / 禁止依赖谁**？
5. **状态**走 URL / Query / UI 哪条？
6. **与壳/路由/导航**如何协作（若相关）？
7. 是否引入双真相、深路径、共享业务？
8. 体量：单文件是否可控（建议 &lt;300，硬顶 400）？
9. 删除该模块要动哪些装配点？

通不过 = 设计未完成。
