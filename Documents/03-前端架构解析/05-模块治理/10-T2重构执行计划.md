## 0. 工程约定（所有史诗）

### 0.1 分支命名

```txt
refactor/t2-00-prep
refactor/t2-01-dep-inv
refactor/t2-02-own-task
...
```

### 0.2 每 PR 注释/提交

- Commit 中文、说明史诗 ID 与目标码（如 `refactor(t2-01): 断开 feature→layout`）
- PR 描述贴：目标码、冒烟勾选、兼容窗是否引入

### 0.3 门禁

```bash
bun run check
```

含：typecheck · lint · **boundaries** · format · tests · rust。

### 0.4 代码注释纪律（本轮重构）

在**边界翻转处**加短注释，说明职责与原因（写清楚「为什么」）：

```ts
// 列表页不得 import layout；创建弹窗经 onRequestCreate 由壳注入。
```

禁止：

- 大段复述代码  
- **史诗号 / 目标码 / Phase / 试点 / 过渡期**（如 `C3`、`T2a`、`史诗 3`）——过程进度只写在**本执行计划**，不进 `src/**` 注释  
- 唯一例外：真正临时兼容层，且写明删除条件  

详见 `src/CONVENTIONS.md` §1。

### 0.5 架构文档纪律（每史诗必做）

完成一史诗代码门禁后：

1. 更新 **被改模块** 的 `src/**/ARCHITECTURE.md`（目录树、职责、public、装配；**用职责语言，不写史诗号**）  
2. **没有则新建** 短契约  
3. 回写 `src/ARCHITECTURE.md` 现网相关段（进度表只维护在**本执行计划**）  
4. 回写本执行计划该史诗「落地」表
