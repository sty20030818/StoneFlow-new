### 9.1 SHR-D1 · shared → app/features 反向依赖

| 字段 | 内容 |
|------|------|
| **标题** | `shared` 三处反向依赖 app/features，破坏分层防火墙 |
| **P / 严重度** | P0 / high（Critical 候选，**确认保持 P0**） |
| **维度主因** | 依赖健康（兼规范） |
| **阻碍可删除?** | **Y** — 无法假设「shared 可任意被依赖且无业务/壳耦合」；迁平台 feature 时 shared 仍勾住 app/features |

#### 证据（代码）

| 违规文件 | 依赖目标 | 消费者（生产） |
|----------|----------|----------------|
| `src/shared/ui/breadcrumbResolver.ts` | `@/app/layouts/shell/config`、`@/app/navigation/*`、`@/features/project/model/types` | inbox / all-tasks / no-project / views / project-overview / project / lifecycle / task detail 等 `resolveBreadcrumb` |
| `src/shared/ui/create-dialog-shell.tsx` | `@/features/metadata-fields` | **仅** `ShellLayout` → CreateDialogShell |
| `src/shared/form/use-submit-target-from-form.ts` | `@/features/submit/model` | TaskCreate / ProjectCreate / SpaceEditor / ViewEditor |

As-Is：`01-As-Is/07-shared-and-styles.md` §14、§2.7。

#### 爆炸半径

- **修 resolver：** 所有列表/详情 breadcrumb 调用点改 import 路径（约 8 个 feature 页）。  
- **修 create-dialog-shell：** 1 处 ShellLayout + 可能测试。  
- **修 submit form hook：** 4 个创建/编辑对话框。  
- **不修：** 任何「shared 边界 lint」无法落地；后续 shared 继续吸壳逻辑，分层债务复利。

#### 阻碍可删除性的机制

理想：删/换 metadata-fields 或改 navigation 语义时，**不应**碰到 `shared/`。  
现实：metadata 与 navigation 已嵌入 shared → 平台/壳变更 **强制** 改 shared → 全站 UI 消费者间接耦合。

#### 若修（候选方向 · 非搬家清单）

| 块 | 候选落点 | 留下 shared 的 |
|----|----------|----------------|
| breadcrumbResolver | `app/navigation/` 或 `app/layouts/shell/` | `AppBreadcrumb` 纯展示 |
| create-dialog-shell | `app/layouts/shell/` 或 `features` 装配 | `patterns/create-dialog` 纯 class |
| useSubmitTargetFromForm | `features/submit/` | `useZodForm` / normalize-error |

原则：**shared 零 `@/app` / `@/features` import**（可用 lint boundary 锁）。

#### 若不修

- 分层文档作假；AI/新人继续往 shared 塞壳逻辑。  
- To-Be「可删除平台 feature」在 shared 处永久漏气。  
- **不可接受为长期状态**；最多短期延后实现，不能标 wontfix。

### 9.2 SHELL-D1 · ShellLayout God composition root

| 字段 | 内容 |
|------|------|
| **标题** | `ShellLayout.tsx` ~1271 行集 Provider 嵌套、command bridge、bulk adapter、chrome、创建弹窗、sync/update 于一身 |
| **P / 严重度** | P0 / high（**确认保持 P0**） |
| **维度主因** | 可删除性 + 依赖（God 装配） |
| **阻碍可删除?** | **Y** — 删/换任一平台 feature 都要改此文件大段，而非「卸装配一行」 |

#### 证据（代码）

| 项 | 事实 |
|----|------|
| 体积 | `src/app/layouts/shell/ShellLayout.tsx` **1271** 行 |
| feature import 行 | **≥22** 条 `@/features/*`（command、bulk、selection、submit、filter、danger、task、project、space、lifecycle、entity-detail、metadata、global-search、settings、sync、update…） |
| Provider 栈 | Selection → Submit → Filter → Danger → TaskPreview → Bulk →（Content 内）SidebarProvider → Sync → ShortcutLayer + chrome + overlays |
| 命令桥 | `shellCommandActions` 巨型 useMemo（open*/submit*/bulk*/navigate*/filter*…）焊死 PLAT-D2 |
| As-Is | `01-As-Is/03` §3；`08` 枢纽表 |

#### 爆炸半径

- **任何** 主壳平台能力变更（command/bulk/filter/submit/preview/sync/update/create dialog）→ 本文件。  
- 测试：Shell 相关集成测全敏感。  
- 列表 scene **不**直接 import ShellLayout，但依赖其提供的 context；拆分不当会全壳挂。

#### 阻碍可删除性的机制

决策 2=A 要求：删 feature ≈ 卸装配点。  
现实：装配点不是「注册表一行」，而是 **内联 200+ 行 actions + 多处 JSX 插槽** → 等价于历史纠缠（`historical-tangle` + `god-assembly`），虽职责「该在壳里装配」正确，但 **形态** 不可演进。

#### 若修（候选方向 · 非搬家清单）

建议拆为（逻辑边界，非最终文件名）：

```txt
ShellProviders          # 仅嵌套 Provider + bulk adapter 注入
useShellCommandBridge   # shellCommandActions + runtime/runner 接线
ShellChrome             # Header / Sidebar|Settings / Main / Footer
ShellOverlays           # CreateDialog / CustomDate / UpdateDialog / chips
ShellLayout             # 薄编排：providers → chrome → overlays → children
```

约束：

1. **先**能把 Provider 树与 Content 拆文件，不改变行为（低风险）。  
2. Command bridge 与 PLAT-D2 **同波或紧随**（G2 深评后进同一 Migrate 史诗）。  
3. 禁止再往 ShellLayout 加业务分支；新能力走 registry/插件接口（To-Be 定）。

#### 若不修

- P1 的 command/bulk 收口无法「只改公开 API」——消费方仍是巨石。  
- 可删除性理想对平台 feature **永久不可达**。  
- 每次壳改动回归成本高。  
- **不可 long-term wontfix**；可分多 MR，但必须进路线图。

#### 建议动作 / Migrate 预映射

| 项 | 值 |
|----|-----|
| 动作 | **Split**（行为锁测后拆文件/职责） |
| 优先 | **P0-2**（可在 SHR-D1 部分切片后开始；与 PLAT-D2 耦合） |
| 预映射 | Migrate **M-2+ 壳装配拆分**；子切片：Providers → Overlays → CommandBridge → Chrome |
| 依赖 | 建议先有壳行为测试/关键路径手工清单；**不**阻塞 SHR-D1 |

#### 与其它债关系
