# 产品蓝图

## 核心对象

| 对象 | 用户心智 | 关系 |
|---|---|---|
| Space | 个人的工作上下文，如工作或生活 | 任务与 Project 都归属一个 Space |
| Project | 同一目标下的轻量任务容器 | 独属于一个 Space；Task 可选归属 |
| Task | 最小执行单元 | 必须属于一个 Space，可属于一个 Project |
| Saved View | 用户命名并保存的完整任务查询 | 只服务 Task；保存 scope、context、baseViewKey 与 filters |

**所有空间**是跨可见 Space 的任务查询并集（执行台），不是可编辑实体，也不是第三个组织容器。创建或编辑 Task 时，Task 始终落在具体 Space。

「所有任务」在所有空间与单个 Space 下**语义相同**（同一列表规则），仅范围不同：所有空间 = 各 Space 任务并集。

## 信息架构

```text
主应用
├── 所有空间（Task 执行台，不管项目树）
│   ├── 所有任务（默认）
│   └── Saved View Library
├── 单个 Space
│   ├── 所有任务
│   ├── Saved View Library
│   ├── 独立事项
│   └── Projects
├── Archive
└── Trash

独立 Launcher
└── 跨所有空间搜索 Task / Project，并创建 Task（须落到具体 Space）
```

任务结果页使用按页面上下文定义的 **Default View** 承载高频查询；Default View 是代码定义的产品入口，不是可持久化实体。`/views` 根页是 **Saved View Library**，负责查找、创建和管理 Saved View；打开 Saved View 后由与所有任务、独立事项和项目详情相同的任务工作台呈现结果。Archive 与 Trash 是生命周期管理入口，不属于 Task Saved View。

## 核心用户路径

### 创建与组织

1. 用户从应用外唤起 Launcher，或在主应用内打开创建入口。
2. 输入标题，选择具体 Space；可选择 Project、状态、优先级和时间。
3. 创建后任务保留在所选 Space 中；不要求必须归入 Project。
4. 用户稍后可在 Task 详情或列表中继续编辑与组织。

Launcher 是独立窗口，只复用 Task 创建后端契约；主应用创建弹窗是另一套主应用交互，不共享窗口状态或 UI。

### 日常推进

1. 用户进入默认 Space 的“所有任务”，或切换到「所有空间」跨 Space 执行台。
2. 侧栏入口展示真实的全部未归档、未删除任务；进入入口时清除临时筛选。
3. 在所有空间列表中可扫读每条任务的 Space 归属，并直接改状态/优先级。
4. 用户从当前 Default View 出发，用 URL 中的 Filter Draft 临时缩小范围，或保存为 Saved View 供长期复用。
5. 用户通过状态、优先级、计划日期和截止日期识别下一步，并可使用 Command、快捷键和批量操作推进。

### 查看与编辑

- `Space` 只打开只读 Peek，用于不中断列表扫描的快速预览。
- 没有打开任务时，MainCard 只显示任务列表。
- 窗口宽度 `>=1024px` 时，从任务列表点击任务或按 `Enter`，在 Main 内打开可编辑的非模态 Aside；任务列表宽度不小于 `352px`，Aside 默认 `360px`，可在 `320–440px` 内临时拖宽。
- 窗口宽度 `<1024px` 时，同一操作打开任务详情 Sheet。跨越 `1024px` 只在 Aside 与 Sheet 之间切换容器，保留同一任务、草稿和 URL，不关闭详情，也不自动跳转完整页。
- Shell 只派生一份 `isCompact`（窗口 `<1024px`）供 Sidebar 与任务详情消费；两者的 open state 分开，窄窗中导航 Sheet 与任务 Sheet 互斥，避免同时出现两个模态层。
- 任务列表只在自身容器宽度 `<560px` 时进入唯一一档紧凑排版，`>=560px` 使用默认排版。
- 独立详情页用于完整编辑、链接和操作记录，只能由用户通过明确入口打开，不作为响应式回退。
- Task 的完整活动时间线是正式能力；Project、Space 和全局活动入口尚未承诺。

### 归档、删除与恢复

- Task、Project 和 Space 都可归档或删除。
- 删除进入 Trash，可恢复；永久删除只在 Trash 中执行。
- Project 或 Space 的归档/删除应级联其内容；恢复只恢复该操作影响的内容。这是已确认的目标规则，当前实现尚未完全对齐。

## 执行信息

| 信息 | 规则 |
|---|---|
| 状态 | 待执行、进行中、等待中、已完成、已取消；手动维护 |
| 优先级 | 无、低、中、高、紧急；固定五档，不开放自定义 |
| 时间 | 计划日期、截止日期、提醒日期 |

提醒日期当前只保存信息，不定义通知调度或提醒 UI。逾期后的界面和操作规则也仍待后续单独设计。

Project 的状态、优先级与时间将与 Task 逐步对齐，并保持手动维护；不根据子任务自动联动。当前代码尚未实现完整统一模型。

## Default View、Saved View 与 Filter Draft

- **Default View** 是页面专属的高频查询入口，由代码定义，始终单选且不入库。不再使用“System View”指代这类入口。
- **Saved View** 是用户主动命名并保存的长期查询。它显式持久化 `scope + context + baseViewKey + filters`：`scope` 是 `all` 或某个 Space；`context` 是 `all`、`standalone` 或 `projectId`；`baseViewKey` 固定保存时的默认查询基线；`filters` 是该上下文内的额外筛选公式。
- `context` 是不可被 Filter Draft 移除的查询边界，不是一条 filter clause，也不额外保存 origin/page metadata。因此从独立事项或项目页保存后，仍能精确复现原查询边界。
- **Filter Draft** 是 URL 中临时、可恢复的完整 FilterQuery 快照。页面未修改时不存在 Draft；只有 Draft 与当前 Default View 或 Saved View 的 base 在语义上不同时，才显示 FilterBar。
- 保存使用当前完整查询：当前 scope、不可移除的 context、当前 baseViewKey 和 effective filters。Saved View 只服务 Task，不承担 Project Overview 或 Archive/Trash 的分类系统。

### 每页 Default View

| 页面上下文 | Default View（第一项为默认） |
|---|---|
| All Tasks | 未完成、今天（含逾期）、即将到期、全部 |
| Standalone | 未完成、今天、全部 |
| Active Project | 未完成、今天、即将到期、已完成、全部 |
| Completed Project | 全部、已完成、未完成 |
| Project Overview | 进行中、已完成、全部 |
| Archive / Trash（所有空间） | 全部、空间、项目、任务 |
| Archive / Trash（单个 Space） | 全部、项目、任务；不出现“空间” |
| Saved View Detail | 当前 Saved View，其后为所属 context 任务页的 Default View |

`/views` 根页是 Saved View Library，不是任务结果页，因此不再展示任务状态 Default View。`/views/:viewId` 保留稳定可分享路径，但使用与其他任务结果页相同的任务工作台。

## 平台与体验

- 正式桌面平台为 macOS 与 Windows；暂不承诺 Linux。
- 移动端是更后期方向，当前不为其提前设计界面或平台抽象。
- 默认使用浅色、高信息密度、低装饰的正式界面；键盘优先但不牺牲鼠标流程。
