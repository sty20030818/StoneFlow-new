# 创建弹窗工作面复原与日期渐进展示

**Status:** implemented-awaiting-manual-acceptance

## 问题陈述（Problem Statement）

应用内新建 Task 与 Project 的弹窗在样式系统迁移后失去了原有的编辑器感：标题和描述呈现为带填充背景的普通表单控件，外壳变窄，各分区叠加不同的内边距，用户无法获得在同一张干净工作面上连续输入的体验。Task 创建时三个尚未设置的日期入口始终占据属性栏，也增加了视觉负担。

当前已经有共享创建外壳和标题、描述、属性、底栏槽位，不是缺少组件化。另有必须一起收口的行为边界：顶部 Space 选择与 Task 表单归属分别持有状态，存在显示空间与实际提交归属不一致的代码路径；Task 与 Project 的提交错误呈现也不一致。

本工作包恢复已确认的视觉方向，并在现有共享结构上整理真实状态所有权，不重建通用表单或弹层框架。

## 解决方案（Solution）

Task 与 Project 继续使用同一创建工作面：白色浮层、24px 圆角、统一内容对齐、无边框/背景/阴影/ring 的标题与描述。保留当前字体、语义颜色、属性控件和各自的提交行为。长描述只有一个实际滚动区域，属性和底部操作始终可达。

Task 属性栏默认显示状态、优先级、归属和末尾的更多按钮。截止时间、计划时间和提醒时间在未设置时只出现在更多菜单；设置后，对应日期胶囊出现在更多按钮前。胶囊和菜单都能修改同一日期，清除后胶囊消失，菜单恢复设置入口。

顶部 Space、Project 归属和最终提交输入来自同一份创建状态。错误就地可见且可被辅助技术感知，失败不清空输入，重试不依赖重新填写。

创建更多保持一次性：成功创建一条后清空文本、保留弹窗、恢复标题焦点，并关闭创建更多开关。草稿保存、跨关闭恢复及关闭确认明确后置。

## 用户故事（User Stories）

1. 作为键盘用户，我希望通过现有 C 快捷键打开 Task 创建弹窗，以便快速记录当前要做的事。
2. 作为 Project 使用者，我希望通过现有新建 Project 入口或快捷键打开同一视觉体系的弹窗，以便不必重新学习创建界面。
3. 作为用户，我希望列表、分组、项目页和其他已有创建入口继续进入同一创建流程，以便入口不同不会产生不同的样式和提交规则。
4. 作为项目页用户，我希望新建 Task 保留当前 Project 与已有入口提供的状态预填，以便少做重复选择。
5. 作为跨 Space 用户，我希望创建时明确显示实际目标 Space，以便不会把内容创建到错误的空间。
6. 作为用户，我希望修改顶部 Space 后实际提交使用新 Space，以便显示与结果一致。
7. 作为用户，我希望选择另一个 Space 的 Project 时顶部 Space 同步反映该归属，以便知道 Task 最终属于哪里。
8. 作为用户，我希望切换 Space 后不会继续携带不属于该 Space 的旧 Project，以便归属始终有效。
9. 作为用户，我希望改变归属时保留已输入的标题、描述和其他属性，以便不因调整上下文丢失内容。
10. 作为用户，我希望标题输入没有边框、背景块、阴影或 ring，以便输入过程像编辑内容而不是填写卡片。
11. 作为用户，我希望描述区在默认、悬停和聚焦时都保持透明，以便工作面不会随交互出现突兀色块。
12. 作为用户，我希望创建弹窗使用明确的 24px 圆角和适合输入的宽度，以便视觉柔和且内容不拥挤。
13. 作为用户，我希望标题、描述、属性和底栏沿同一内容边对齐，以便视线自然移动。
14. 作为长描述输入者，我希望描述增长后只在一个区域滚动，以便不会遇到嵌套滚动和难以控制的滚动焦点。
15. 作为窄窗口用户，我希望属性可以换行且提交按钮始终可达，以便缩小窗口后仍能完成创建。
16. 作为用户，我希望没有日期时只看到一个更多入口，以便常用属性栏保持简洁。
17. 作为用户，我希望在更多菜单里分别设置截止、计划和提醒日期，以便三种时间含义不会混淆。
18. 作为用户，我希望设置一个日期后立即看到对应胶囊，以便不用重新打开菜单也能检查创建条件。
19. 作为用户，我希望三个日期可以独立设置和显示，以便选择其中一个不会覆盖其他日期。
20. 作为用户，我希望日期胶囊与更多菜单都能修改已设置值，以便从任一入口继续操作都得到相同结果。
21. 作为用户，我希望已有日期的菜单项显示更改文案和当前值，以便知道正在编辑而不是新增重复属性。
22. 作为用户，我希望清除日期后对应胶囊消失，以便界面只展示当前生效的条件。
23. 作为用户，我希望取消日期选择不改变原来的值，以便可以放心查看日历而不误改任务。
24. 作为键盘用户，我希望关闭日期选择器或菜单时只退出最上层，并回到合理的触发位置，以便不意外关闭整个创建弹窗。
25. 作为中文输入用户，我希望输入法选词不会误触提交，以便可以顺畅输入标题和描述。
26. 作为辅助技术用户，我希望输入有稳定名称、错误会被感知、操作有清晰焦点，以便不依赖输入框边框也能完成创建。
27. 作为用户，我希望创建中有明确反馈且不会重复提交，以便不意外生成重复内容。
28. 作为用户，我希望创建失败时保留文本、归属和日期，并可以重试，以便错误不会迫使我重新填写。
29. 作为连续录入用户，我希望创建更多成功一次后清空文本并回到标题，同时关闭该开关，以便下一次普通提交仍按默认方式完成。
30. 作为用户，我希望普通 Task 创建、Task 创建并打开、Project 创建后的导航继续遵循现有规则，以便样式改造不改变工作流。
31. 作为 Task 使用者，我希望切换现有放大呈现时保留当前输入，以便可以继续编辑较长内容。
32. 作为 Project 使用者，我希望没有属性栏需求时不出现空占位或凭空新增的日期字段，以便简单创建仍然简单。
33. 作为用户，我希望其他表单、Popover、详情页和 Launcher 不受本次创建样式影响，以便局部改善不会带来全局视觉回退。

## 实施决定（Implementation Decisions）

### 范围与现有架构

- 沿用 A1 领域模型、A2 系统设计、A3 界面系统与 ADR-0002 的单轨 HeroUI 平台及依赖方向。Task 必须归属具体 Space；有 Project 时两者必须同 Space；独立事项不是 Project。
- 应用内创建仍通过既有 Command、创建状态与 Shell 创建组合进入。C 是 Task 快速创建入口，Project 保持现有 N P 入口，不重绑快捷键。
- 继续复用 CreateDialogShell 与 CreateModalContent。共享壳拥有创建容器、分区布局、响应式几何与组合合同；TaskCreateContent、ProjectCreateContent 保留各自 schema、领域属性、mutation、提交意图及成功导航。
- 先在任务 01 整理 Header 与表单的组合及归属所有权；任务 02 直接消费最终组合边界完成视觉和日期交互，不保留临时双轨或兼容接线。
- 不创建通用创建引擎、第二套 Composer 框架、一对一 HeroUI wrapper、CVA 镜像或新的依赖。必要的共享只提炼两个真实创建消费者必须一起变化的合同。

### 归属与表单状态

- 每次创建会话只有一份权威归属状态。Header Space 选择、Task placement / Project 选择和提交 payload 读取、修改同一所有者；不让 Shell 与表单各存一份再用双向 effect 同步。
- 从 Project 入口预填时，Header 显示该 Project 所属 Space；保留现有等待项目选项就绪后再挂载创建内容的行为，不增加空表单闪现路径。
- 选择 Project 时，从项目身份解析所属 Space，Header 同步呈现。显式切换 Space 时，若原 Project 不属于新 Space，清除该 Project 归属并显示为新 Space 内的独立事项；不静默保留跨 Space 的非法组合。
- 归属变化保留已填写的标题、描述、状态、优先级与日期，不通过重挂载表单或整体 reset 同步 Header。
- Project 创建直接使用当前有效 Space；无有效目标时保留明确的不可提交状态。领域校验、Task / Project DTO、数据库、同步及导航契约不改变。

### 创建工作面与样式所有权

- Task 与 Project 的普通创建弹窗采用白色浮层、24px 圆角、桌面最大宽度 768px 和偏上方的定位方向；内容内边距及分区间距为 spacing 3（12px），Header 分隔符两侧与属性之间为 spacing 1.5（6px）。窄窗保留安全边距，短窗口限制高度，不让固定留白挤掉操作区。
- 创建标题使用现有字体的 18px / 600 层级，描述使用 14px / 400；沿用 Inter Variable、系统中文回退、现有语义颜色和 Accent，不新增字体或色板。
- 标题与描述在默认、hover、focus 及 focus-visible 下均无边框、背景填充、阴影和 ring。保留真实输入语义、清晰光标、可访问名称、校验信息；错误不能只依赖红框表达。其他按钮与菜单仍保留项目规定的键盘焦点反馈，强制颜色模式保持系统可辨识性。
- 透明编辑区与 24px 创建外壳是本轮批准的窄产品语义，不修改其他 Input、TextArea、Popover 或普通 Overlay 的外观。当前通用 Overlay 12px 保持；不从 Tailwind 圆角类名推断本项目的实际尺寸。
- 几何与分区结构由共享创建 Module 统一，皮肤差异由现有集中语义主题与最小公共 recipe 承载。实施时同步现行界面系统、样式架构及相关 ADR 对创建场景的例外说明，不回改冻结归档，也不开放通用 radius / tone / surface 参数。
- 清理 Modal、分区与输入控件重复叠加的内边距。标题与描述左侧比属性、底栏额外缩进 4px，描述空态为三行 60px；Project 没有正常态属性时不渲染空属性占位。
- 两类创建底栏最左侧提供禁用的圆形素材图标按钮，仅占位，不触发上传、文件选择或表单提交；素材功能仍在范围外。
- 描述随内容增长，在可用高度上限内只有一个实际纵向滚动区域；标题、属性和底栏保持可达，不同时保留描述 textarea 与其外层的独立滚动。Task 现有放大呈现保留，不扩展为新的全屏系统，也不为 Project 新增放大功能。
- 不增加第一方动画、输入过渡、骨架屏或预加载系统。HeroUI 继续负责标准 Overlay / 控件行为及官方动效；本次没有已测量的冷启动性能目标。

### 日期更多菜单与胶囊

- 日期渐进展示只应用于 Task 创建，三个字段按截止时间、计划时间、提醒时间的固定顺序呈现；Project 创建不新增日期能力。
- Task 属性栏固定基础项为状态、优先级、归属，随后是已设置日期的胶囊，末尾始终是更多按钮。没有日期时不渲染任何空日期胶囊，也不给更多按钮添加已设置数量、小圆点等重复提示。
- 更多菜单始终保留三个日期入口。未设置时显示设置截止时间 / 设置计划时间 / 设置提醒时间；设置后改为更改相应时间，并显示当前值。
- 选择菜单项进入对应日期选择流程，复用已有日期预设、自定义日期、格式化与清除能力。胶囊点击进入同一日期编辑能力，两个入口不持有独立日期副本。
- 当前日期值为空时无胶囊；保存有效值后立即显示一个对应胶囊；修改只更新该胶囊和菜单值；清除后该胶囊立即消失，菜单恢复设置入口；取消不改值。可同时显示一至三个胶囊，固定顺序不随设置先后变化，空间不足时属性行换行。
- 沿用现有日期图标、胶囊控件与可访问名称，区分截止、计划、提醒语义，不只展示三个无法区分含义的日期文本。
- 三个日期继续使用现有本地日历日期选择合同。字段文案含时间不表示本轮增加小时、分钟、时区编辑或提醒调度；不改变现有日期与持久化值之间的转换。
- 菜单、日期选择器和创建弹窗遵循既有 Overlay 栈。Escape / 取消只处理当前最上层；关闭后返回仍存在的合理触发器。若清除导致原胶囊卸载，焦点回到更多按钮，不能停留在被移除的元素或跳到底层页面。

### 提交与反馈

- 创建失败时保留文本、归属及已选属性，不增加创建计数、不关闭弹窗、不触发成功导航；提供语义一致、可感知的错误及原位重试路径。错误与成功计数统一底部反馈位置，具体业务错误仍由所属领域提供。
- 保留既有 pending 反馈、防重复提交、表单校验与 Command Submit 协作；不借视觉改造更改空标题 / 名称的可提交规则或增加第二套提交快捷键。
- 创建更多是一次性开关：成功后清空文本、保留弹窗、更新本次创建计数、恢复标题焦点，同时复位开关。Task 继续保留现有下一条预填属性策略；不顺便重定义默认值继承。失败时不执行成功清理。
- 普通 Task 创建保持原有关闭行为；Task 创建并打开保持打开刚创建任务；普通 Project 创建保持关闭并导航新项目；Project 不新增创建并打开提交意图。
- 用户明确将草稿能力后置。本轮不增加关闭确认、持久化草稿或跨关闭恢复，也不把现有仅含预填条件的创建意图描述为已实现草稿保护。

## 测试决定（Testing Decisions）

### 主测试接缝

用户已确认以真实完整创建组合为主要测试边界。优先在既有 ShellCreationOverlays 与创建状态组合处补一组行为测试，使用现有交互 Provider，真实渲染 Header、领域表单、属性控件、日期菜单与自定义日期选择器；仅模拟 mutation、导航等外部副作用。

不新增生产测试接口、平行表单框架或为了测试暴露内部 setter。不以 CSS class、hook 调用顺序、状态容器形状作为行为正确性的替代证据。

### 既有测试先例

- TaskCreateContent 与 ProjectCreateContent 的组件行为测试已覆盖基础提交、继续创建及不同提交意图；复用其交互约定，补缺失断言，不复制多套相同用例。
- CreateDialogShell 的 Space 回调测试不能独自证明最终提交归属；新的组合接缝必须覆盖 Header 到实际创建输入的完整路径。
- metadata-fields 已有清除、自定义日期、取消、Escape 与日期合同测试；保留基础语义覆盖，新增创建场景的菜单 / 胶囊 / 提交联动即可。
- 既有 Overlay 焦点与 Escape 优先级测试作为先例；创建组合仍需验证真实更多与日期选择路径，不能只依赖通用样例通过。
- CreateModalContent 中仅锁定旧 padding class 的断言随合同调整，改由可观察结构及真实布局证据承担，不保留过时实现快照。

### 日常行为矩阵

| 场景 | 最小数据与操作 | 通过判据 |
| --- | --- | --- |
| Space / Project 同源 | 两个 Space、各一个 Project；从项目预填、切 Space、选另一 Project 后提交 | Header、可见归属与提交目标一致；没有跨 Space 非法组合；文本保留 |
| 日期闭环 | 对三个日期参数化执行设置、修改、清除、取消，再组合设置三个日期后提交 | 胶囊可见性、菜单文案和实际日期值一致，三个字段互不串扰 |
| 普通与附加提交 | Task / Project 正常创建，Task 创建并打开，继续创建后再普通创建 | 关闭、导航、清文本、计数和一次性开关符合各自原有合同 |
| 失败恢复 | Task / Project 各一次写入拒绝后重试成功 | 错误可感知，输入和属性保留，无错误计数或导航，重试使用同一内容 |
| 嵌套键盘路径 | 打开更多、进入日期选择、逐层 Escape；清除当前胶囊 | 只关闭最上层，创建内容未丢失，焦点回到有效入口 |
| 呈现切换 | Task 有文本和属性时切换现有放大呈现 | 表单内容与属性保持，不重复提交 |

测试只使用少量日常数据，不引入几千条实体、长时压力循环或与本弹窗无关的压测门槛。

### 真实界面与桌面验收

- 浏览器或隔离预览验证空表单、短文本、长描述、一至三个日期、错误和 pending 状态；检查实际计算的 24px 圆角、透明输入的各状态、对齐、窄窗换行、长内容单滚动及底栏可达。
- 检查现有 Accent 下的文字、日期语义、错误与按钮焦点，不扩展新的主题体系。输入无 ring 仍需确认可见光标与可访问名称，按钮和菜单保留键盘焦点；强制颜色模式单独记录结果。
- 在可用的真实 Tauri Main 中验证 C / Project 创建入口、中文 IME 选词、提交快捷键、Escape、日期返回焦点及 Task 放大切换。记录实际平台、窗口和结果；未执行的平台或原生交互明确记为未验证。
- UI Lab 当前只有创建相关组件登记，登记不等于存在可交互预览。需要预览时复用既有隔离样例机制，渲染真实生产组合与模拟写入，不用复制的静态弹窗替代验收。
- 不主动启动长期开发服务，不以测试修改正式数据库。现有服务、隔离测试与真实桌面证据分别记录；需要额外运行环境时按项目权限约定处理。
