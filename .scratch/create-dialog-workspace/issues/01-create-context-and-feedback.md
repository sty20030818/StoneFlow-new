# 01: 创建归属与提交反馈收口

**What to build:** 用户从任何现有入口创建 Task 或 Project 时，顶部 Space、Project 归属和实际提交目标一致；调整归属不丢失输入，提交失败可原位重试，成功后的关闭、导航及一次性创建更多行为保持不变。复用现有创建组合，完成任务 02 所需的 Header / 表单职责整理，不先重做视觉或日期布局。

**Blocked by:** 无（可立即开始）。

**Status:** complete

- [x] 应用内 C、Project 创建及已有鼠标入口继续使用同一共享创建路径，保留入口提供的 Project / 状态预填和等待项目选项就绪的挂载行为。
- [x] 每次创建会话只有一份权威归属状态；Header、属性选择和创建 payload 同源，不保留 Shell 与表单双副本或双向 effect 同步。
- [x] 从 Project 入口创建或选择另一 Space 的 Project 后，Header 显示该 Project 所属 Space，提交归属一致。
- [x] 显式切换 Space 后，若原 Project 不属于新 Space，则清除旧 Project 并展示为新 Space 的独立事项；标题、描述、状态、优先级与日期保留。
- [x] Project 创建使用当前有效 Space；无有效创建目标时不能提交。Task 与 Project 同 Space 的领域不变式、API 和持久化合同不变。
- [x] 共用壳只承担容器与组合合同，领域表单继续承担各自校验、属性与提交语义；不新增通用创建引擎或一对一 HeroUI wrapper。
- [x] Task 与 Project 在统一底部反馈位置呈现可感知的错误；失败不清文本或属性、不增计数、不关闭、不导航，可使用原输入重试。
- [x] 保留 pending、防重复提交及既有校验规则；正常 Task 创建、Task 创建并打开、Project 创建导航符合原有语义，Project 不新增 open 提交意图。
- [x] Task 与 Project 的创建更多均在成功一次后清空文本、保留弹窗、更新计数、恢复标题焦点并关闭开关；Task 原有下一条属性继承不变。失败不执行成功清理。
- [x] 在真实创建组合与创建状态接缝补齐行为测试，仅模拟写入 / 导航等外部边界；两个 Space、少量 Project 足以验证 Header 到实际提交的一致性。
- [x] 测试覆盖两类创建失败保留输入与重试、一次性创建更多后再普通提交，以及各自成功导航；复用已有 Provider 和提交测试，不为测试新增生产接口。
- [x] 保留并回归既有 Overlay / Command 行为，任务放大切换不重挂载丢失表单；不增加草稿、关闭确认或跨关闭恢复。
- [x] 删除因归属所有权收口而无消费者的旧 props、重复状态、同步旁路和兼容接线；不清理无关 Feature，也不更改全局控件皮肤。
- [x] 运行与本次状态及组合改动相称的根级检查和相关行为测试，记录实际结果、未覆盖边界；按需同步现行模块合同，不把测试计划记成通过。

## 实施与证据（2026-09-08）

- 创建归属改为领域 RHF 表单单一事实源；Shell 的重复 Space 状态、同步 effect 和旧 props 已删除，Header 通过组合槽直接读写表单。
- 共用底部反馈；pending 禁止修改字段和重复写入，失败保留内容，一次性创建更多的计数、复位和标题焦点保持。
- 追加关闭竞态回归：Task / Project 在旧提交期间关闭并重开后，旧结果不能关闭新弹窗或导航。两项先红，生命周期守卫修复后通过；已发出的写入不取消。
- 完整创建组合 19 项 + 既有 Task / Project / 默认值三文件 13 项，共 32/32 通过。只在 IPC 写入、导航等外部边界模拟，没有替换领域表单与日期组件。
- 浏览器真实组合实测 Project 失败后保留名称、说明及创建更多；原输入重试后计数变为 1、文本清空、开关关闭、标题获得焦点。Task 放大切换保留文本。
- 根级自动化和整个工作包的浏览器 / 原生边界统一记录在任务 02；原生快捷键与中文输入法未验收，不以本任务状态替代原生验收。
