# 04: 筛选条件可准确检查和修改

**What to build:** 用户能检查 View 的完整边界和包含/排除条件，修改条件不会反转含义；无匹配任务时给出准确说明及调整入口。

**Blocked by:** None (can start immediately).

**Status:** implemented; archived; remaining acceptance transferred

**覆盖：** V05、V10；用户故事 20–24、43、44。

- [x] 复用现有 FilterMenu 展示不可移除的 scope/context/base 与完整 effective filters；clean FilterBar 仍隐藏，dirty 时展示完整公式、恢复与保存。
- [x] 当前 is_not 在菜单中准确表达；修改值保留操作符，只有明确改包含/排除才改变操作符；同字段多个有效条件不被普通值选择无提示删除。
- [x] 保持选择即时应用；仅打开检查、Escape 或点击外部关闭不改变 URL、dirty 或结果，关闭不回滚已经明确应用的修改；不加第二份待提交筛选状态。
- [x] 前后端支持的 FilterQuery 语义一致；重复 field/op clauses 可等价规范化才转换，不能合并为扩大的 OR。非法字段/操作符/值或无法无损表达的旧定义明确失败，不用空条件兜底。
- [x] 无法表达的旧定义沿用现有不可用状态，03 完成后接入同一逐行恢复呈现；不另外发明错误模型，也不为等待新 DTO 人为阻塞正常筛选修复。
- [x] 区分项目确实为空、当前 View/筛选无匹配、首屏未加载、首屏/续页失败；筛选空态提供调整入口，不额外全量读取任务，不把未就绪 count 当作 0。定义读取重试归 03。
- [x] 页面行为覆盖 clean 检查、负向编辑、即时应用、多个同字段条件与空态；通过共同查询执行接缝验证规范化前后成员相等，不仅验证菜单 payload。
- [x] 控件键盘可达、名称和焦点清晰，长条件不遮挡操作；更新既有 Filter 和界面契约说明。
