# 06: 主分组统一排序、折叠与选择

**What to build:** 状态、优先级、项目和日期分组都能按完整结果顺序连续分页，并具备一致的折叠、展开、已加载成员选择和预览恢复行为。

**Blocked by:** 05 — 完整结果排序与稳定分页。

**Status:** implemented; archived; remaining acceptance transferred

实现与本地验证见 [06 验证记录](../06-verification.md)；09 原生现场验收独立保留。

**覆盖：** AR3 的唯一投影与主组交互、AR2 的主组窗口；用户故事 34、38、39、47。

- [x] 先收敛唯一 group-key 投影并同票迁移状态及非状态消费者，移除状态二次 regroup 与 customSections/statusOrder 双重事实源；不另建 renderer 或通用分组框架。
- [x] 主分组作为 05 总序/cursor/Query key 的前缀：状态用固定业务序，优先级 4 到 0，日期桶依次逾期、今天、明天、本周剩余、更晚、未设置，项目按名称二进制序和 ID、独立事项置后。
- [x] 主组顺序不随组内排序方向反转；组内复用 05 的自然/recency 规则，done 分区只影响当前组，不跨组搬移成员；SQL 与前端使用相同组身份和顺序。
- [x] 投影提供稳定身份、标签、已加载成员和可选领域动作元数据；status 不再充当所有分组身份，也不从非状态组标签猜测状态或写任务属性。
- [x] 所有实际主组使用相同展开和已加载成员选择；折叠身份区分来源与分组配置，组选择不包含其他组或未加载任务，状态组原有创建预填继续有效。
- [x] 同一主组跨页只形成一个逻辑组；追加不会把后页任务插回已经完成的前序组，不用总数制造未加载任务高度。
- [x] 复用 CollectionBody、集合几何、虚拟 flat items、sticky、sentinel、append anchor 与 stable-id 焦点/预览恢复，不改虚拟列表性能基线。
- [x] 每种主分组通过真实 SQL 窗口测试验证跨页顺序；页面至少覆盖状态与一个非状态组折叠、选择、续页、错误重试、预览关闭及偏好恢复。子组和精确空组在 07/08 完成，不复制其摘要实现。
- [x] 更新 Board、Display 与工作台权威文档，检查旧分组接口无消费者；有效既有测试迁移至公共行为接缝，不保留永久双轨。
