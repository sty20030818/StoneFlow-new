# 03: 无效 View 单条隔离并提供恢复入口

**What to build:** 一个损坏、不可迁移或项目范围失效的 View 不影响其他视图；用户能理解问题、重试读取或删除坏记录，应用不会静默扩大查询。

**Blocked by:** 01 — 同步后的 View 仍可编辑和删除。

**Status:** implemented-awaiting-acceptance

**覆盖：** V03、V08、V09；用户故事 18、19、27–31。

- [x] 在 01 的共同解码/事务边界逐条区分有效、不可迁移、损坏及当前项目边界失效，不因一行 scope 解码失败中断整个 Library。
- [x] 可识别 scope 的坏定义保留在原 Library；未知 scope 的条目在“所有空间”Library 可达，DTO 明确范围未知而不伪造合法 scope。
- [x] 不可用行保留身份、原因与删除动作，禁止运行、重命名和覆盖；按 ID 删除无需先成功解码，失败可恢复，不自动删除或猜测查询。
- [x] create/update/run 均校验项目存在及与 scope 一致；space scope 的项目迁出后明确失效，不自动改 scope/context，全范围 scope 的合法 project 查询仍有效，归属恢复后重新校验可用性。
- [x] 返回 Library、删除、从有效项目重新保存等恢复路径可达；不改项目移动/归档/删除业务规则。
- [x] Library 与定义读取失败均有实际重试，Saved View 保留返回 Library；定义错误、任务零结果和未加载不混淆。
- [x] 同步页里有效实体继续应用，坏记录必须以可清理异常记录与协议状态/cursor 同事务保留；无法形成可恢复记录时沿用 01 的回滚，不能只警告后跳过。
- [x] 混合坏 scope、两个不同 scope 的有效 View、不可迁移筛选及项目移动夹具，穿过 SQLite/同步与 Library 公共边界验证隔离、清理、读取重试和恢复；04 新的筛选校验复用该不可用语义，不另建异常模型。
- [x] 更新既有领域及模块说明；不直接改用户正式库，不引入通用坏数据后台或跨 Space 自动迁移。
- [x] 本票完成前检查异常条目、读取重试和删除的键盘路径、焦点与错误可感知性，长名称/错误及窄窗口下恢复动作保持可达。
