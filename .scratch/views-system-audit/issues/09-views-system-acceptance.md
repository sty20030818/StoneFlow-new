# 09: Views 整体回归与原生验收

**What to build:** 在实际应用中证明保存、切换、同步恢复、排序和分组共同工作，并闭合用户最初“切换后仍只有待执行”的现场问题。

**Blocked by:** 02 — 保存后打开新 View，切换时恢复正确查询；03 — 无效 View 单条隔离并提供恢复入口；08 — 准确显示空组与分组数量。

**Status:** ready-for-agent

**覆盖：** 全部 V01–V10、AR1–AR4 的整合；用户故事 45–47 及原始现场。

- [ ] 前置票各自已有功能与聚焦验证证据；本票做跨票集成和最终验收，不接收被前置票推迟的主逻辑、回归测试或消费者迁移。
- [ ] 实际 Tauri 主窗口以可恢复隔离数据完成项目“未完成” → “待执行” → 保存 → 新 View → 返回“未完成” → “全部”；混合 todo/doing/waiting/done 验证选中项、有效条件、实际任务和总数一致。
- [ ] 所有任务与独立事项做代表性同链验证，Saved View 再另存/覆盖/恢复，加入负向条件、空 Draft、失败重试与迟到请求，证明各票组合后不重新引入原问题。
- [ ] 同一含分组/排序的查询走 Default/Draft 与 Saved 两个入口，得到同一成员、顺序和数量；完整加载超过两页，主/子组追加、空组及 recency 结果一致。
- [ ] 端到端整合已知旧格式恢复、同步往返后再修改、坏 scope 隔离及项目移动失效；验证 04 的不可等价筛选接入 03 的同一异常呈现，没有第二套错误模型。
- [ ] 检查真实键盘保存/取消/重试、焦点恢复、错误朗读、长 View 名称、窄窗口与 200% 缩放；滚动、sticky、选择、预览关闭和 sentinel 恢复无回退。
- [ ] 分别记录自动化、SQLite/协议夹具往返和真实设备同步证据；本地双副本不冒充跨设备通过。实际 Tauri 无法操作时保持原生验收未完成，不以 UI Lab 登记或隔离 Router 探针结案。
