# 01: 同步后的 View 仍可编辑和删除

**What to build:** View 经同步往返或遇到已确认的旧格式后，仍能保留原查询并正常重命名、覆盖和删除；重命名及删除失败有明确反馈和恢复动作。

**Blocked by:** None (can start immediately).

**Status:** implemented-awaiting-acceptance

**实施与证据：** [01 验证记录](../01-verification.md)。当前版本代码已实现，旧版混用、历史云端残缺定义的恢复策略及原生验收尚未闭合；本票未标记完成。

**覆盖：** V01、AR4、V02 的重命名/删除部分；用户故事 14、15、25、26。

- [x] 先在现有 View 边界收敛具体定义 codec 与协议投影，CRUD、seed、协议基线回填和下载物化共用；不新增通用框架，不改 schema/wire shape。
- [x] 创建 → Outbox → 另一 SQLite 副本物化 → 读取 → 重命名 → 覆盖 → 再次同步 → 删除完整往返成功；ID、名称和查询语义准确（新版 producer，历史远端残缺定义见待验项）。
- [x] 精确兼容裸文本 none 与正常 canonical 值，落盘为合法 JSON；恢复幂等，不改查询、业务时间或制造重复 Outbox。旧 sort/group 不再决定当前业务更新是否成功；未知查询损坏不能兜底为空查询。
- [x] 冷协议状态的 rename/filter patch 用既有行或完整协议快照补齐后应用；不足时明确恢复或失败，不能覆盖成残缺定义。
- [x] 物化失败时业务投影、协议状态与 cursor 同事务回滚；恢复完整定义后重放原页成功且幂等。下载路径不写 AppliedOps，上传 ACK 去重维持现有所有权，未新建第二套去重。后续异常记录隔离复用该事务机制。
- [x] 重命名失败保留输入、删除失败保留记录，错误可感知且能重试；提交中防重复，关闭/新会话后迟到结果不覆盖新输入或关闭新弹窗。创建、另存和覆盖的界面反馈归 02。
- [x] 使用临时 SQLite 与真实协议投影留下往返回归，以及重命名/删除的页面失败恢复检查；不直接修写正式数据库，不将夹具副本称为跨设备验收。
- [x] 更新现有 View 与同步权威说明，核对全部编码消费者；兼容退出条件明确，不提前删旧列或协议字段。
- [x] 检查重命名/删除相关键盘操作、焦点恢复和长名称/错误在窄窗口的可达性。已完成真实浏览器组件样例与页面回归，原生验收仍未代签。
