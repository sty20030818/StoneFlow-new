# changelog 当前实现设计

## 内容链路

仓库根 [CHANGELOG.md](../../../CHANGELOG.md) 是唯一可编辑内容源。发布流程把经过同一契约校验的完整文件发布到 release base 根目录；应用通过独立 `get_changelog` 命令读取该静态文件。

模块同时在构建时内置根文件快照，打开时即能展示。远端只负责后台刷新，不从 updater manifest 读取用户可见说明。

## 语法契约

文档必须先出现唯一的 `## [未发布]`，它也是第一个结构性 H2。其前面只允许 H1 和普通简介。`未发布` 可以没有分类内容。

已发布版本使用以下标题：

```md
## [1.2.3] - 2026-08-07
## [1.2.3-beta.4] - 2026-08-07
## [1.2.2] - 2026-08-01 [已撤回]
```

约束如下：

- 只接受 `major.minor.patch` 和 `major.minor.patch-beta.N`。
- 数字部分不允许多余前导零，Beta 序号从 1 开始。
- 不接受其它预发布标签、build metadata、`v` 前缀或额外版本段。
- 日期必须是有效的 `YYYY-MM-DD`。
- 版本必须唯一，并按 SemVer 从新到旧严格排列。
- 版本比较使用任意精度整数，避免大版本号丢失精度。

每个已发布版本至少包含一个非空规范分类，`未发布` 可以为空。分类标题只允许：

```md
### 新增
### 变更
### 弃用
### 移除
### 修复
### 安全
```

正文必须位于分类下，未知或重复分类会被拒绝。代码围栏中的标题和比较链接按正文处理，不参与结构解析。

文末可以包含 `未发布` 或受支持版本的比较链接。比较链接必须集中位于文末，标签不能重复，目标不能为空。发布目标还必须在文档中存在且没有标记为 `[已撤回]`。不接受旧英文标题或别名。

## 历史与区间选择

完整历史用于 `ChangelogDialog`：

- Stable 只包含正式版本。
- Beta 同时包含正式版本和 Beta 版本。
- 两种历史都保留已撤回条目，由界面标记“已撤回”。

更新对话框使用 `(currentVersion, targetVersion]` 区间：

- 当前版本是开区间下界，目标版本是闭区间上界。
- Stable 区间只包含正式版本。
- Beta 区间可以包含落在 SemVer 区间内的正式版本和 Beta 版本。
- 区间始终排除已撤回条目。
- 目标版本的 Stable/Beta 类型必须与查询渠道一致。
- 当前版本不低于目标版本时返回空结果。

区间按版本号计算，不依赖某台机器是否发布过每一个中间版本。比如 Windows 从 `0.1.2-beta.2` 直接更新到 `0.1.2-beta.4` 时，会展示区间内实际存在的条目；`beta.3` 缺失也不会阻止 `beta.4` 展示或安装。

## 即时展示与后台刷新

`get_changelog` 使用带超时的 HTTP 请求读取：

```txt
<release-base>/CHANGELOG.md
```

非成功响应、空正文、网络错误和超时都返回空结果。前端先展示可读内容，再按需发起请求：

```txt
最近有效文档 / 构建时内置 CHANGELOG.md
  -> 立即展示
  -> 后台获取远端，成功解析后替换文档；失败保留原内容
```

缓存由 `useChangelog.ts` 唯一管理，通过 React 原生订阅通知所有消费者：

- 当前可读文档与请求状态，初始文档仅解析一次内置快照。
- 当前唯一远端请求。
- 最近请求时间与最近请求目标；保鲜/失败重试间隔均为 5 分钟。

内置快照不被标记为成功远端请求。多个消费者和预取共用同一个在途请求，完成后释放；保鲜期内重开、切换渠道或区间只重新筛选缓存。过期后再次打开触发后台刷新，不靠定时轮询。

新目标不在可读文档中且尚未请求过时，`prefetchChangelog(targetVersion)` 越过保鲜期刷新。如果加入了早于新目标的在途请求，完成后仍缺少目标便补取一次。同一缺失目标失败后不会因重开弹窗连续重试，保鲜期结束后可再取。

## 展示

`ChangelogRelease` 展示版本、日期和撤回状态，正文由 `ChangelogReleaseContent` 将六个中文规范分类交给 HeroUI Pro 静态 `Markdown` 渲染。正文直接沿用上游排版、GFM、换行和代码块，不叠加 `Typography.Prose` 或自有通用样式；唯一元素覆盖隐藏水平分隔线，原始 HTML 不执行。分类默认为版本 H3 下的 H4，目标更新正文可显式使用弹窗 H2 下的 H3。

已验证锁定版本的上游静态 Markdown 按顶层块独立解析，跨块引用链接和脚注仍显示字面语法；当前更新日志没有使用这些写法。本模块不增加第二套解析器或兼容预处理，也不因此改变发布语法契约。

完整历史由 `ChangelogDialog` 在最大 768px 的阅读窗口内按版本分为独立 HeroUI Card，卡片之间间隔 12px。外壳采用次级表面，保留统一的 24px 圆角与 12px 内边距；原生滚动区向两侧各借用 8px 外壳留白，再以等量 padding 保持卡片位置，让滚动条位于卡片旁边。传统占位滚动条使用双侧等宽 gutter，避免仅右侧增宽；卡片不收缩，列表整体滚动，支持键盘聚焦。只有没有可读条目时才显示加载提示；版本定位每次打开只执行一次，不随后台刷新抢回滚动位置。

更新对话框把目标版本的小尺寸 soft Chip 及已知发布日期放在状态标题旁，正文由一个 HeroUI Card 承载。目标版本使用 `ChangelogReleaseContent`，不重复显示版本标题；中间版本继续使用 `ChangelogRelease` 保留各自身份。目标说明缺失时仍展示目标版本及轻量提示，不把中间版本误作更新目标。Card 边框固定，仅内部 Card.Content 持有日志纵向滚动，并提供键盘焦点；其他状态提示与 Card 平级，不嵌套说明滚动区。发现更新目标时提前预取，不必等弹窗打开或运行版本 IPC 完成。失败时保留已有区间条目；下载、安装按钮不依赖日志结果。底部“跳过此版本”靠左，“稍后”与更新动作靠右；“稍后”只关闭当前提醒，不承诺额外定时通知。

## 失败边界

- 远端读取失败不会覆盖最近有效远端文档。
- 远端和内置文档都无效时记录内置解析错误并返回空文档。
- 中文语法为一次性 hard cut，不保留英文兼容解析。切换前新客户端会把旧英文远端文档视为无效，切换后旧客户端会把中文远端文档视为无效；两者都只回退到各自的内置快照，不阻断 updater。
- 查询边界或目标渠道不合法时契约抛错，调用方不得把错误结果当作发布或安装依据。
- changelog 只解释内容，不决定 updater 是否有可用版本，也不修改 update 会话。
