# changelog 当前实现设计

## 内容链路

仓库根 [CHANGELOG.md](../../../CHANGELOG.md) 是唯一可编辑内容源。发布流程把经过同一契约校验的完整文件发布到 release base 根目录；应用通过独立 `get_changelog` 命令读取该静态文件。

模块同时在构建时内置根文件快照。远端读取失败、内容为空或语法无效时，前端按固定顺序回退，不从 updater manifest 读取用户可见说明。

## 语法契约

文档必须先出现唯一的 `## [未发布]`，它也是第一个结构性 H2。其前面只允许 H1 和普通简介。`未发布` 可以没有分类内容。

已发布版本使用以下标题：

```md
## [1.2.3] - 2026-08-07
## [1.2.3-beta.4] - 2026-08-07
## [1.2.2] - 2026-08-01 [已撤回]
```

约束如下：

- 只接受 `major.minor.patch` 和 `major.minor.patch-beta.N`。
- 数字部分不允许多余前导零，Beta 序号从 1 开始。
- 不接受其它预发布标签、build metadata、`v` 前缀或额外版本段。
- 日期必须是有效的 `YYYY-MM-DD`。
- 版本必须唯一，并按 SemVer 从新到旧严格排列。
- 版本比较使用任意精度整数，避免大版本号丢失精度。

每个已发布版本至少包含一个非空规范分类，`未发布` 可以为空。分类标题只允许：

```md
### 新增
### 变更
### 弃用
### 移除
### 修复
### 安全
```

正文必须位于分类下，未知或重复分类会被拒绝。代码围栏中的标题和比较链接按正文处理，不参与结构解析。

文末可以包含 `未发布` 或受支持版本的比较链接。比较链接必须集中位于文末，标签不能重复，目标不能为空。发布目标还必须在文档中存在且没有标记为 `[已撤回]`。不接受旧英文标题或别名。

## 历史与区间选择

完整历史用于 `ChangelogDialog`：

- Stable 只包含正式版本。
- Beta 同时包含正式版本和 Beta 版本。
- 两种历史都保留已撤回条目，由界面标记“已撤回”。

更新对话框使用 `(currentVersion, targetVersion]` 区间：

- 当前版本是开区间下界，目标版本是闭区间上界。
- Stable 区间只包含正式版本。
- Beta 区间可以包含落在 SemVer 区间内的正式版本和 Beta 版本。
- 区间始终排除已撤回条目。
- 目标版本的 Stable/Beta 类型必须与查询渠道一致。
- 当前版本不低于目标版本时返回空结果。

区间按版本号计算，不依赖某台机器是否发布过每一个中间版本。比如 Windows 从 `0.1.2-beta.2` 直接更新到 `0.1.2-beta.4` 时，会展示区间内实际存在的条目；`beta.3` 缺失也不会阻止 `beta.4` 展示或安装。

## 请求与回退

`get_changelog` 使用带超时的 HTTP 请求读取：

```txt
<release-base>/CHANGELOG.md
```

非成功响应、空正文、网络错误和超时都返回空结果，由前端统一决定回退。前端加载顺序为：

```txt
本次有效远端文档
  -> 最近一次有效远端文档
  -> 构建时内置 CHANGELOG.md
  -> 空文档
```

缓存只包含：

- `lastValidRemoteDocument`：最近一次成功解析的远端文档。
- `inFlightRequest`：当前唯一远端请求。

内置快照和空文档都不会写入远端缓存。多个并发消费者复用同一个在途请求；请求在 `finally` 中清理，所以网络恢复后可以重试。Dialog 关闭后重开、目标版本变化或区间边界变化都会发起新请求。

## 展示

`ChangelogRelease` 直接展示六个中文规范分类，并展示版本、日期和撤回状态。`ChangelogMarkdown` 只支持当前更新日志需要的标题、段落、两级缩进列表、加粗和围栏代码，水平分隔线不显示；围栏内的标题和列表按代码原文展示。它不执行 HTML，也不承担通用 Markdown 兼容。

完整历史由 `ChangelogDialog` 在有界滚动区内展示。更新对话框渲染版本区间中的多个 `ChangelogRelease`；查询为空或回退失败时只省略说明，更新按钮保持可用。

## 失败边界

- 远端读取失败不会覆盖最近有效远端文档。
- 远端和内置文档都无效时记录内置解析错误并返回空文档。
- 中文语法为一次性 hard cut，不保留英文兼容解析。切换前新客户端会把旧英文远端文档视为无效，切换后旧客户端会把中文远端文档视为无效；两者都只回退到各自的内置快照，不阻断 updater。
- 查询边界或目标渠道不合法时契约抛错，调用方不得把错误结果当作发布或安装依据。
- changelog 只解释内容，不决定 updater 是否有可用版本，也不修改 update 会话。
